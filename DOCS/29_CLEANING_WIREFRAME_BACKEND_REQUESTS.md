# 청소 와이어프레임 복원과 백엔드 요청

기준: 2026-09-29 사용자 요청, 프런트 와이어프레임, 백엔드 main `5303fd505f18ed45fe9945d35239ccef25df2b13`. 이전 감사 원문은 변경하지 않는다. 프런트 컨펌 전이므로 이 문서는 협의 초안이며 백엔드 이슈는 아직 게시하지 않았다.

## 이번 프런트 반영

- 청소 목차, 근무표, 랜덤 배정, 객실별 담당 선택, 메이드별 배정 요약, 저장·통보를 와이어프레임에 맞춰 연결했다.
- 청소 순서 번호·입력·조정 문구를 제거했다. 현재 API 필수 `sequenceNumber`는 adapter 내부 호환 값일 뿐 메이드의 수행 순서를 지시하지 않는다.
- 더보기 청소 템플릿 메뉴와 직접 액션을 차단했다. 사진 업로드에 필요한 서버 슬롯 조회는 유지한다.
- 송금 여부 스위치에서 기존 start/paid 명령을 연결했다. 현재 API 필수 참조번호만 별도 확인한다. 앱이 돈을 송금하는 것은 아니다.
- 일반 사진 1~20장, 모바일 갤러리 다중 선택, 남은 수량 내 추가, 폭탄방/특이사항 별도, 최근 7일 사진 이력·확대와 홈 목적지/뒤로가기를 유지했다.

## 구현 구분과 수용 테스트

- 프런트는 API로 가능한 담당 선택·통보·사진·검수·이력·주급 조회/완료 기록을 연결했다. 위 API 미지원 기능을 완료한 것으로 보고하지 않는다.
- 제출 후 변경 범위는 현재 촛불과 새 특이사항으로 가정했다. 제출 사진·기존 검수 결과 수정은 구현하지 않았다. 송금 해제는 오표시 정정으로 가정했으며 세부 권한은 협의 대상이다.
- API 지원 후: 같은 메이드가 제출→검수 대기→승인 뒤 촛불 감소/새 이슈 등록, 다른 메이드/이전 담당 403, 제출본 및 주급 불변을 확인한다.
- 지급: 같은 주차·메이드만 on/off, 중복 클릭 1회, 409 최신값 갱신, 응답 유실 동일 키 재시도, 금액 변경 시 자동 완료 금지를 확인한다.
- 사진: 0장 제출 차단, 1/20장 성공, 21장 무전송, 7+13 성공/7+14 무전송, 증빙과 일반 사진 분리, 7일 이력 확대를 확인한다.
- 모든 자동 쓰기 검증은 로컬 API fixture다. 실제 운영 계정·객실에서 제출/승인/송금 표시를 임의로 만들지 않았다.
