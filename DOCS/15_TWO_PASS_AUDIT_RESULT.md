# 캐슬디아트 최종 2회 감사 결과

- 감사 대상: `castle-the-art-ux-audit.md` 최종 제품 기준
- 감사일: 2026-08-14
- 결과: 출시·와이어프레임 설계를 가르는 발견사항을 모두 기준 문서에 반영했으며, 남은 항목은 사용자가 추후 입력하기로 한 운영 데이터뿐이다.

## 1차 감사 — 정책·상태·정산·권한

다음 축을 처음부터 다시 추적했다.

- 수동 예약과 입실 가능 상태 분리
- 예약 겹침, 체크인·체크아웃 자동 전이, 레이트 체크아웃 충돌
- 예약별 입실 준비 의무와 원 청소·재청소 연결
- 공개 일감 선점, 관리자 직접 배정, 취소·재배정 동시성
- 청소 수행·사진 동기화·전체 제출·검수 단일 결정
- 촛불·특이사항·운영 중지의 입실 차단 반영
- 재청소 수익 귀속과 월~일 주급 잠금
- 오프라인 작업, 메이드 비활성·퇴사, 개인정보·사진 보존
- 계정·로그인 비밀번호와 객실 PIN 권한 분리

1차에서 발견한 개별 작업 단가 수정, 이전 제출 버전 검수, 준비 청소 링크 단절, 중복 담당·수행, 승인·정산 중복, 오프라인 신규 작업 시작, 중단자의 유효 제출, 과거 담당 덮어쓰기 같은 모순을 제거했다. 상태·돈·권한을 화면 색이나 클라이언트 토글이 아니라 서버 판정 가능한 원장·버전·이벤트로 정의했다.

## 2차 감사 — 회귀·화면 소유권·구현 준비도

1차 수정본을 독립적으로 다시 읽어 P0 3건, P1 8건을 확인했고 모두 반영했다.

| 심각도 | 발견사항 | 최종 반영 |
|---|---|---|
| P0 | 새 제출 뒤 이전 버전도 검수될 수 있음 | 현재 제출 포인터와 `SUPERSEDED`, 최신 제출 조건부 승인·반려 |
| P0 | 실제 도어락 PIN 변경 뒤 앱 저장 실패 복구 없음 | PIN 변경 lease, 불일치 차단, 재입력 저장 또는 물리 원복만 허용 |
| P0 | 외부 송금을 먼저 하면 복수 관리자가 중복 송금 가능 | 송금 전 `OPEN → PAYING` 선점, 확인 필요 상태, 이후 `PAID` |
| P1 | 예약 순서 변경·재청소가 준비 청소 링크를 끊음 | 불변 준비 의무와 객실 일정 잠금 안의 앞뒤 관계 재계산 |
| P1 | 비활성 중단 증빙의 종결·보존 기준 불명확 | 담당·회차·lease 종결 게이트와 관리자 종결 후 180일 보존 |
| P1 | 지급 정정이 지급 잠금 밖에서 생성될 수 있음 | 같은 지급 주차 행 잠금과 고유 원천 ID, 지급 후 다음 주 정정 |
| P1 | 큐마다 정본 상세가 달라 구현이 분기될 수 있음 | 객실·청소·메이드·컴플레인·지급 상세 소유권 표 |
| P1 | 예약·PIN 충돌이 빨강 표시에서 끝남 | 객실 `영향 확인·충돌 해결` 화면과 종결 조건 |
| P1 | 조회 실패를 0건으로 오인할 수 있음 | 불러오는 중·0건·데이터·오래된 데이터/오류 네 상태 |
| P1 | 연박 청소 생성 입력·검증·공개 연결 없음 | 예약 상세 생성 폼, 시간 검증, 비공개 작업·공개 대기 연결 |
| P1 | 컴플레인 접수 뒤 관리자·메이드 왕복 화면 없음 | 접수→확인→판정→확인/이의→종결 상세 흐름 |

## 자동 일관성 검사

- Markdown 코드 펜스: 32개, 열고 닫힘 정상
- Mermaid 흐름도: 13개
- MVP 수용 기준: 1~82번 연속, 누락·중복 없음
- 손상된 유니코드 대체 문자: 0개
- 감사 근거로 연결한 현재 시안 파일: 누락 없음
- 제거 대상 문구: 이전 준비 청소 ID, 수동 추가수당, 모든 큐의 청소 상세 강제, 사진별 승인 강제, 외부 송금 후 직접 `OPEN → PAID` 전이 잔존 없음

## 남은 운영 데이터

아래는 제품 모순이나 질문 대기가 아니라 관리자가 나중에 입력할 값이다.

- 실제 객실 번호와 네 객실 타입의 매핑
- 객실 타입별 실제 청소 단가와 예상시간
- `객실 타입 × 퇴실·연박·재청소`별 체크리스트와 필수·선택 사진 템플릿

클릭형 와이어프레임에서는 위 값을 모두 `데모`로 표시해 구조와 흐름을 먼저 검증한다.
