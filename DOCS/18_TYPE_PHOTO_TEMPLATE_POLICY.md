# 객실 타입별 청소 사진 템플릿 정책

- 확정일: 2026-08-16
- 메이드 사진 전용 확정일: 2026-08-18
- 근거: 사용자 제공 `clean-template/` 사진 123장, 2026년 8월 객실 마스터, 현재 클릭형 와이어프레임 구현
- 상태: 타입별 청소 사진 템플릿의 구현 기준

## 1. 적용 범위와 우선순위

이 문서는 청소 완료 사진의 촬영 구역을 객실 타입별로 구성하고 실제 객실 레이아웃에 맞게 보정하는 방법을 구체화한다. 현재 메이드 템플릿·수행·현장 완료·전체 제출은 체크리스트 없이 구역별 사진만 사용한다. 이 범위에서는 `DOCS/FINAL_UX_AUDIT.md`와 `DOCS/14_CLICKABLE_WIREFRAME_HANDOFF.md`의 기존 체크리스트 요구를 대체한다. 근무 가능일·관리자 전날 배정·폭탄방·무급 재청소는 `DOCS/16_WEEKLY_AVAILABILITY_ASSIGNMENT_POLICY.md`, 그 밖의 제품·보안·보존 정책은 `DOCS/FINAL_UX_AUDIT.md`를 따른다. 충돌할 때는 현재 사용자의 명시적 결정과 저장소의 기존 정본 문서를 우선한다.

`clean-template/`은 사용자 제공 참고 원본이며 앱의 운영 사진 저장소가 아니다. 이 문서의 `원본 비반입`은 참고 원본 123장을 템플릿 이미지나 앱 자산으로 복사하지 않는다는 뜻이다. 메이드가 실제 업무에서 새로 촬영하는 제출 사진은 별도의 청소 제출·보존 정책을 따른다.

이 문서와 기존 템플릿 코드의 `연박 청소`는 체류 기간과 관계없이 투숙 중인 객실에서 요청하는 `투숙 중 청소` 유형을 뜻한다. 장기투숙 상태나 전용 객실 분류를 만들지 않는다.

## 2. 참고 사진 감사 결과

파일명과 폴더명은 객실 번호가 아닌 KakaoTalk 내보내기명과 `1`–`9` 순번이다. EXIF에도 객실 번호가 없어 각 폴더의 첫 객실 표지 사진을 육안 확인해 다음처럼 매핑했다. 이 매핑을 파일명만으로 다시 자동 추론해서는 안 된다.

## 3. 타입별 청소요금 정본

- 사용자 제공 시트의 청소요금을 운영 정본으로 사용한다: 스탠다드 16,000원, 프리미어 20,000원, 파셜 오션뷰 20,000원, 패밀리 투룸 30,000원.
- 위 금액은 데모 fixture나 예상값이 아니다. 와이어프레임의 객실 카드·배정·템플릿·검수·폭탄방·주급 원장은 모두 이 타입별 기본 청소요금을 사용한다.
- 유상 작업 생성 시 당시 정본 단가를 작업·수익 자격에 스냅샷으로 고정한다. 이후 단가가 바뀌더라도 기존 작업·제출·검수·수익 이력을 소급해서 덮어쓰지 않는다.
- 폭탄방 인정과 전체 청소 승인이 함께 끝나면 해당 객실만 `기본 청소요금 + 동일 금액 추가요금`으로 정확히 2배가 된다. 타입별 총액은 스탠다드 32,000원, 프리미어 40,000원, 파셜 오션뷰 40,000원, 패밀리 투룸 60,000원이다.
- 전체 반려 뒤 최초 수행자 본인에게 자동 귀속되는 재청소는 정본 단가와 무관하게 무급 0원이며 새 수익 원장을 만들지 않는다.
- 객실 점유와 기준정보는 `DOCS/17_ROOM_CATALOG_LONG_STAY_DECISIONS.md`를 따른다. 점유 상태는 `투숙 / 공실`이고 장기투숙 전용 상태·필터·패널은 없다. 11실은 최초 투숙 seed일 뿐이며 `고객 배정 가능`은 청소·안전·운영 조건을 만족한 공실의 파생 결과다. 762호의 `확인 필요`는 세 번째 점유 상태가 아닌 데이터 품질 배지다. 관리자는 읽기 전용 호수를 제외한 객실 타입·엘리베이터 위치를 수정할 수 있고, 확인을 마칠 때까지 762호의 고객 배정·청소 배정만 잠근다.

## 4. 원본 비반입과 개인정보

- 참고 원본 파일, 썸네일, 파일명, 로컬 경로, EXIF, 해시를 `WIREFRAME/index.html`, 저장소 자산, URL, 로그, 알림, 브라우저 영속 저장소에 넣지 않는다.
- 와이어프레임에는 타입별 참고 객실 번호·사진 수와 원본에서 추출한 촬영 구역 문구만 둔다. 참고 사진 자체를 메이드의 정답 예시처럼 보여주지 않는다.
- 객실 표지 사진 일부에는 운영 연락처 등 개인정보성 문구가 있다. 얼굴, 거울 반사, 고객 물품, 연락처, 켜진 TV 화면도 템플릿 자료로 재사용하지 않는다.
- 실제 서비스에서 관리자용 예시 이미지를 별도로 운영한다면 원본을 그대로 가져오지 않고 권리·개인정보를 확인한 비식별 파생본을 새 자산 ID와 보존정책으로 등록한다.
- 메이드의 새 청소 제출 사진에는 `연락처·얼굴·고객 물품·켜진 TV 화면 제외` 안내를 고정하고, 검수자는 제출 전체와 연결된 당시 템플릿 스냅샷을 함께 본다.

## 5. 타입 기본 규칙

퇴실 청소 사진 템플릿은 객실별 사진 10–18장을 그대로 복제하지 않고, 여러 객실에서 반복 확인된 공간을 `촬영 구역`으로 정규화한다. 한 구역은 여러 장을 허용할 수 있으며 필수 여부는 사진 장수보다 구역 충족 여부로 판단한다.

| 타입 | 퇴실 청소 촬영 구역 | 필수 / 선택 | 주요 기본 구역 |
|---|---:|---:|---|
| 스탠다드 | 9개 | 8 / 1 | 현관, 스튜디오형 메인 공간, 주방·가전, 드레스룸, 욕실·배수구 |
| 프리미어 | 10개 | 9 / 1 | 현관, 침실별, 거실, 수납, 주방·가전, 욕실별·배수구 |
| 파셜 오션뷰 | 12개 | 11 / 1 | 현관, 침실별, 높은 창 거실, 계단·하부 수납, 팬트리, 주방·가전, 욕실별 |
| 패밀리 투룸 | 10개 | 9 / 1 | 현관, 침실별, 거실·식당, 침실별 수납, 주방·가전, 욕실별 |

선택 구역은 모든 타입의 추가 설비·비품·하자·특이사항 증빙이다. 퇴실 청소 외 연박 청소와 재청소는 현재 표본 123장에서 도출했다고 표현하지 않고 별도 데모 규칙으로 구분한다.

## 6. 타입 기본 + 객실 레이아웃 보정

1. 작업 생성 시점의 객실 번호로 관리자가 수정할 수 있는 현재 객실 마스터의 타입을 결정한다.
2. `객실 타입 × 청소 유형`의 현재 활성 템플릿을 불러온다.
3. 퇴실 청소에는 위 타입 기본 촬영 구역을 적용한다.
4. 사진으로 확인한 객실은 `ROOM_LAYOUT_PROFILES`의 침실·욕실·배수구·팬트리 수를, 확인하지 못한 객실은 타입별 최소 공통값을 사용한다.
5. `침실별`, `욕실별`, `침실별 수납`, `욕실별 배수구`처럼 반복 가능한 구역은 실제 개수만큼 펼친다. 존재하지 않는 공간을 필수 사진으로 요구하지 않고, 타입 기본에서 빠진 추가 공간은 객실 보정 구역으로 더한다.
6. 관리자가 작업 생성 전 보정 결과를 확인하고, 작업 생성 시 타입·단가·예상시간·촬영 구역·필수 여부·반복 수를 하나의 버전 스냅샷으로 고정한다. 이후 객실 타입을 수정해도 이 스냅샷은 바뀌지 않는다.
7. 템플릿이나 레이아웃을 나중에 바꿔도 이미 생성·배정·수행·제출된 작업에는 소급하지 않는다. 새 작업부터 새 버전을 사용한다.

현재 사진으로 확정한 레이아웃 프로필은 다음 9객실이다. 숫자는 `침실 / 욕실 / 배수구`이며, 템플릿에 반복 속성이 있는 필수 촬영 구역을 이 수만큼 개별 슬롯으로 펼친다.

| 타입 | 사진 확인 객실 | 침실 / 욕실 / 배수구 | 추가 보정 |
|---|---|---:|---|
| 스탠다드 | 750호 | 1 / 1 / 2 | 없음 |
| 프리미어 | 651호 | 1 / 1 / 1 | 없음 |
| 프리미어 | 540호 | 2 / 2 / 2 | 없음 |
| 프리미어 | 455호 | 1 / 1 / 2 | 없음 |
| 파셜 오션뷰 | 639·641호 | 각 1 / 1 / 1 | 팬트리 있음 |
| 파셜 오션뷰 | 536호 | 1 / 1 / 1 | 팬트리 없음 |
| 패밀리 투룸 | 645호 | 2 / 2 / 2 | 없음 |
| 패밀리 투룸 | 542호 | 1 / 1 / 1 | 없음 |

레이아웃 보정은 같은 타입의 모든 객실이 같은 방·욕실 수를 가진다고 가정하지 않기 위한 필수 단계다. 사진으로 프로필을 확정하지 못한 나머지 112실은 `레이아웃 확인 보류`로 둔다. 이들에게는 침실 1·욕실 1·배수구 1의 최소 공통 슬롯만 생성하고 화면에 보류 사유를 노출한다. 실제 서비스 전에는 이 112실의 레이아웃 마스터를 관리자가 확인해야 한다. 이 템플릿 품질 표식은 762호의 점유·기준정보 `확인 필요`와 무관하며 투숙·공실을 바꾸지 않는다.

## 7. 역할과 화면 계약

### 관리자

- `더보기 → 청소 템플릿`에서 4개 타입 × 퇴실·연박·재청소 12개 조합을 본다.
- 객실 상세의 별도 기준정보 편집에서 객실 타입과 엘리베이터 위치를 수정한다. 호수는 읽기 전용이며 타입 변경은 새 작업에만 반영한다.
- 타입 목록에는 정본 기본 청소요금·참고 객실·사진 수를 표시하되 원본 사진은 노출하지 않는다.
- 상세에서 활성 버전, 예상시간, 필수·선택 촬영 구역, 다중 사진·반복 가능 여부를 본다.
- 작업 생성 전 객실 레이아웃 보정 결과를 확인하고, 검수에서는 제출 당시 스냅샷과 메이드가 올린 사진을 함께 본다.
- 템플릿 변경은 새 버전으로 게시하며 기존 작업을 바꾸지 않는다.
- 현행 템플릿 설정과 검수에는 메이드 체크리스트를 노출하거나 완료 조건으로 요구하지 않는다.

### 메이드

- 본인에게 통보된 작업의 읽기 전용 템플릿 스냅샷만 본다.
- `현관 / 침실 / 거실 / 주방 / 욕실`처럼 구역별 사진 카드만 이어서 처리한다. 별도 체크리스트·체크박스·체크 진행 수는 표시하지 않는다.
- 구역 완료와 현장 완료는 해당 작업 스냅샷의 필수 사진 슬롯이 모두 채워지고 처리 중·실패 사진이 없을 때만 가능하다. 선택 사진은 없어도 완료할 수 있다.
- 각 촬영 슬롯의 필수·선택, 실제 레이아웃 수만큼 반복 여부와 현재 상태를 확인한다. 한 슬롯은 현재 사진 1장만 유지하며 제출 전 재촬영으로 교체하거나 삭제할 수 있다.
- `바로 촬영`은 `accept="image/*" capture="environment"`인 해당 슬롯 입력을 열어 지원 기기에서 후면 카메라를 요청하고, `갤러리`는 별도 `accept="image/*"` 입력을 연다. 브라우저·기기 정책에 따라 `바로 촬영`도 파일 선택기로 열릴 수 있으므로 후면 카메라 실행 자체를 저장 성공 조건으로 삼지 않는다.
- 선택한 사진은 현재 탭 메모리의 `blob:` 미리보기로만 확인한다. 원본 파일명과 `blob:` URL 문자열은 화면·URL·로그·알림·브라우저 영속 저장소에 노출하거나 저장하지 않는다.
- 필수 구역의 새 현장 사진이 서버 검증 완료되기 전에는 전체 제출할 수 없다.
- 참고 원본 123장과 다른 객실의 템플릿·제출 사진은 볼 수 없다.

## 8. 현재 와이어프레임 구현과 한계

`WIREFRAME/index.html`은 다음을 결정적 메모리 상태로 표현한다.

- `PHOTO_TEMPLATE_EVIDENCE`: 타입별 참고 객실과 11/42/42/28장 표본 메타데이터
- `TYPE_PHOTO_GROUPS`: 퇴실 청소의 타입별 필수·선택 촬영 구역
- `ROOM_LAYOUT_PROFILES`: 사진으로 확인한 9객실의 침실·욕실·배수구·팬트리 보정값
- `expandPhotoRules()`: 작업 생성 시 반복 규칙을 객실 프로필 수만큼 서로 다른 필수 슬롯으로 확장
- `taskZoneGroups()`: 사진 슬롯의 ID·필수 여부·반복 수를 보존한 채 촬영 구역 카드로 묶어 렌더링
- `templateCatalog()`: 4개 타입 × 3개 청소 유형의 12개 활성 조합
- `templateSnapshotFor()`: 작업 생성 시 템플릿·단가·예상시간·사진 규칙 고정
- 메이드 구역별 사진 카드, 슬롯별 카메라·갤러리 입력, 현재 사진 1장 교체·삭제와 로컬 `blob:` 미리보기
- 관리자 템플릿 목록·상세·부분 편집, 메이드 작업 상세, 관리자 제출 검수에서 같은 버전과 제출 사진 표시

현재 구현은 운영 제품이 아니라 다음 한계를 가진다.

- 참고 원본 123장은 저장소와 앱에 반입하지 않았다. 사용자가 슬롯에서 새 이미지를 촬영·선택하면 현재 탭 메모리의 `blob:` 미리보기를 사용하고, 선택하지 않은 데모 제출은 SVG fixture로 구분한다.
- 사진 확인 9객실은 정확한 반복 슬롯을 생성한다. 나머지 112실은 확정 레이아웃 마스터가 없어 최소 공통 슬롯과 `레이아웃 확인 보류` 안내를 사용한다.
- 템플릿 편집 데모는 예상시간만 바꾼다. 촬영 구역 추가·삭제·순서·객실 보정·초안/게시 승인 서버는 구현하지 않았다.
- 퇴실 청소 촬영 구역만 123장 표본을 반영했다. 연박·재청소 사진 규칙과 예상시간은 데모 fixture지만 타입별 기본 청소요금 16,000/20,000/20,000/30,000원은 운영 정본이다.
- 카메라·갤러리 입력과 로컬 미리보기는 동작하지만 실제 이미지 서버 전송·형식/크기/해시 검사·악성 파일 검사·오프라인 재전송·180일 보존·동시 편집·서버 권한 검사는 구현하지 않았다. 지원 모바일에서 후면 카메라가 실제로 열리는지는 실기기에서 별도 확인해야 한다.
- 새로고침·초기화·탭 종료 뒤 템플릿 편집과 사진 상태는 복원되지 않으며, 실제 청소 제출이나 검수 효력을 만들지 않는다.

## 9. 수용 기준

- 관리자 목록에 네 타입과 퇴실·연박·재청소 12개 조합이 구분된다.
- 타입별 참고 객실·사진 수는 위 감사 결과와 일치하고 원본 파일·로컬 경로·개인정보는 앱에 포함되지 않는다.
- 객실 카드·배정·템플릿·검수·폭탄방·주급의 기본 청소요금이 스탠다드 16,000원, 프리미어 20,000원, 파셜 오션뷰 20,000원, 패밀리 투룸 30,000원으로 일치한다.
- 객실의 정상 점유 표시는 `투숙 / 공실`이고 장기투숙 전용 상태·필터·패널이 없다. 최초 11실은 일반 투숙 seed로만 표시하며 `고객 배정 가능`은 준비 조건을 만족한 공실에서만 파생된다.
- 관리자는 모든 객실에서 읽기 전용 호수와 수정 가능한 타입·엘리베이터 위치를 확인한다. 타입 변경 뒤 새 작업은 새 타입 템플릿·단가를 사용하고 기존 작업의 템플릿·단가 스냅샷은 유지한다.
- 퇴실 청소의 필수·선택 구역 수와 촬영 안내가 타입마다 구분된다.
- 사진으로 확인한 9객실의 침실·욕실·배수구 반복 구역은 객실 프로필 수만큼 개별 필수 슬롯으로 생성된다.
- 나머지 112실은 최소 공통 슬롯만 생성하고 `레이아웃 확인 보류`와 사유를 표시한다.
- 작업 생성 시 활성 템플릿과 객실 보정 결과를 고정하며 이후 변경이 기존 작업·제출·검수 이력을 덮어쓰지 않는다.
- 메이드는 본인 작업의 스냅샷만 보고 관리자는 제출 당시 스냅샷으로 검수한다.
- 메이드 작업 상세에는 체크리스트·체크박스·체크 진행 수·`필수 체크` 문구가 없고, 구역별 필수·선택 사진만 표시한다.
- 필수 촬영 구역 누락, 사진 처리 중·실패, 업로드 미검증은 현장 완료와 전체 제출을 막는다. 체크리스트 값은 현장 완료·전체 제출·관리자 검수 조건에 사용하지 않는다.
- 관리자 템플릿 목록·상세와 현행 제출 검수도 사진 구역과 제출 사진을 기준으로 표시하며 메이드 체크리스트 완료를 요구하지 않는다.
- 모든 촬영 슬롯에 `accept="image/*" capture="environment"` 카메라 입력과 `accept="image/*"` 갤러리 입력이 있고, 버튼은 해당 시도의 현재 슬롯을 다시 검증한 뒤 입력을 연다. 상태만 완료로 바꾸는 가짜 사진 추가 행동은 없다.
- 슬롯마다 현재 사진은 1장이고 재촬영은 기존 사진을 교체한다. 제출 전 삭제 뒤에는 해당 슬롯이 다시 미완료가 되며, 파일명·로컬 `blob:` URL 문자열이 화면·URL·로그·브라우저 영속 저장소에 남지 않는다.
- 메이드 구역별 사진 촬영 화면은 360/390/768/1440px에서 가로 넘침, 카메라·갤러리·삭제 컨트롤 최소 44×44px, 접근성 이름, 키보드 포커스, 브라우저 파일 선택기, 콘솔 warning/error를 실제 브라우저로 검증하고 대표 390px·1440px PNG를 남긴다. 물리 모바일의 후면 카메라 실행은 자동화 결과와 구분해 별도 실기기 확인으로 기록한다.
- 기존 관리자 템플릿과 메이드 528호의 체크리스트 포함 화면은 이전 검증 기록으로만 보존한다. 새 사진 전용 화면 검증은 별도 QA 항목과 같은 `maid-zone-camera-390.png`, `maid-zone-camera-1440.png` 파일의 최신 캡처로 기록하며, 편집·게시 서버와 121실 전체 프로필은 현재 수용 범위가 아니다.
