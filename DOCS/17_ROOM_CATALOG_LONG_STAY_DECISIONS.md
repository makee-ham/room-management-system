### 메이드 청소 정보 · 2026-10-30 사용자 확정

- 베딩 수는 스탠다드·프리미어·파셜 오션뷰 프리미어 각각 1개, 패밀리 투룸 2개다. 숙박 인원과 별개의 항목이다.
- 통보된 메이드 업무 카드와 펼친 업무 정보에 청소 유형(퇴실·연박·추가·재청소)과 베딩 수를 표시한다.
- 베딩 수는 배정에 보존된 객실 타입으로 계산하며 현재 객실 마스터로 과거 작업을 덮어쓰지 않는다. 타입 근거가 없으면 `유형 확인 필요`로 표시한다.
- 청소 추가 객실 선택은 유형별 굵은 제목과 호수 오름차순 목록으로 제공하며 객실번호·유형명으로 검색한다. 검색 결과에 선택 객실이 없으면 선택을 해제하고 계속 버튼을 비활성화한다.

위 개수는 초기 반입 결과이지 변경할 수 없는 하드코딩 집계가 아니다. 객실은 불변 내부 ID로 식별하고 현재 호수는 그 내부키와 연결되어 있어 관리자 화면에서 읽기 전용으로 둔다. 관리자는 모든 객실 상세에서 다음 기준정보를 수정할 수 있다.

- 객실 타입: 확정된 네 타입 중 하나
- 엘리베이터 위치: `A / B / C / 미기재`

저장하면 목록·상세·청소 대상·배정 추천의 현재 기준정보와 타입·엘리베이터 집계를 다시 계산하고, 이전 값·새 값·관리자·시각을 감사 이력에 남긴다. 타입을 바꾸면 새로 생성하는 작업부터 새 타입의 단가·템플릿을 사용한다. 이미 생성·배정·수행·제출된 작업의 타입·단가·템플릿 스냅샷과 과거 객실 이력은 소급 변경하지 않는다.

## 2. 점유와 객실 카드 주 상태

### 퇴실 예정 집계·필터 · 2026-10-30 사용자 확정

- 명칭은 집계·필터·카드 모두 `퇴실 예정`으로 통일한다. 이미 퇴실한 객실을 뜻하는 `퇴실`·`퇴실 객실`과 구분한다.
- 선택한 한국시간 날짜에 체크아웃 예정이고, 조회 기준 시각에 아직 종료되지 않은 현재 유효 예약의 객실을 한 번씩 센다. 레이트 체크아웃은 조정된 예정 시각을 사용한다. 취소·수동 퇴실·예정 퇴실 시각 도달·종료일 미정은 제외한다.
- 운영은 선택일 객실 projection의 `reservationPhase`, `displayReservationId`, `displayCheckInAt`, `displayCheckOutAt`, `evaluatedAt`으로 판정한다. 오늘은 서버 조회 시각, 미래는 선택일 시작, 과거는 선택일 종료 기준이다. 과거의 하루 전체 퇴실 건수로 해석하지 않는다. 필수 근거 미제공·조회 중·실패는 0개로 표시하지 않는다.
- 오늘 객실 요약의 기존 4개 카드를 유지하고 그 아래 작은 `퇴실 예정 N개` 바로가기를 둔다. 객실 현황의 전체 객실 수 옆에도 같은 바로가기를 둔다. 전체 객실 기준 집계이며 클릭하면 검색·유형 조건을 해제하고 같은 날짜의 퇴실 예정 목록을 연다.
- 기존 상태 필터의 상세 조건에 `퇴실 예정`을 추가하며 객실번호 검색·유형 필터와 함께 사용할 수 있다. 카드의 기존 체크아웃 일정 줄에만 작은 표시를 더한다.
- 주 상태와 색·점유·버튼 목적지는 유지한다. 퇴실 예정은 투숙 중 또는 배정 불가 등과 겹치는 일정 조건이므로 주 상태 합계에 더하지 않는다.

정상적인 객실 점유 상태는 `투숙 / 공실` 두 가지다. `장기투숙`은 별도 객실 상태, 필터, 집계, 상세 패널이 아니다. 체류 기간과 관계없이 현재 유효한 점유가 있으면 `투숙`, 없으면 `공실`로 표시한다.

- `장기-결제` 시트에서 활성으로 확인된 139·358·359·449·458·461·553·558·559·628·629호 11실은 앱 최초 상태를 만들기 위한 `투숙` seed다. 화면에서 장기투숙 11실로 따로 구분하거나 시작일·시트 출처를 노출하지 않는다.
- 위 11실과 762호를 제외한 109실은 최초 `공실` seed다.
- 109실은 별도 운영·청소 fixture가 덮어쓰지 않은 초기 화면에서 준비 완료 근거도 함께 seed해 점유는 `공실`, 카드 주 상태는 `배정 가능`으로 파생되게 한다. 이는 고정 마스터 상태가 아니며 이후 점유·청소·차단 사건으로 다시 계산한다.
- 527호의 이전 장기 체류는 종료 이력일 뿐이며 최초 현재 상태는 `공실`이다.
- 142호도 장기투숙 예외가 아니라 현재 예약·점유에 따라 투숙 또는 공실이 되는 일반 객실이다.
- 762호는 점유 근거가 불명확하므로 `확인 필요` 데이터 품질 배지를 둔다. 이는 세 번째 점유 상태가 아니며 카드 주 상태 `배정 불가`의 상세 사유다. 관리자가 기준정보와 실제 점유를 확인해 `투숙` 또는 `공실`로 확정하기 전에는 고객 배정과 청소 배정을 잠그되, 기준정보 수정과 상태 확인 행동은 제공한다.

`배정 가능`은 고객에게 객실을 배정할 수 있다는 카드 주 상태이며, 객실 마스터에 저장하는 점유 상태가 아니다. 다음 조건을 모두 만족하는 공실에서만 계산한다.

- 현재 점유가 `공실`
- 직전 점유·오염 뒤 필요한 청소가 승인됨
- 운영 중지, 촛불, 미해결 입실 차단, PIN 불일치가 없음
- 기준정보·점유 확인이 보류 중이 아님

따라서 수동 또는 예정 체크아웃 직후의 객실은 점유 `공실`과 카드 주 상태 `청소 필요`를 갖는다. 청소·안전 조건까지 해결된 공실에서만 카드 주 상태를 `배정 가능`으로 바꾸며, 투숙 객실에는 배정 가능을 표시하지 않는다.

### 객실 카드 주 상태·색상 정본

객실 카드의 가장 눈에 띄는 주 상태는 아래 네 가지 중 정확히 하나만 표시한다. 이 값은 객실 마스터에 저장하는 단일 상태가 아니라 선택 날짜의 점유·청소·안전 원본 상태에서 계산한 카드 표현이다. `DOCS/FINAL_UX_AUDIT.md`의 기존 카드 색·주 상태 표현은 이 절과 충돌하는 범위에서만 이 절이 대체하며, 기존 상세 상태 축·사유·감사 이력은 유지한다.

| 카드 주 상태 | 색 | 파생 조건 |
|---|---|---|
| `투숙 중` | 회색 | 현재 점유 중이고 더 높은 우선순위의 배정 불가 사유나 선택 대상일의 청소 필요가 없는 객실 |
| `청소 필요` | 주황 | 선택 대상일에 퇴실 청소 또는 투숙 중 청소 요청에 따른 연박 청소가 필요한 객실 |
| `배정 가능` | 초록 | 공실이고 직전 점유·오염 뒤의 필요 청소가 승인됐으며 운영·안전·정보 확인 차단이 없는 객실 |
| `배정 불가` | 빨강 | 운영 중지, 촛불, 미해결 입실 차단 특이사항, PIN 불일치, 기준정보·점유 확인 보류 등 청소 외 사유로 고객에게 배정할 수 없는 객실 |

여러 조건이 겹치면 `배정 불가 → 청소 필요 → 투숙 중 → 배정 가능` 순서로 하나를 고른다. 청소 미완료 자체는 `배정 불가`가 아니라 `청소 필요`다. `배정 가능 / 배정 불가`는 고객에게 객실을 배정할 수 있는지를 뜻하며, 청소 담당자 배정 상태인 `미배정 / 저장 전 / 통보 완료 / 변경 통보 완료`와 혼용하지 않는다.

촛불 수, 입실 차단 특이사항, 운영 중지, 정보 확인 필요 등 기존 세부 분류는 삭제하지 않고 주 상태 아래의 상태명·아이콘·이유로 보존한다. `청소 미배정`, `청소 중`, `현장 완료·업로드 대기`, `검수 대기`, `재청소` 같은 청소 진행 단계는 주 상태를 대체하지 않는 덜 중요한 서브 배지로 표시한다.

전날 미배정이거나 미완료여서 다음 날로 넘어온 객실도 카드 주 상태는 계속 `청소 필요`다. 별도 주 상태나 색을 만들지 않고 `전일 이월 · 미배정` 또는 `전일 이월 · 미완료`, `원 계획 M/D`, 필요할 때 `이월 N일째`를 청소 진행 서브 배지로만 표시한다. 같은 청소대상 ID·불변 원 계획일·이전 담당과 수행 이력, 다음 날 배정·계속 수행의 상세 규칙은 `DOCS/16_WEEKLY_AVAILABILITY_ASSIGNMENT_POLICY.md`를 따른다. 현장 완료 뒤 업로드 대기와 전체 제출 뒤 검수 대기는 전일 청소 배정 이월로 표시하지 않고 각각 기존 진행 배지를 유지한다.

`얼리 체크인 · N시간`과 `레이트 체크아웃 · N시간`은 청소 진행 서브 배지보다 눈에 잘 띄는 일정 배지로 표시하고, 조정된 실제 예정 시각을 같이 보여준다. 얼리·레이트 자체는 카드 주 상태나 색을 바꾸지 않는다. 기본 시각이면 특수 배지를 표시하지 않는다.

카드가 표시하는 현재 또는 가장 가까운 유효 예약의 총 숙박 인원이 해당 객실 타입의 기준인원보다 많을 때만, 기준 인원과의 차이를 `N인 추가` 형식의 일정 강조 배지로 표시한다. 예를 들어 기준 4명인 패밀리 6명 예약은 `2인 추가`다. 기준인원 이하이거나 예약이 없는 카드에는 인원 배지를 표시하지 않는다. 운영에서는 객실 projection의 `displayGuestCount`와 `displayBaseOccupancy`를 우선 사용하고 미제공 값을 fixture로 채우지 않는다. 객실 상태 필터의 `인원 추가`는 이 동일한 조건의 카드만 모아 보여 준다.

카드형 객실 목록에는 별도의 큰 예약 요약 행을 두지 않는다. 체크인→체크아웃 일정 행과 얼리·레이트·연박 일정 배지는 유지하고, 예약 등록·수정·취소 진입은 카드 하단의 예약 버튼 하나로 통합한다.

유효한 2박 이상 예약에서 선택 날짜가 체크인 당일부터 투숙 기간 안에 있을 때, 안정적인 예약 ID의 체크인·체크아웃을 근거로 현재 일차와 전체 일차를 계산해 `4박 2일차` 형식의 일정 강조 배지로 표시한다. 2026-10-30 사용자 결정에 따라 체크인 당일은 예정 시각 전의 `입실 예정` 카드에도 `4박 1일차`를 인원 추가 배지 바로 옆에 표시한다. 이 연박 진행도는 별도 주 상태·필터·집계가 아니며 카드 주 상태나 색을 바꾸지 않는다. 체크인 날짜 전·체크아웃 후에는 표시하지 않고, 최초 장기투숙 seed처럼 전체 숙박일 근거가 없으면 일차를 추정하거나 배지를 만들지 않는다. 1박에는 연박 배지를 표시하지 않는다. 체크인 날짜를 1일차로 계산하고 체크아웃 직전까지 마지막 숙박 일차를 유지한다(2박 예약은 1일차/2일차). 날짜는 한국 시간과 선택한 조회일을 기준으로 한다.

CSV·엑셀 객실 현황에도 기준 인원·예약 인원·추가 인원·`N인 추가` 문구·총 숙박 수·숙박 일차·연박 문구를 같은 예약 근거로 내보낸다. 1박의 연박 문구와 기간 근거가 없는 예약의 숙박 일차는 비운다. 엑셀에는 읽을 수 있는 열 너비·고정 머리글·필터와 추가 인원/연박 강조색을 제공하며, PIN·고객명은 포함하지 않는다.

모든 투숙 객실은 체류 기간 구분 없이 필요할 때 `투숙 중 청소 요청`을 만들 수 있다. 계획 서비스일·출입 허용 시작·종료·요청 완료 시각을 입력하고, 생성된 작업은 기존 전날 배정·순서·검수·폭탄방 흐름을 재사용한다. 별도 장기투숙 반복 일정과 월별 결제 원장은 현재 객실관리 범위에 포함하지 않는다.

## 3. 예정 전 수동 체크아웃

관리자는 투숙 중인 객실 상세에서 예정 체크아웃 전에도 `지금 체크아웃`을 실행할 수 있다. 체크인 전 예약을 없애는 `예약 취소`와 이미 시작한 투숙을 끝내는 `지금 체크아웃`은 서로 다른 행동이다.

- 확인창에는 객실, 예정 체크아웃, 실제 종료 시각과 점유는 `공실`, 카드 주 상태는 `청소 필요`로 바뀐다는 결과를 보여준다. 예정 체크아웃이 없는 초기 투숙 seed는 `예정 체크아웃 없음`으로 표시하되 지금 체크아웃을 허용한다. 별도 장기투숙 종료 폼은 만들지 않는다.
- 성공하면 예정 체크아웃은 원 예약 일정으로 보존하고 `실제 체크아웃 시각`, 수행 관리자, 기록 시각을 별도 이벤트로 추가한다. 예약과 기존 점유 이력을 삭제하거나 예정 시각을 실제 시각으로 덮어쓰지 않는다.
- 실제 체크아웃과 동시에 점유를 `공실`로 바꾸고 기존 체크아웃 후 청소 출입 흐름을 연다. 청소 승인 전에는 카드 주 상태를 `배정 가능`으로 만들지 않는다.
- 예약에 연결된 활성 퇴실 청소가 있으면 같은 작업을 실제 체크아웃 시각 기준으로 갱신·활성화한다. 없으면 한 건만 생성한다. 동일 예약의 퇴실 청소는 수동 체크아웃 재시도, 화면 재진입, 이후 예정 체크아웃 도달로 중복 생성되지 않는다.
- 이미 배정·통보된 미시작 작업의 일정이 앞당겨지면 같은 작업 ID와 기존 이력을 유지하고 변경 통보를 보낸다. PIN만 조회한 미시작 작업은 기존 조회 lease와 원문을 폐기한 뒤 실제 퇴실 시각부터 다시 조회하게 하며, 청소를 시작한 뒤의 일정 충돌만 기존 예약·출입 충돌 해결 흐름을 사용한다.
- 이미 공실이거나 점유 확인이 보류 중인 객실에는 `지금 체크아웃`을 제공하지 않는다.

## 4. 현재 결정 요약

- 객실 호수는 현재 내부키와 연결된 읽기 전용 값이고, 관리자는 객실 타입과 엘리베이터 위치를 수정할 수 있다.
- 점유 상태는 `투숙 / 공실`만 사용한다.
- 카드 주 상태는 `투숙 중(회색) / 청소 필요(주황) / 배정 가능(초록) / 배정 불가(빨강)` 네 가지만 사용하고 세부 사유·청소 진행 배지를 별도로 유지한다.
- 유효한 다박 예약의 체크인 당일부터 실제 체크아웃 전까지 `N박 n일차`를 일정 강조 배지로만 표시하며, 전체 숙박일 근거가 없으면 추정하지 않는다.
- 장기투숙 전용 상태·필터·집계·상세 패널·월별 결제 원장은 만들지 않는다.
- `배정 가능`은 준비 조건을 모두 만족한 공실의 파생 카드 주 상태다.
- 11실은 최초 투숙 seed이고, 762호의 `확인 필요`는 관리자가 해제하는 데이터 품질 배지다.
- 관리자는 예정 체크아웃 전에 `지금 체크아웃`할 수 있으며 예정·실제 시각과 퇴실 청소 한 건을 분리해 보존한다.
- 건물 지도 보완 뒤 최초 엘리베이터 미기재 객실은 0실이다. 이후 관리자가 위치를 `미기재`로 바꾸는 경우에는 추정값을 자동 저장하지 않는다.


## 2026-08-30 · 장기 투숙과 선택 종료일

- `장기 투숙`은 일반 예약과 구분되는 예약 유형으로 저장한다.
- 종료일을 알고 있으면 종료 일시를 입력하고 객실 카드·상세·예약 관리에 표시한다.
- 종료일을 모르면 입력을 비워 두며 화면에는 `종료일 미정`으로 표시한다.
- 두 경우 모두 투숙 기간에는 `장기` 배지를 표시하고 예약 가능 객실에서 제외한다.
- 종료일이 입력된 장기 투숙은 해당 종료일의 퇴실 청소를 준비한다.
- 종료일 미정 장기 투숙은 일반 퇴실 청소를 미리 만들지 않고, 실제 종료가 기록될 때 퇴실 청소를 만든다.
- 연박·추가 청소처럼 관리자가 명시적으로 만든 투숙 중 청소 요청은 계속 허용한다.

## 예약 임박 상태와 객실 변경 (2026-09-16 · 최신 사용자 결정)

이 절은 위의 `객실 카드 주 상태·색상 정본`과 충돌하는 범위에서 최신 결정으로 대체한다. 점유 원본은 계속 `투숙 / 공실` 두 가지이며, 아래 값은 선택 날짜·운영 시각에 따라 계산하는 화면 주 상태다.

### 예약 임박 상태

- 체크인 날짜가 선택 날짜보다 이틀 이상 뒤라면 미래 예약은 현재 주 상태를 바꾸지 않는다. 해당 예약과 겹치지 않는 다른 기간은 계속 예약할 수 있다.
- 체크인 전날(D-1)에는 주 상태를 `예약 있음`으로 표시한다.
- 체크인 당일 예정 시각 전에는 주 상태를 `입실 예정`으로 표시한다.
- 예정 체크인 시각에 도달하면 주 상태를 `투숙 중`으로 자동 전환한다.
- `입실 예정`과 `예약 있음`은 `배정 불가`가 아니다. `배정 불가`는 운영 중지, 촛불 회수, 미해결 입실 차단, PIN·기준정보 확인 보류처럼 실제 차단 사유가 있을 때만 쓴다.
- 큰 상태의 우선순위는 `배정 불가 → 투숙 중 → 입실 예정 → 예약 있음 → 청소 필요 → 배정 가능`이다. 큰 상태와 별개로 청소 필요·입실 차단·예약 임박 상태를 보조 배지로 함께 표시할 수 있다.
- `배정 가능`은 현재 객실 준비 상태이고, 임의 기간의 예약 가능 여부는 요청한 `[체크인, 체크아웃)` 구간과 기존 예약의 겹침을 검사해 별도로 계산한다. 미래 예약이 있다는 이유만으로 객실 전체를 배정 불가로 만들지 않는다.

### 예약 전 객실 변경

- 체크인 전에는 예약 상세에서 `예약 객실 변경`을 제공한다.
- 예약 ID, 고객·인원·체크인·체크아웃은 유지하고 객실 연결만 바꾼다.
- 대상 객실의 전체 `[체크인, 체크아웃)` 구간 겹침, 운영 차단, 장기 투숙 종료일을 다시 확인한 뒤 한 트랜잭션으로 처리한다.
- 연결된 퇴실 청소가 공개·담당 확정·수행 시작 상태라면 자동으로 덮어쓰지 않고 먼저 청소 배정을 조율한다.

### 투숙 중 방 이동

- 체크인 뒤에는 같은 행동을 `방 이동`으로 표시한다.
- 기존 객실의 투숙 구간은 이동 시각으로 종료하고 삭제하거나 새 객실로 덮어쓰지 않는다.
- 새 객실에는 이동 시각부터 원래 체크아웃까지의 연속 투숙 구간을 만든다. 두 구간은 같은 stay/reservation 그룹으로 연결한다.
- 원 객실은 즉시 공실·청소 필요가 되고, 새 객실은 투숙 중이 된다.
- 원 객실 PIN 접근은 이동 시각에 종료하고, 새 객실 접근 권한은 새 구간에 맞춰 발급한다. PIN 원문을 이동 이벤트나 로그에 남기지 않는다.
- 이동 이벤트는 원 객실, 새 객실, 적용 시각, 사유, 수행 관리자, 예상 버전을 append-only 이력으로 보존한다.

운영 백엔드 구현 계약과 오류 코드는 `DOCS/24_RESERVATION_ARRIVAL_ROOM_MOVE_BACKEND_HANDOFF.md`를 따른다.
