# 8월 객실 마스터·장기투숙 기능 결정안

이 문서는 사용자가 제공한 `객실현황(26.08)`의 `8월`·`장기-결제` 시트를 바탕으로 정리한 객실 기준정보와 다음 기능 결정안이다. 개인정보·PIN·자유문구 속 고객명은 앱 fixture에 가져오지 않는다.

## 이번 반영 확정

- 최신 객실 정본은 `8월` 시트의 121개 객실이다.
- 타입 구성은 스탠다드 22개, 프리미어 51개, 파셜 오션뷰 13개, 패밀리 투룸 35개다.
- 엘리베이터 표기는 A 33개, B 21개, C 56개이며 공란 11개는 `엘리베이터 미기재`로 보존한다.
- 공란 객실은 139, 358, 359, 449, 458, 461, 553, 559, 628, 629, 762호다. 위치를 추정하지 않는다.
- 객실 목록·상세·청소 대상·메이드별 순서 보드에 객실 호수, 타입, 엘리베이터 위치를 함께 표시한다.
- 객실 마스터 상태는 `고객 배정 가능 기준 109실 / 장기투숙 중 11실 / 확인 보류 1실`로 확정한다. 일반 109실은 별도 중립 상태를 만들지 않고 기존 녹색 `고객 배정 가능` 객실과 같은 카드·상세·수정 기능을 사용한다. 9개 시나리오 객실은 이 기준 위에 데모 운영 상태를 덮어쓴다.
- 타입별 청소요금 정본은 시트 값인 `스탠다드 16,000원 / 프리미어 20,000원 / 파셜 오션뷰 20,000원 / 패밀리 투룸 30,000원`으로 확정한다. 더 이상 임시값이나 미확정 값으로 부르지 않는다.
- 762호는 유일한 `확인 보류(hold)` 객실이다. 스탠다드 타입과 16,000원 기본 청소요금만 정본으로 사용하고, 엘리베이터 위치는 미기재로 보존하며 일반 편집·청소 배정 대상에서는 잠근다.
- 시트의 별도 숫자 `타입` 1/1.5/1.5/2는 의미 범례가 없어 청소 난이도·인원 계수로 추정하지 않는다.

## 시트에서 확인된 장기투숙 운영

- 현재 장기투숙으로 명시된 객실은 `139·358·359·449·458·461·553·558·559·628·629호` 11실이다. 이 목록은 `장기-결제` 시트의 활성 행을 근거로 하며 고객명·회사명·결제 메모 같은 개인정보성 값은 앱 fixture에 반입하지 않는다.
- 527호는 종료된 장기투숙 이력으로만 남기고 현재 객실 마스터에서는 `고객 배정 가능` 기준 상태로 취급한다. 종료 이력은 활성 장기투숙 필터와 집계에서 제외한다.
- 시작 예정, 현재 투숙, 퇴실·종료가 자유문구와 행 색으로 섞여 있어 상태 변경 이력이 덮어써질 위험이 있다.
- 월별 결제 칸에는 날짜, 분할 납부, 퇴실 메모가 한 셀에 섞여 있다.
- 장기 객실 날짜 칸에도 청소 담당으로 보이는 이름이 반복되어, 장기투숙 청소가 단발 업무가 아니라 반복 일정일 가능성이 높다. 색·공란에는 범례가 없어 상태로 자동 해석하지 않는다.
- 월 시트가 오른쪽으로 계속 늘어나는 방식이므로 앱에서는 월 전환과 과거 월 스냅샷을 분리한다.

## 권장 기능 확정안

### 1차: 장기투숙 마스터 + 연박 청소 요청

- 장기투숙 상태는 객실 마스터에서 `장기투숙 중`으로 구분하고, 근거가 있는 시작일만 표시한다. 종료된 527호는 활성 상태로 되살리지 않는다.
- 활성 장기투숙 11실은 객실 상세에서 날짜·입실 가능 시간·퇴실 기한을 지정해 `연박 청소 요청`을 만들 수 있다. 생성된 요청은 기존 전날 배정 화면에 포함하고 담당·순서·검수·폭탄방 정책은 일반 청소 흐름을 재사용한다.
- 142호는 장기투숙 객실이 아니라 기존 예약을 이용한 `연박 청소 데모` 오버레이다. 장기투숙 필터·11실 집계에 포함하지 않는다.
- 고객명·회사명·결제 내역·자유문구 원문은 객실 상태와 청소 요청을 표시하기 위해 앱이나 내보내기에 복사하지 않는다.
- 반복 주기·요일·마지막 청소일·다음 청소일·일시 중지 기능은 별도 확정 전까지 자동 생성하지 않는다.
- 객실 변경 시 이전 객실 기록을 삭제하지 않고 이동 이력을 남긴다.

### 2차: 월별 결제 원장

- 월 청구액은 숫자로 저장하고 `예정 / 일부 납부 / 완납 / 연체 / 종료` 상태를 계산한다.
- 한 달에 여러 번 납부할 수 있는 거래 원장으로 분할 납부를 지원한다.
- 퇴실·종료일 이후에는 다음 달 청구 생성을 중단하고, 수정 전후 값과 수정자를 감사 이력에 남긴다.
- 청소 주급과 장기투숙 결제는 서로 다른 원장으로 유지한다.

### 후속: 객실 운영 보조

- `운영 시작 예정 / 운영 중 / 운영 중지`를 자유문구 대신 구조화해 신규 객실 시작일을 관리한다.
- 카드키 보유 현황은 객실 PIN과 분리된 실물 자산 대여·회수 기록으로 설계한다.
- 세스코 같은 정기 작업은 업체별 전용 화면보다 범용 `정기 점검 작업`으로 만들어 객실 묶음, 회차, 완료 증빙을 관리한다.
- 색상은 보조 표현으로만 쓰고 모든 상태에 상태명·아이콘·이유·범례를 제공한다.

## 해결된 결정

- 청소 단가는 시트 값을 운영 정본으로 사용한다: 스탠다드 16,000원, 프리미어 20,000원, 파셜 오션뷰 20,000원, 패밀리 투룸 30,000원.
- 객실 마스터는 `고객 배정 가능 기준 109 / 장기투숙 중 11 / 확인 보류 1`을 사용한다. 762호는 확인 보류로 잠그고, 나머지 일반 객실은 기존 고객 배정 가능 카드와 동일하게 편집할 수 있다.
- 활성 장기투숙은 위 11실로 한정하며, 527호는 종료 이력·현재 고객 배정 가능 기준, 142호는 연박 청소 데모 오버레이로 구분한다.

## 아직 사용자 확인 필요

1. 활성 장기투숙의 반복 청소를 주기·요일 기준으로 자동 생성할지, 현재처럼 건별 연박 청소 요청만 둘지.
2. 월별 결제 원장을 객실 운영 기능에 포함할지, 포함한다면 개인정보와 권한·보존 범위를 어떻게 분리할지.
3. 엘리베이터 미기재 11개 객실의 실제 위치. 확정 전에는 위치를 추정하지 않는다.
