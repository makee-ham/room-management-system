# 와이어프레임 우선 운영 개편 진행 기록

## 사용자 결정

- 일반 청소 사진 1~20장, 구역 구분 없음.
- 폭탄방·객실 특이사항은 별도로 유지.
- 기존 제출 없음. 미제출 작업 전체 전환.
- 최근 7일 청소 기록과 사진 조회.
- 홈 바로가기 목적지 고정, 모바일 뒤로가기, 간결한 문구, 주급 API 정상 연결.
- 의견이 필요한 단계에서 질문을 모아 확인 후 진행.

## 1차 수정 범위

- 홈 검수·오늘 배정 버튼에 실제 하위 탭 경로 연결.
- 운영 화면에도 page/modal history 적용. 탭·주차·상세 복귀 및 역할 재검증. history에는 허용된 화면 키와 ID만 저장하고 모달 HTML·사진·PIN·고객명은 제외.
- 현재 주차 주급 조회, 메이드 관리 주급 탭 진입 시 조회, 오래된 응답 역전 방지. 종료되지 않은 주차의 지급 명령 차단. 금액 누락을 0원으로 표시하지 않음.
- 검수 사진 확대 창·이전/다음 사진·키보드·뒤로가기. 일반 모달을 닫아도 기존 사진 blob URL 유지.
- 폭탄방 `evidencePhotoIds` 조회와 별도 갤러리. 실제 제출 내용이 없는 가짜 타임라인·메모 제거.
- 기능과 무관한 상단 설명 및 감사 구현 설명 축소. 실패·권한·필수 정보 유지.

## 아직 끝나지 않은 API 계약

2026-09-28 확인한 공개 OpenAPI는 v0.5.1이다. 아래 작업은 프런트 성공 상태로 가장하지 않는다.

| 범위 | 현재 계약과 필요한 변경 |
| --- | --- |
| 일반 사진 1~20장 | `GET /v1/attempts/{attemptId}/photo-slots`의 `maxPhotos`는 1 또는 10. 컬렉션 업로드는 기존 `extra-proof` 슬롯에 한정. 구역 없는 필수 일반 컬렉션과 1~20장 제출 검증, 템플릿·미제출 작업 전환이 서버에 필요 |
| 삭제 | `DELETE /v1/attempts/{attemptId}/photo-slots/{slotId}/photos/{photoItemId}`의 브라우저 CORS 허용과 컬렉션·항목 revision 충돌 검증 필요 |
| 과거 사진 | `GET /v1/cleaning-history`는 최근 완료 목록만 제공. 관리자 검수 단건 API는 있지만 메이드가 본인의 과거 제출·사진을 조회하는 전용 상세 계약이 필요 |
| 주급 예상·산출 | `GET /v1/payroll`은 확정·조정·이월 금액 제공. 검수 대기 예상액과 객실별 기본요금·폭탄방 가산 내역은 없음. 기존 와이어프레임 자리를 유지하고 미제공 값을 추정하지 않음 |

백엔드 저장소 `wrongstory/room-management-system-backend`의 `dev`를 읽기 전용으로 확인했다. 아직 해당 저장소의 코드 수정·PR·운영 DB migration·배포는 하지 않았다. 저장소 지침상 기능 PR은 dev로 병합하고, 운영 반영은 별도 release PR 및 로컬 DB 검증을 거쳐야 한다. 로컬 Docker daemon은 현재 실행 중이 아니므로 DB/RLS 검증을 통과했다고 기록하지 않는다.
