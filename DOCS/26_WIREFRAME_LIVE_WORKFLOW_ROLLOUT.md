# 와이어프레임 우선 운영 개편 진행 기록

## 사용자 결정

- 일반 청소 사진 1~20장, 구역 구분 없음.
- 폭탄방·객실 특이사항은 별도로 유지.
- 기존 제출 없음. 미제출 작업 전체 전환.
- 최근 7일 청소 기록과 사진 조회.
- 홈 바로가기 목적지 고정, 모바일 뒤로가기, 간결한 문구, 주급 API 정상 연결.
- 의견이 필요한 단계에서 질문을 모아 확인 후 진행.
- 모바일 갤러리에서 한 번에 최대 20장 선택. 이후에는 남은 수량까지 다중 선택 추가.
- 프런트 컨펌 후 남은 프런트·백엔드 차이를 화면/API 계약/기대 동작/재현 방법을 포함한 백엔드 이슈로 등록. 컨펌 전에는 이슈를 미리 만들지 않음.

## 2026-09-28 추가 승인과 구현

사용자가 백엔드 포함 전체 개편과 운영 배포를 승인했다. 아래 기록은 앞선 1차의 API 미완료/승인 대기 상태를 대체한다. 운영 사전 조회에서 승인 제출 1건과 사진 version 11개가 확인되어 삭제하지 않는다. 시작/업로드/제출 전 작업만 새 규칙으로 전환하고 이전 스냅샷은 비공개 이관 기록으로 보존한다.

- OpenAPI 0.6.0: 131 paths / 141 operations. 일반 `cleaning-proof` 1~20장, 별도 `bomb-proof`/`issue-proof` 각 최대 10장. 기존 시작·제출 작업은 당시 계약 보존.
- 일반 사진 0장 제출 차단, 다중 선택·개별 삭제·확대, 업로드/컬렉션 revision 충돌 처리. 폭탄방·특이사항 사진은 일반 필수 사진으로 세지 않음.
- `POST /v1/attempts/{attemptId}/room-issues`로 담당 메이드의 메모·검증된 증빙 등록. 검수/이력에서는 별도 갤러리로 조회.
- 최근 7일 목록에서 `GET /v1/cleaning-history/{submissionId}`로 관리자 또는 실제 수행 메이드만 사진 상세 조회. 만료/삭제 사진은 원본 조회 불가 표시. 기존 보존·purge 정책 유지.
- 주급 `accrualAmount`, `expectedAmount`, `pendingAmount`, `pendingCount`를 API projection에서 계산. 프런트에서 운영 단가나 누락된 금액을 추정하지 않음. 기존 지급 잠금·정정·이월 원장 변경 없음.
- CORS DELETE, 정적 앱 서비스 워커 버전 갱신, 내부 구현 설명 정리.

로컬 Playwright에서 사진 0/1/20/21장, 별도 증빙, 이력 사진 확대/뒤로가기, 주급 주차/금액/응답 역전, 홈 목적지, 네 가지 화면 너비를 확인했다. 운영 배포 확인과 실제 계정 mutation UAT는 별도이며 아래 과거 기록을 완료 근거로 사용하지 않는다. 최신 검증은 `WIREFRAME/QA.md`의 2차 기록을 따른다.

## 1차 수정 범위

- 홈 검수·오늘 배정 버튼에 실제 하위 탭 경로 연결.
- 운영 화면에도 page/modal history 적용. 탭·주차·상세 복귀 및 역할 재검증. history에는 허용된 화면 키와 ID만 저장하고 모달 HTML·사진·PIN·고객명은 제외.
- 현재 주차 주급 조회, 메이드 관리 주급 탭 진입 시 조회, 오래된 응답 역전 방지. 종료되지 않은 주차의 지급 명령 차단. 금액 누락을 0원으로 표시하지 않음.
- 검수 사진 확대 창·이전/다음 사진·키보드·뒤로가기. 일반 모달을 닫아도 기존 사진 blob URL 유지.
- 폭탄방 `evidencePhotoIds` 조회와 별도 갤러리. 실제 제출 내용이 없는 가짜 타임라인·메모 제거.
- 기능과 무관한 상단 설명 및 감사 구현 설명 축소. 실패·권한·필수 정보 유지.

## 1차 당시 API 계약 과제 (현재 해결)

아래는 같은 날 1차 시점의 과거 기록이다. 당시 공개 OpenAPI는 v0.5.1이었으며 최신 상태는 위 운영 배포 확인을 따른다.

| 범위 | 현재 계약과 필요한 변경 |
| --- | --- |
| 일반 사진 1~20장 | `GET /v1/attempts/{attemptId}/photo-slots`의 `maxPhotos`는 1 또는 10. 컬렉션 업로드는 기존 `extra-proof` 슬롯에 한정. 구역 없는 필수 일반 컬렉션과 1~20장 제출 검증, 템플릿·미제출 작업 전환이 서버에 필요 |
| 삭제 | `DELETE /v1/attempts/{attemptId}/photo-slots/{slotId}/photos/{photoItemId}`의 브라우저 CORS 허용과 컬렉션·항목 revision 충돌 검증 필요 |
| 과거 사진 | `GET /v1/cleaning-history`는 최근 완료 목록만 제공. 관리자 검수 단건 API는 있지만 메이드가 본인의 과거 제출·사진을 조회하는 전용 상세 계약이 필요 |
| 주급 예상·산출 | `GET /v1/payroll`은 확정·조정·이월 금액 제공. 검수 대기 예상액과 객실별 기본요금·폭탄방 가산 내역은 없음. 기존 와이어프레임 자리를 유지하고 미제공 값을 추정하지 않음 |

백엔드 저장소 `wrongstory/room-management-system-backend`의 `dev`를 읽기 전용으로 확인했다. 아직 해당 저장소의 코드 수정·PR·운영 DB migration·배포는 하지 않았다. 저장소 지침상 기능 PR은 dev로 병합하고, 운영 반영은 별도 release PR 및 로컬 DB 검증을 거쳐야 한다. 로컬 Docker daemon은 현재 실행 중이 아니므로 DB/RLS 검증을 통과했다고 기록하지 않는다.

## 1차 당시 계획 (과거 기록)

1. 별도 백엔드 저장소의 직접 수정·릴리스까지 이번 작업에서 진행할지 사용자 확인.
2. 서버 사진 컬렉션·제출·보존·상세 조회·주급 projection 변경과 실제 역할/RLS/경계값 테스트.
3. 새 OpenAPI를 생성하고 와이어프레임/운영 모드의 일반 사진 입력을 함께 교체. 업로드 큐·0/1/20/21장·삭제·실패·다른 화면 이동 검증.
4. 최근 7일 이력에서 사진 확대 조회. 본인/타인, 승인/반려, 만료 경계, 로그/저장소 유출 검증.
5. 전체 화면의 와이어프레임 대조, 360/390/768/1440px 및 실제 모바일 설치 앱 검수, 배포 버전 확인.

이 과거 계획 자체는 완료 근거가 아니다. 최신 배포와 실제 검증 범위는 위 운영 배포 확인 및 `WIREFRAME/QA.md`에 구분해 남긴다.
