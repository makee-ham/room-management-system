## 1. 적용 우선순위

이 문서는 청소 근무 가능일·담당 배정과 폭탄방 신고·검수·2배 적립에 한해 `DOCS/FINAL_UX_AUDIT.md`와 `DOCS/14_CLICKABLE_WIREFRAME_HANDOFF.md`의 `매일 근무 등록`, `공개 일감`, `메이드 선점`, `재공개` 규칙 및 일반 청소요금과 충돌하는 부분을 대체한다. 주급 화면에서는 모든 메이드 카드에 지급 컨트롤을 노출하고 `(maid_id, week_start)`별로 상태를 분리하는 범위만 구체화하며, 지급 상태 전이는 기존 정본의 `OPEN → PAYING → PAID`와 완료 뒤 정정·상계 원칙을 유지한다. 객실 기준정보, `투숙 / 공실` 점유, `투숙 중 / 청소 필요 / 배정 가능 / 배정 불가` 카드 주 상태, 예정 전 `지금 체크아웃`은 `DOCS/17_ROOM_CATALOG_LONG_STAY_DECISIONS.md`가 기존 장기투숙 전용 표현과 기존 카드 색·주 상태 표현, 예정 시각 자동 종료만 있는 흐름을 대체·확장한다. 다른 예약·PIN·검수·주급·감사 정책은 기존 정본을 유지한다.

## 2. 주간 운영 흐름

1. 메이드는 한국시간 기준 일요일 12:00부터 23:59까지(양 끝 시각 포함) 다음 주 월요일–일요일의 근무 가능일을 모두 선택해 제출한다.
2. 마감 전에는 제출 내용을 직접 수정할 수 있다. 마감 뒤에는 기존 제출을 유지하고 관리자에게 변경 요청을 보낸다.
   - `제출 내용 수정`을 열어도 마지막 제출은 새 내용을 다시 제출하기 전까지 유효하다. 수정 중 마감되거나 화면을 나가도 기존 제출과 관리자 배정 자격을 유지한다.
3. 관리자는 일요일 밤 또는 월요일 근무 시작 전에 모든 메이드의 제출·미제출·변경 요청과 요일별 가능 인원을 한 화면에서 확인한다.
   - 일요일은 다음 주 가능일 제출·확인 시점이다. `내일 청소 배정`은 일요일 전용 화면이 아니라 청소대상이 있는 매일 전날 운영하며, 각 대상일에 제출된 가능 여부를 사용한다.
4. 시스템은 배정 대상일에 예정 체크아웃하거나 관리자가 `지금 체크아웃`으로 실제 점유를 종료한 객실과 해당 날짜에 투숙 중 청소를 신청한 객실을 `청소대상 객실`에 자동 포함한다. 같은 예약의 예정·수동 체크아웃은 활성 퇴실 청소 한 건을 공유하며 중복 작업을 만들지 않는다.
   - 이 자동 집계는 객실 카드의 주 상태와 무관하게 청소 대상 원장을 기준으로 실행한다. 얼리 체크인·레이트 체크아웃이 있으면 조정된 실제 예정 시각과 기준 대비 차이를 같은 배정 행에 자동 집계한다. 얼리·레이트 표식만으로 별도 청소 작업을 만들지 않는다.
5. 관리자는 자동 대상 외 현장 요청을 같은 화면에서 직접 등록해 추가할 수 있다. 검수 반려로 생기는 재청소는 직접 등록 대상이 아니라 최초 청소한 메이드에게 자동 귀속한다. 동일 대상일·객실·청소 유형의 중복 등록은 차단한다.
6. 각 근무일 전날 밤, 관리자는 `메이드 주간 근무표`에서 대상일의 근무 가능자를 먼저 확인한다. 근무표 바로 다음에는 `동선 고려 랜덤 배정 초안`을 두고, 그 아래에서 객실별 담당과 메이드별 1–N 순서를 세부 수정한다.
7. 랜덤 초안은 해당 날짜를 근무 가능으로 제출한 활성 메이드와 미배정 청소대상만 사용하며, 이미 통보한 담당·순서와 관리자가 수동으로 지정한 담당은 바꾸지 않는다.
8. 마감 안에 완료 가능한 객실 수를 최대화하는 것은 배정의 선행 제약이다. 그 최대 배정 후보들 사이의 1순위는 메이드별 `총 청소요금`이 가능한 균형에 가깝게 되도록 나누는 것이다. 총 요금의 최대·최소 격차와 전체 편차가 정확히 같은 후보끼리만 2순위로 같은 엘리베이터 구역과 가까운 호수를 비교한다. 그 다음까지 동률이면 랜덤으로 고르며, 반복 실행이 항상 같은 결과를 내야 하는 결정성은 요구하지 않는다.
9. 랜덤 초안 아래에서 관리자는 `전체`와 확정된 네 객실 타입 필터로 청소대상을 좁혀 보며, 각 타입의 대상 수와 객실당 고정 청소 요금을 확인하고 객실별 담당을 직접 바꾼다. 이어지는 `메이드별 청소 순서` 보드에서는 같은 메이드의 객실을 `1번째`부터 끊김 없이 위·아래로 조정한다. 담당을 바꾸면 해당 객실은 새 메이드 순서의 마지막으로 이동하고 양쪽 순서를 1부터 다시 연속화한다. 필터는 표시만 바꾸고 전체 대상의 담당 상태·미배정 현황·순서를 바꾸지 않으며, 별도의 메이드별 작업량·동선 비교판은 사용하지 않는다.
10. 담당 선택 목록에는 해당 날짜를 `근무 가능`으로 제출한 메이드만 표시한다. `근무 불가` 또는 `미제출` 메이드는 예외 배정할 수 없으며, 먼저 가능일 변경 요청을 승인해 일정 기록을 바로잡아야 한다.
11. 모든 청소대상을 다 배정하지 못해도, 담당 메이드와 해당 메이드 안의 연속 청소 순서가 정해진 객실만 먼저 저장·통보할 수 있다. 미배정 객실은 대기 상태로 유지하고 추후 담당을 정한 시점에 추가 통보한다. 배정·순서 변경은 기존 담당 구간과 이전 순서를 삭제하지 않고 변경 이력을 추가한다.
12. 전날 담당을 정하지 못했거나 통보된 메이드가 청소를 시작하지 못한 객실은 같은 청소대상 ID를 다음 날로 이월한다. 이미 청소를 시작한 미완료 건은 기존 수행 회차·담당 메이드·촬영 진행을 유지해 다음 날 이어서 완료한다. 세부 상태 전이는 아래 `전일 미배정·미완료 청소 이월` 규칙을 따른다.
13. 가능일 제출 버전, 관리자 배정·순서 통보일, 실제 청소 수행 완료일을 서로 다른 기록으로 주차별 보존하고 관리자가 조회 주차(월요일–일요일)를 달력에서 고른 뒤 메이드별 과거 기록을 조회한다. 요약은 기록이 있는 고유 메이드를 `N명`, 메이드별 기록 날짜 합계를 `N일`로 분리하고 두 뜻을 섞은 단위는 사용하지 않는다.

### 8–10명 운영의 랜덤 배정 초안

- 전날 배정 화면은 `메이드 주간 근무표 → 동선 고려 랜덤 배정 초안 → 객실별 담당 수정 → 메이드별 1–N 순서 수정 → 저장·통보` 순서로 읽힌다. 여기서 `동선 고려`는 실제 이동시간이나 전역 경로 최적화가 아니라, 총 청소요금 점수가 같은 후보에서 엘리베이터 구역과 호수 거리를 보조 기준으로 사용하는 것을 뜻한다. `사전 조건 / 1순위 / 2순위 / 관리자 최종 수정` 설명은 반복 칩으로 늘어놓지 않고 랜덤 배정 제목 옆 `배정 기준` 툴팁 하나에 묶는다.
- 대상은 해당 근무일을 `가능`으로 제출했고 계정이 활성인 메이드와 아직 담당이 없는 객실만이다. 기존 통보 완료와 관리자 수동 배정은 고정하고 랜덤 초안이 덮지 않는다.
- 마감 안에 완료 가능한 객실 수를 최대화한 후보만 남긴다. 그 안에서 먼저 메이드별 총 청소요금의 최대·최소 격차와 전체 편차를 줄이고, 금액 점수가 정확히 같은 후보에서만 같은 엘리베이터 구역·가까운 호수를 비교한다. 두 기준까지 같으면 랜덤으로 선택한다.
- 결과는 `저장 전 초안`이며 메이드 업무·알림·배정 이력을 즉시 만들지 않는다. 관리자는 객실별 담당을 수정하거나 미배정으로 되돌리고, 기존 1–N 순서 보드에서 순서를 수정한 뒤 저장·통보한다.
- 별도의 작업량·동선 비교판은 놓지 않는다. 다만 기존 메이드별 1–N 순서 카드의 제목 오른쪽에는 그 카드에 현재 배정된 `통보 완료 + 저장 전` 작업의 기본 청소요금 합계를 표시한다. 통보 완료 작업은 당시 고정한 단가 스냅샷, 저장 전 작업은 현재 배정 대상 단가를 사용한다. 미배정 작업과 폭탄방 추가요금은 제외하며, 이 값은 검수 확정액·주급·지급액이 아닌 배정 균형 확인값이다. 랜덤 배정·되돌리기와 담당 선택·해제·변경 때 즉시 다시 계산하고, 순서 이동이나 타입 표시 필터만 바꿀 때는 같은 합계를 유지한다. 재배정 수정 중 배정이 0건이 된 근무 가능 메이드 카드는 `0원`으로 남겨 불균형을 숨기지 않되, 수정 전 초기 화면에 빈 카드를 추가하지 않는다. 엘리베이터·호수의 별도 합계나 비교 정보는 추가하지 않는다.

### 전일 미배정·미완료 청소 이월

- 이월은 새 청소 작업을 복제하는 기능이 아니다. 같은 청소대상 ID를 유지한 채 최초 생성 때의 `원 계획일`, 객실·청소 유형·기본 청소요금·템플릿·연결 예약 스냅샷을 고정하고, 현재 배정에서 사용할 `이월 대상일`만 다음 날로 옮긴다. 같은 건이 다시 미완료되면 같은 ID로 하루씩 이월하며 `이월 N일째`를 누적한다.
- 전날까지 담당을 정하지 못한 대상은 다음 날 배정 화면에 `전일 이월 · 미배정`으로 다시 나타난다. 현재 담당과 순서는 없는 상태이며 다음 날 근무 가능·활성 메이드를 대상으로 랜덤 초안 또는 관리자 직접 배정을 적용한다.
- 담당·순서를 통보했지만 메이드가 청소를 시작하지 않은 대상은 이전 담당·순서·통보 시각을 감사 이력에 보존한 뒤 현재 담당과 순서를 해제한다. 다음 날에는 `전일 이월 · 미완료`와 현재 상태 `미배정`을 함께 표시하고, 전날 담당자를 자동 유지하지 않은 채 다음 날 근무 가능 여부를 다시 확인해 배정한다.
- 메이드가 청소를 이미 시작했으나 현장 완료하지 못한 대상은 수행 회차를 새로 만들거나 담당을 풀지 않는다. 같은 수행 회차·담당 메이드·사진 슬롯·촬영 결과·특이사항을 유지해 다음 날 이어서 진행하며 랜덤 배정과 객실별 담당 변경 대상에서는 제외한다.
- 현장 완료 뒤 업로드 중·실패·대기 상태인 건은 실제 청소가 끝났으므로 다음 날 배정 대상으로 이월하지 않고 기존 업로드 재시도 흐름에서 이어간다. 전체 제출 뒤 검수 대기인 건도 배정 이월에서 제외하고 기존 검수 흐름을 유지한다.
- `원 계획일`은 이월이나 재배정으로 바꾸지 않는다. 실제 근무일·완료일·주급 귀속 주차는 메이드가 현장 완료한 한국시간의 실제 날짜로 계산하며, 원 계획일이나 이월 대상일로 소급하지 않는다. 업로드·전체 제출이 다음 날로 넘어가도 이미 기록한 실제 현장 완료일과 주급 귀속 주차는 바뀌지 않는다.
- 관리자 배정 행과 메이드 업무 카드에는 긴 시스템 설명 대신 `전일 이월 · 미배정` 또는 `전일 이월 · 미완료`, `원 계획 M/D`, 필요할 때 `이월 N일째`만 짧은 배지로 표시한다. 이월 사유·이전 담당·순서·실제 완료일은 상세와 감사 이력에서 확인한다.

- 인명, 예약·청소 상태, 특수 입퇴실 시각과 과거 주급 기록은 현재 와이어프레임의 기능 확인용 데모 fixture이며 실제 운영 기록으로 해석하지 않는다.

객실 호수는 현재 불변 내부키와 연결된 읽기 전용 값이다. 관리자는 객실 상세에서 객실 타입과 `A / B / C / 미기재` 엘리베이터 위치를 수정할 수 있다. 변경한 타입·위치는 목록·상세·새 청소대상·랜덤 배정 초안에 반영하고 이전 값·새 값·관리자·시각을 남긴다. 타입 변경 뒤 새로 생성하는 작업은 새 타입의 단가·템플릿을 사용하지만 이미 생성한 작업의 타입·단가·템플릿 스냅샷은 유지한다.

### 예약 시각 기반 특수 입퇴실 판정

- 객실의 예정 체크인은 `16:00`, 예정 체크아웃은 `11:00`을 기본 기준으로 한다.
- 예정 체크인이 16:00보다 이르면 `얼리 체크인`, 예정 체크아웃이 11:00보다 늦으면 `레이트 체크아웃`으로 자동 판정한다. 정확히 16:00·11:00이면 각각 기본 상태이며 특수 상태를 표시하지 않는다.
- 상태와 차이는 별도 수동 선택값이 아니라 실제 예정 시각에서 계산한다. 예를 들어 체크인 15:00은 `얼리 체크인 · 1시간`, 체크아웃 13:00은 `레이트 체크아웃 · 2시간`이다.
- 객실 카드, 관리자 청소 배정 행, 메이드별 1–N 청소 순서 수정 보드에서 얼리·레이트는 조정된 실제 예정 시각과 함께 청소 진행 상태 서브 배지보다 눈에 잘 띄는 일정 배지로 표시한다. 이 배지 자체는 객실 카드 주 상태나 색을 바꾸지 않는다.
- 한 고객의 예약 등록·수정 화면은 `체크인 → 체크아웃` 순서로 입력한다. 두 시각은 같은 예약 ID에 속하며 체크아웃은 체크인보다 뒤인 최소 1박 구간이어야 한다.
- 이전 예약의 체크아웃과 다음 예약의 체크인은 한 고객의 예약 입력값으로 합치지 않는다. 두 예약 사이의 청소 준비 일정에서만 `이전 예약 체크아웃 → 준비 마감 → 다음 예약 체크인`으로 구분해 표시한다.
- 실제 체크인·체크아웃 시각 구간이 기존 예약과 겹치면 저장하지 않는다. 예약 수정 중 원본 일정이 바뀌거나 취소된 경우에도 오래된 화면으로 덮어쓰거나 신규 예약으로 바꾸지 않고 최신 예약을 다시 열도록 안내한다.
- 예약 입력은 기존 정책과 같이 1시간 단위를 유지하며, 예약 시각이 바뀌면 객실 카드·상세·특수 상태 필터·관리자 청소 배정 일정에 같은 결과를 즉시 반영한다. 이미 메이드에게 통보한 일정은 관리자 재통보 전까지 당시 스냅샷을 유지하고, 같은 대상일의 시각 변경은 저장 전 변경으로 표시한 뒤 재통보 시 새 시각으로 교체한다. 대상일이 바뀌면 기존 담당에게 취소를 통보하고 원 배정 이력을 보존한다.
- 다음 예약의 체크인 시각을 바꾸거나 그 예약을 취소하면 직전 예약의 퇴실 청소 준비 마감도 다시 계산한다. 이미 통보한 직전 퇴실 청소는 기존 스냅샷을 유지하면서 `재통보 필요`로 전환한다.
- 과거 수동 얼리·레이트 표식이 남아 있더라도 판정 근거로 쓰지 않는다. 예정 시각이 없으면 상태를 추정하지 않고 `일정 없음`으로 표시한다.

### 점유 상태·예정 전 체크아웃 연동

- 정상 점유 상태는 체류 기간과 관계없이 `투숙 / 공실` 두 가지다. 장기투숙 전용 상태·필터·집계·상세 패널은 사용하지 않는다.
- `배정 가능`은 마스터 점유 상태가 아니라 공실이면서 청소 승인·운영 정상·촛불 0·차단 이슈 없음·기준정보 확인 완료를 모두 만족할 때만 계산하는 카드 주 상태다.
- 관리자는 투숙 객실 상세의 `지금 체크아웃`으로 예정 체크아웃 전에 실제 점유를 종료할 수 있다. 예정 체크아웃이 없는 초기 투숙도 같은 행동을 제공한다. 예정 체크아웃은 원 일정으로 보존하고 실제 체크아웃 시각·관리자·기록 시각을 별도 이벤트로 남긴다.
- 수동 체크아웃 직후에는 점유 `공실`, 카드 주 상태 `청소 필요`로 표시하고 기존 체크아웃 후 출입·청소 흐름을 연다. 청소 승인 전에는 카드 주 상태를 `배정 가능`으로 만들지 않는다.
- 예약에 연결된 퇴실 청소가 있으면 같은 작업을 실제 체크아웃 시각 기준으로 갱신·활성화하고, 없을 때만 한 건을 생성한다. 재시도·화면 재진입·이후 예정 체크아웃 도달은 추가 작업을 만들지 않는다.
- 체크인 전에는 `예약 취소`, 투숙 시작 뒤에는 `지금 체크아웃`을 사용한다. 이미 공실이거나 점유 확인이 보류 중인 객실에는 지금 체크아웃을 제공하지 않는다.

### 폭탄방 신고·검수·2배 적립

- 본인에게 배정된 객실이 통상 범위를 크게 넘게 지저분하면 메이드는 청소 시작 전부터 청소 중·현장 완료 뒤 업로드 단계까지, 청소 전체를 제출하기 전에 `폭탄방`으로 신고할 수 있다.
- 신고에는 이미지가 최소 1장 필요하며 여러 장을 한 번에 선택할 수 있다. 개인정보를 제외한 메모는 선택 사항이고, 신고 시각·신고 단계·신고자·해당 작업의 기본 청소요금 스냅샷을 함께 기록한다.
- 청소 전체 제출과 함께 신고 이미지와 메모를 현재 제출 버전에 잠근다. 제출 뒤 메이드는 신고 증빙이나 판정 상태를 임의로 바꾸지 못한다.
- 관리자는 전체 청소 검수에서 이미지 증빙을 확인하고 `폭탄방 인정` 또는 `폭탄방 미인정`을 별도로 결정한다. 폭탄방 결정이 대기 중이면 전체 청소 승인·반려를 완료할 수 없다.
- 폭탄방 인정 뒤 전체 청소가 승인되면 **주간 전체 금액이 아니라 해당 객실 한 건의 기본 청소요금만 정확히 2배**로 확정한다. 원장은 `기본 청소요금 + 기본 청소요금과 같은 금액의 폭탄방 추가요금 = 해당 객실 총액 2배`로 표시한다.
- 전체 청소가 반려되면 재청소는 최초 청소한 메이드 본인에게 자동 귀속하고 다른 메이드에게 이관·재배정하지 않는다. 재청소 수행 회차는 무급 `0원`이며 별도 청소 수익 원장을 생성하지 않는다.
- 재청소 수행 회차에는 폭탄방을 새로 신고·인정하지 않고 폭탄방 추가요금이나 폭탄방 수익 원장을 만들지 않는다. 최초 반려 제출의 폭탄방 신고·결정·증빙은 감사 이력으로만 보존하며 재청소 보상으로 승계하지 않는다.
- 폭탄방 미인정 뒤 전체 청소가 승인되면 해당 객실 기본 청소요금만 확정한다. 전체 청소가 반려되면 폭탄방 인정 여부와 관계없이 그 제출에서는 청소요금을 적립하지 않는다.
- 승인 재시도나 화면 재진입으로 같은 폭탄방 추가요금이 다시 생기지 않도록 제출·신고·수익을 한 번만 연결한다. 이미 생성된 수익 원장이 있으면 기존 원장을 유지한다.
- 전체 청소가 반려되어도 폭탄방 신고 원문, 이미지 증빙, 관리자 결정·사유와 제출 버전은 삭제하지 않고 검수·재청소 이력에 보존한다.
- 관리자와 해당 메이드는 청소 상세·검수 결과·완료 내역·주급 내역에서 `검수 대기 / 폭탄방 승인 · ×2 / 폭탄방 미인정 / 청소 전체 반려 · 적립 없음` 상태와 기본·추가·총액을 같은 기준으로 확인한다. 메이드는 본인 기록만 볼 수 있다.

## 3. 권한

### 메이드

- 본인의 다음 주 근무 가능일만 제출·수정·변경 요청할 수 있다.
- 관리자에게 통보받은 본인 업무만 볼 수 있다.
- 객실을 선택하거나 본인·다른 메이드의 담당을 확정·변경할 수 없다.
- 담당 취소가 필요하면 사유를 포함해 관리자에게 요청하며, 결정 전까지 기존 담당을 유지한다.
- 본인에게 배정된 객실은 전체 제출 전까지 이미지 1장 이상을 첨부해 폭탄방으로 신고할 수 있지만, 폭탄방 인정·미인정이나 2배 적립을 직접 확정할 수 없다.
- 본인 청소 상세·완료 내역·주급 내역에서 폭탄방 검수 상태와 해당 객실의 기본·추가·총액을 볼 수 있다.

### 관리자

- 전체 메이드의 주간 가능일 제출 현황을 볼 수 있다.
- 전날 배정 화면의 주간 요약은 `메이드 주간 근무표`로 부른다. 각 날짜 셀은 `✓ / × / —` 도형만 표시하고, 표 아래 범례와 메이드명·요일·가능 여부를 포함한 접근성 이름으로 의미를 보완한다.
- 대상일의 예정·수동 체크아웃과 투숙 중 청소 신청에서 자동 구성된 청소대상과 관리자가 직접 등록한 대상을 한 목록에서 볼 수 있다.
- 객실 상세에서 읽기 전용 호수와 현재 타입·엘리베이터 위치를 확인하고 타입·엘리베이터를 수정할 수 있다. 미기재 위치를 추정값으로 자동 저장하지 않는다.
- 투숙 객실은 예정 시각 전에도 `지금 체크아웃`할 수 있고, 예정·실제 체크아웃과 연결된 퇴실 청소 한 건을 구분해 볼 수 있다.
- 전체와 네 객실 타입별로 청소대상을 좁혀 보고 각 타입의 대상 수·객실당 고정 청소 요금을 확인할 수 있다. 타입 필터에 숨은 객실도 전체 대상·미배정 현황과 부분 통보 판단에 유지한다.
- 자동 대상 외 청소대상을 직접 등록할 수 있으며 자동·직접 등록 근거를 바꾸거나 숨기지 않는다.
- 다음 날 청소 대상 객실의 담당을 생성·변경·보류할 수 있다.
- `메이드 주간 근무표` 바로 다음의 동선 고려 랜덤 배정 초안을 만들고, 그 아래에서 객실별 담당을 직접 수정하며, 기존 메이드별 청소 순서 보드에서 1–N 순서를 지정·변경할 수 있다. 각 순서 카드 제목 오른쪽에서 통보 완료 작업의 단가 스냅샷과 저장 전 작업의 현재 배정 대상 단가를 더한 총 청소요금을 확인한다. 배정 기준 상세는 제목 옆 접근 가능한 툴팁으로 확인하며, 별도 기준 칩 줄·작업량·동선 비교판은 제공하지 않고 미배정 객실에는 순서를 부여하지 않는다.
- 담당과 연속 순서가 유효한 객실만 먼저 저장·통보하고, 아직 배정하지 못한 객실은 삭제하거나 임의 배정하지 않고 대기 상태로 남긴다.
- 해당 근무일을 `가능`으로 제출한 메이드만 배정 후보로 본다.
- 근무 불가·미제출 메이드를 담당 선택 목록이나 직접 배정 목록에 노출하지 않는다.
- 과거 주차와 메이드를 선택해 가능일 제출·배정 통보·실근무 완료일을 구분해 볼 수 있다.
- 주급 정산에서 주차와 메이드를 선택하고 메이드별 주급 카드의 `청소 내역 · 산출 보기`로 들어가 해당 주의 객실별 청소 산출 원장을 조회할 수 있다. 원장은 객실·객실 타입·청소 종류·기본 청소요금·폭탄방 추가요금·해당 객실 총액·검수 및 정산 상태를 함께 보여준다.
- 선택한 주차의 모든 메이드 카드에 같은 위치의 지급 컨트롤을 제공한다. 지급 상태는 `(maid_id, week_start)`로 분리하고, 한 메이드의 `OPEN → PAYING → PAID` 또는 `PAYING → CHECK` 전이가 다른 메이드나 다른 주차를 바꾸지 않는다. `PAYING` 이후 카드와 확인창에는 담당 관리자·주차·잠근 금액·잠근 수익·시작 시각을 표시한다. `PAYING`·`CHECK`를 `OPEN`으로 돌릴 때는 외부 송금이 없었음을 확인한 필수 사유와 당시 잠근 금액·수익 ID 스냅샷을 감사 이력에 남기고, `PAID`는 직접 취소하지 않고 정정·상계로 처리한다.
- 지급 진행 뒤 객실 원장이 바뀌어도 `PAYING`·`CHECK`·`PAID` 카드와 메이드 지급 내역은 잠근 지급액을 유지한다. 현재 원장 금액은 별도로 표시하고 차이는 지급 기록 직접 수정이 아니라 정정·상계 대상으로 남긴다.
- 확정 지급액이 0원인 메이드와 아직 마감되지 않은 현재 주차도 컨트롤 자리를 숨기지 않고 `지급 대상 없음` 또는 `주차 마감 전` 사유와 함께 잠근다. 앱은 실제 송금을 실행하지 않고 외부 전액 송금 완료 여부만 기록한다.
- 검수 대기 금액은 승인 시 예상액으로 확정액과 분리하고, 청소 전체 반려와 처음 청소한 본인의 재청소는 `0원 · 주급 합계 제외`로 남겨 확정 주급을 늘리지 않는다.
- 담당 취소 승인과 일반 미시작 업무 변경은 공개 목록으로 보내지 않고 관리자가 직접 결정한다. 검수 반려 재청소는 예외 없이 최초 청소한 메이드에게 자동 귀속하며 타 메이드에게 이관·재배정할 수 없다.
- 폭탄방 신고의 이미지 증빙과 메모를 전체 청소 검수에서 확인하고 인정 또는 미인정 사유를 기록한다.
- 검수·청소 완료·메이드별 주급·과거 지급 이력에서 폭탄방 상태와 해당 객실의 기본 청소요금·동일 금액 추가요금·총액을 관리한다.

## 4. 상태와 감사 이력

- 가능일 제출: `미제출 / 작성 중 / 제출 완료 / 변경 요청`
- 객실 배정·순서: `미배정 / 저장 전 / 통보 완료 / 변경 통보 완료`
- 청소대상 타입 필터: `전체 / 스탠다드 더블 로프트 / 프리미엄 더블 로프트 / 파셜 오션뷰 프리미엄 더블 로프트 / 파셜 오션뷰 패밀리 투룸 로프트`
- 청소대상 등록 근거: `자동 · 예정 체크아웃 / 자동 · 수동 체크아웃 / 자동 · 투숙 중 청소 신청 / 직접 등록`
- 주간 근무 기록: `가능 제출(계획) / 담당 통보(예정) / 실근무 완료(수행 실적)`
- 주간 근무 기록 요약 단위: `해당 기록이 한 번 이상 있는 메이드 N명 / 메이드별 기록 날짜 합계 N일`
- 관리자 주급 산출 원장: `주차·메이드 / 객실 / 객실 타입 / 청소 종류 / 기본 청소요금 / 폭탄방 추가요금 / 해당 객실 총액 / 상태`
- 주급 반영 상태: `확정 합계 포함 / 검수 전 예상만 / 주급 합계 제외 · 0원`
- 지급 기록: `주차 마감 전 / 지급 대상 없음 / 지급 대기(OPEN) / 지급 진행(PAYING) / 정산 확인 필요(CHECK) / 지급 완료(PAID)`, 식별키 `(maid_id, week_start)`
- 폭탄방 신고: `미신고 / 검수 대기 / 폭탄방 승인 · ×2 / 폭탄방 미인정`
- 폭탄방 수익: `기본 청소요금 스냅샷 / 폭탄방 추가요금 / 해당 객실 확정 총액 / 적립 없음`
- 재청소: `최초 청소한 본인 자동 귀속 / 무급 0원 / 타 메이드 이관 없음 / 폭탄방 추가요금·수익 원장 없음`
- 저장 조건: 저장 전 담당 변경이 한 건 이상 있고, 담당이 정해진 객실은 해당 날짜 근무 가능 메이드에게 배정되며 메이드별 청소 순서가 1부터 끊김 없이 지정되어야 한다. 미배정 객실은 저장을 막지 않고 대기 상태로 남는다.
- 랜덤 배정: `초안 전 / 랜덤 초안 / 관리자 수동 수정 / 부분 저장·통보 / 미배정 대기`
- 전일 이월: `전일 이월 · 미배정 / 전일 이월 · 미완료 / 원 계획일 / 이월 대상일 / 이월 N일째`
- 감사 이력: 대상일, 객실, 청소 유형, 자동·직접 등록 근거, 이전 담당·순서, 새 담당·순서, 관리자, 시각, 변경·취소 사유와 폭탄방 신고·증빙 수·제출 버전·관리자 결정·사유·수익 원장 연결을 보존한다. 이월 건은 같은 청소대상 ID, 불변 원 계획일, 이월 전·후 대상일, 이월 횟수·사유, 이전 담당·순서와 수행 회차 유지 여부를 함께 보존한다. 객실 타입·엘리베이터 변경 전후와 예정·실제 체크아웃 시각·수동 체크아웃 관리자도 보존한다. 재청소는 최초 청소 담당·자동 귀속·무급 0원·타 메이드 이관 없음 상태를 별도 수행 회차로 남긴다.
- 가능일 제출은 수정 시 이전 버전을 삭제하지 않고 새 버전을 추가한다. 주차 마감 스냅샷은 당시 표시 이름과 함께 보존한다.
- 실제 근무일은 정상 청소 수행 회차의 현장 완료일을 기준으로 하며, 가능일만 제출했거나 배정만 받은 날짜를 실제 근무로 세지 않는다.
- 현재 주 제출·재배정은 과거 주차 스냅샷과 완료 수행 기록을 덮어쓰지 않는다.
- 메이드 알림에는 본인 업무와 변경 내용만 포함하며 다른 메이드의 일정·배정은 노출하지 않는다.

## 5. 프로토타입 표현 범위

- `WIREFRAME/index.html`은 예정 체크아웃·수동 체크아웃·투숙 중 청소 신청 fixture에서 활성 청소 한 건을 계산하고, 브라우저 메모리 상태와 과거 주차 fixture로 객실 기준정보 수정·타입별 보기·현장 요청 직접 등록·배정·메이드별 순서 보드·통보·근무 기록 조회를 시뮬레이션한다. 검수 반려 재청소는 최초 청소한 본인에게 자동 귀속되는 무급 0원 회차로 표현한다.
- 전날 미배정, 통보 뒤 미착수, 시작 뒤 미완료, 현장 완료 뒤 업로드 대기, 제출 뒤 검수 대기를 구분하는 이월 fixture를 제공한다. 이월되는 물리 청소는 같은 청소대상 ID와 원 계획일을 유지하고, 실제 현장 완료일을 근무 기록과 주급 주차에 사용한다.
- 폭탄방 이미지는 현재 탭 메모리의 미리보기와 데모 fixture로만 다루며 신고·검수 결정·해당 객실의 기본+동일 금액 추가요금·양쪽 내역 표시를 시뮬레이션한다.
- 관리자 주급 카드는 객실별 산출 원장에서 확정·검수 대기·합계 제외 금액을 다시 계산하고, 주차·메이드별 상세에서 각 청소 행과 카드 합계가 일치하는지 보여준다.
- 지급 컨트롤은 선택 주차의 모든 메이드 카드에 표시하고 주차·메이드별 `OPEN → PAYING → CHECK 또는 PAID` 메모리 상태를 독립적으로 시뮬레이션한다. `PAYING`에서 금액·수익 ID를 잠그고, 외부 전액 송금 뒤 `PAID`를 기록하거나 결과가 불명확하면 `CHECK`를 유지한다. `PAYING`·`CHECK`에서 미송금 확인과 필수 사유가 있을 때만 `OPEN`으로 복귀하며 실제 송금 기능으로 표현하지 않는다.
- 실제 서버 저장, 이미지 전송·영속 보관, 다중 관리자 동시성, 자동 지급·송금, 푸시·SMS 발송은 구현한 것으로 표현하지 않는다.
- 객실 타입과 타입별 기본 청소요금 16,000/20,000/20,000/30,000원은 8월 시트 운영 정본이다.
- 인명·예약·청소 상태·특수 시각·과거 주급 기록은 실제 운영 데이터가 아닌 데모 fixture다.

## 6. 수용 기준

- 메이드 화면에 공개 일감 목록이나 객실 선택 행동이 없다.
- 메이드는 한국시간 기준 일요일 12:00–23:59(양 끝 시각 포함)에 다음 주 7일 가능 여부를 제출하고 마감 전 수정 또는 마감 뒤 변경 요청을 할 수 있다.
- 관리자는 전체 제출 매트릭스와 다음 날 객실별 담당 선택을 한 화면에서 처리한다.
- 관리자 `메이드 주간 근무표`의 셀에는 `가능 / 불가 / 미제출` 한글을 반복하지 않고 `✓ / × / —`만 표시하며, 가로 넘침 없이 전체 7일을 보여준다. 스크린리더에는 메이드명·요일·상태를 함께 전달한다.
- 배정 대상일에 예정 체크아웃하거나 수동 체크아웃한 객실과 해당 날짜의 투숙 중 청소 신청 객실은 별도 선택 없이 청소대상 목록에 자동 포함된다. 동일 예약의 퇴실 청소는 정확히 한 건이다.
- 자동 포함 여부는 객실 카드 주 상태와 무관하게 청소 대상 원장으로 계산되고, 얼리·레이트가 있으면 조정된 실제 예정 시각·기준 대비 차이가 같은 배정 행에 자동 표시된다. 얼리·레이트 표식만으로 청소 작업이 생성되지 않는다.
- 관리자는 자동 대상 외 객실을 같은 화면에서 직접 등록해 즉시 배정 목록에 추가할 수 있고, 같은 대상일·객실·청소 유형의 중복 등록은 차단된다.
- 각 청소대상 행은 `자동 · 예정 체크아웃`, `자동 · 수동 체크아웃`, `자동 · 투숙 중 청소 신청`, `직접 등록` 중 하나의 등록 근거를 표시한다.
- 관리자는 모든 객실 상세에서 읽기 전용 호수와 수정 가능한 객실 타입·엘리베이터 위치를 본다. 저장한 변경은 목록·상세·청소대상·랜덤 배정 초안에 반영되고 기존 작업 스냅샷은 바뀌지 않는다.
- 객실 목록·상세의 정상 점유 구분은 `투숙 / 공실`이며 장기투숙 전용 상태·필터·패널은 없다. 카드 주 상태는 `투숙 중(회색) / 청소 필요(주황) / 배정 가능(초록) / 배정 불가(빨강)` 중 하나만 보이고 기존 상세 사유와 청소 진행 단계는 서브 배지로 분리된다.
- 투숙 객실에서 예정 체크아웃 전 `지금 체크아웃`하면 예정 시각을 보존한 채 실제 체크아웃 이벤트가 한 번 기록되고 점유 `공실`, 카드 주 상태 `청소 필요`, 퇴실 청소 한 건으로 전환된다. 이후 예정 시각이 되어도 점유 종료와 작업이 중복되지 않는다.
- 객실별 담당 선택에는 객실 호수·객실 타입·청소 요금이 항상 보인다. 얼리 체크인·레이트 체크아웃이 있으면 객실별 담당 선택과 메이드별 1–N 순서 수정 양쪽에 조정 체크인·체크아웃 시각과 기준 대비 차이를 청소 진행 서브 배지보다 눈에 잘 띄는 일정 배지로 함께 보여준다.
- 전체와 네 객실 타입 필터에는 대상 수와 객실당 고정 청소 요금이 보이고, 필터를 바꿔도 메이드별 전체 순서·미배정 수·부분 통보 대상은 변하지 않는다.
- 체크인 15:00은 `얼리 체크인 · 1시간`, 체크인 16:00은 기본 체크인으로 자동 판정되며 수동 얼리 선택값은 없다.
- 체크아웃 13:00은 `레이트 체크아웃 · 2시간`, 체크아웃 11:00은 기본 체크아웃으로 자동 판정되며 수동 레이트 선택값은 없다.
- 예약 등록·수정 화면의 표시·DOM·키보드 순서는 `체크인 → 체크아웃`이며 두 값은 같은 예약 ID로 저장된다. 같거나 역순인 시각, 같은 날짜 안의 0박 구간, 실제 시각이 겹치는 예약은 저장되지 않는다.
- 이전 예약 체크아웃과 다음 예약 체크인을 한 예약 입력으로 조합하지 않는다. 다음 예약 체크인 변경·취소 시 직전 퇴실 청소 일정은 중복 작업 없이 재계산되고, 기존 통보가 있으면 재통보 대상으로 바뀐다.
- 예약 시각 변경 결과가 객실 카드·상세·필터와 청소 배정 일정에서 동일해야 한다.
- 담당 목록에는 해당 날짜 `가능` 제출자만 보이며 `불가`·`미제출` 메이드는 선택지에 없다.
- 전날 배정 화면은 `메이드 주간 근무표 → 동선 고려 랜덤 배정 초안 → 객실별 담당 수정 → 메이드별 1–N 순서 수정 → 저장·통보` 순서이며, 네 반응형 너비에서 이 순서가 바뀌지 않는다.
- 랜덤 배정 카드에는 기준 칩을 상시 노출하지 않는다. `랜덤 배정 기준 설명` 버튼의 hover·focus에서 사전 조건·요금 균형·엘리베이터와 호수·관리자 최종 수정·실제 이동시간 비최적화 설명을 한 툴팁으로 확인하고, 버튼과 툴팁은 접근성 이름·연결 설명을 가진다.
- 8–10명 규모에서 랜덤 초안 후보는 근무 가능·활성 메이드만 포함하고, 기존 통보·관리자 수동 배정을 덮지 않은 채 미배정 객실만 채우는지 검증한다.
- 마감 안에 완료 가능한 객실 수를 먼저 최대화하고, 그 최대 배정 후보 안에서 총 청소요금 격차·전체 편차를 절대 1순위로 비교하며, 금액 점수가 같은 후보에서만 엘리베이터 구역·가까운 호수, 그 다음 랜덤 선택이 적용되는지 검증한다. 반복 실행 결과가 항상 같아야 하는 결정성은 검증 기준이 아니다.
- 초안 직후에는 메이드 업무·알림·배정 이력이 증가하지 않는다. 관리자가 객실별 담당과 기존 1–N 순서를 수정해 일부만 저장하면 선택된 변경만 통보되고 나머지는 미배정 대기를 유지한다.
- 별도 작업량·동선 비교판이 노출되지 않고, 객실별 담당 수정과 메이드별 1–N 순서 조정이 유지되며 각 순서 카드 제목 오른쪽에 통보 완료 단가 스냅샷과 저장 전 현재 대상 단가의 합계가 표시되는지 검증한다. 재배정 수정 중 배정이 0건이 된 근무 가능 메이드 카드도 `총 청소요금 · 0건 / 0원`으로 남는지 확인한다.
- 청소 순서 이동 컨트롤은 객실별 담당 행이 아니라 메이드별 청소 순서 보드에만 있다. 관리자는 같은 메이드에게 배정된 객실의 순서를 위·아래로 변경할 수 있고 첫 객실의 위 이동과 마지막 객실의 아래 이동은 잠긴다.
- 담당 변경 시 해당 객실은 새 메이드 순서의 마지막으로 이동하며 양쪽 메이드 순서가 1부터 끊김 없이 다시 계산된다.
- 랜덤 배정·되돌리기와 담당 선택·해제·변경 때마다 객실 행 상태, 메이드별 결과 보드·미배정 수와 양쪽 메이드 카드의 총 청소요금이 즉시 갱신된다. 순서만 이동하거나 타입 필터를 바꾸면 전체 배정·미배정 수, 메이드별 1–N 순서의 구성과 카드 합계는 유지한다.
- 미배정 객실이 있어도 담당이 정해진 객실이 한 건 이상이고, 그 담당이 해당 날짜 근무 가능자이며 메이드별 순서가 1부터 연속되면 배정된 객실만 저장·통보할 수 있다. 담당이 정해진 변경 건이 없거나 담당 가능일·순서가 유효하지 않을 때만 저장·통보가 잠긴다.
- 부분 저장 뒤 해당 메이드의 내 업무·알림은 이번에 확정된 객실을 지정 순서대로 표시하고, 미배정 객실은 관리자 대기 영역에 그대로 남는다. 관리자 이력에는 이번 통보 수·누적 통보 수·남은 미배정 수와 이전·새 담당·순서가 함께 남는다.
- 전날 미배정 청소대상은 새 작업을 만들지 않고 같은 청소대상 ID·원 계획일을 유지한 채 다음 날 배정 목록에 `전일 이월 · 미배정`으로 나타나며, 반복 이월 때 횟수만 증가한다.
- 전날 통보됐지만 시작하지 않은 대상은 이전 담당·순서를 이력에 남기고 현재 담당·순서를 해제한다. 다음 날 `미배정` 상태에서 그날 근무 가능 메이드만 다시 선택할 수 있고, 전날 담당이 불가이면 후보에 노출되지 않는다.
- 이미 시작한 미완료 대상은 같은 수행 회차·담당 메이드·사진 진행을 유지하고 다음 날 이어서 열 수 있으며, 랜덤 초안과 담당 변경 목록에는 나타나지 않는다.
- 현장 완료 뒤 업로드 대기와 전체 제출 뒤 검수 대기는 다음 날 청소 배정 목록으로 이월되지 않고 각각 업로드·검수 흐름에 남는다.
- 이월 건의 실제 근무일·완료일·주급 귀속 주차는 원 계획일이 아니라 실제 현장 완료한 한국시간 날짜에서 계산된다. 전체 제출이 나중에 이루어져도 이미 기록된 실제 완료일을 바꾸지 않는다.
- 관리자 배정 행과 메이드 업무 카드는 이월 상태를 긴 설명으로 반복하지 않고 `전일 이월 · 미배정/미완료`, `원 계획 M/D`, `이월 N일째`의 짧은 배지로 보여주며 자세한 이전 담당·순서는 상세 이력에서 확인한다.
- 관리자는 월요일–일요일 단위 달력에서 조회 주차를 고르고 메이드를 필터링해 가능 제출일·배정 통보일·실근무 완료일을 과거에도 구분해 조회할 수 있다. 인원은 `N명`, 날짜 합계는 `N일`로 각각 표시한다.
- 메이드 역할로 관리자 배정 화면·상세 URL에 직접 진입할 수 없다.
- 메이드는 본인 담당 객실에서 청소 시작 전부터 업로드 단계까지, 전체 제출 전에 이미지 1장 이상을 첨부해야 폭탄방 신고를 저장할 수 있다. 여러 이미지 선택과 개별 제거가 가능하다.
- 폭탄방 신고를 포함해 전체 제출하면 증빙이 제출 버전에 잠기고, 관리자는 이미지 증빙을 확인해 인정 또는 미인정을 먼저 결정해야 전체 청소 승인·반려를 완료할 수 있다.
- 폭탄방 인정과 전체 청소 승인이 모두 완료되면 해당 객실만 `기본 청소요금 + 같은 금액의 폭탄방 추가요금 = 정확히 2배`로 한 번 적립된다. 주간 전체 금액이나 다른 객실 요금에는 배수를 적용하지 않는다.
- 폭탄방 미인정 뒤 전체 청소가 승인되면 기본 청소요금만 적립되고, 전체 청소 반려 시에는 폭탄방 결정과 무관하게 적립이 없다.
- 같은 제출을 다시 승인하거나 화면을 재진입해도 폭탄방 추가요금과 청소 수익이 중복 생성되지 않는다.
- 관리자 청소 검수·완료·주급 원장과 메이드 청소 상세·완료·주급 내역에 폭탄방 상태, 기본요금, 추가요금, 해당 객실 총액이 일치하게 표시된다.
- 관리자 주급 카드에서 선택한 주차·메이드의 산출 보기를 열면 모든 청소 행에 객실·객실 타입·청소 종류·기본 청소요금·폭탄방 추가요금·총액·상태가 보이고, 확정 포함 행의 합계가 카드의 확정 주급과 일치한다.
- 선택한 주차의 모든 메이드 카드에는 지급 컨트롤이 동일하게 보인다. 한 메이드의 지급 진행 시작·정산 확인 필요·필수 사유가 있는 미송금 대기 복귀·외부 송금 완료 기록 후에도 다른 메이드와 다른 주차의 상태는 그대로이며, 메이드는 본인 지급 결과만 읽을 수 있다. 지급 완료(PAID)는 직접 취소하지 않고 이후 차이를 정정·상계한다.
- 지급 진행 뒤 원장 금액이 달라져도 잠근 지급액과 잠근 수익 ID는 바뀌지 않고 카드·확인창·메이드 내역에 유지되며, 현재 원장과의 차이는 명시적으로 구분된다.
- 현재 주차와 확정 지급액 0원 카드는 컨트롤을 숨기지 않고 각각 `주차 마감 전`, `지급 대상 없음`으로 잠기며, 오프라인·오래된 데이터에서도 지급 상태를 바꿀 수 없다.
- 검수 대기 행은 승인 시 예상액과 상태를 별도로 보여주되 확정 주급·지급액에는 포함하지 않는다. 전체 반려와 처음 청소한 본인의 재청소 행은 실제 반영 0원이며 합계에서 제외한다.
- 전체 청소가 반려돼도 폭탄방 신고 이미지·메모·신고 단계·관리자 결정·사유·제출 버전은 검수와 재청소 이력에 남는다.
- 전체 청소 반려로 생긴 재청소는 최초 청소한 메이드에게 자동 귀속되고 타 메이드 담당 선택·이관·재배정 컨트롤을 제공하지 않는다.
- 재청소 수행 회차의 청소요금은 항상 무급 0원이며, 폭탄방 신고·추가요금·폭탄방 수익 원장을 새로 만들지 않는다.
