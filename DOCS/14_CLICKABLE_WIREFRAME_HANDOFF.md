## 2. 고정 제품 기준

- 핵심 축은 관리자용 `객실 상태 관리`와 `메이드 관리`다.
- 객실 타입은 다음 네 개만 사용한다.
  1. 스탠다드 더블 로프트
  2. 프리미엄 더블 로프트
  3. 파셜 오션뷰 프리미엄 더블 로프트
  4. 파셜 오션뷰 패밀리 투룸 로프트
- 관리자가 예약을 수동 입력한다. 기본 체크인은 16:00, 체크아웃은 11:00이며 얼리 체크인·레이트 체크아웃은 1시간 단위다.
- 예약 저장은 해당 체크아웃 대상일의 퇴실 청소대상을 만들고, 관리자가 `오늘 배정 / 내일 배정`에서 근무 가능 메이드의 담당과 1–N 순서를 정해 저장·통보한다.
- 메이드는 객실을 선택하거나 선점하지 않고 본인에게 통보된 업무만 수행한다. 동시에 `청소 중`은 한 건만 가능하다.
- 메이드의 담당 취소 요청은 관리자가 유지·담당 변경·보류 중에서 결정하며 공개 목록으로 보내지 않는다.
- 담당 객실의 출입 가능 시각이 된 뒤에만 객실 4자리 PIN을 볼 수 있다.
- 별도 체크리스트 없이 타입별 필수 구역 사진과 특이사항·촛불을 포함한 청소 제출 전체를 관리자가 한 번에 승인 또는 반려한다.
- 메이드는 청소 완료 시 새로 둔 촛불 개수를 기록하고 관리자는 전체 수량을 증감한다. 촛불이 1개 이상이면 고객 입실이 차단된다.
- 재청소는 최초 청소한 메이드 본인에게 자동 귀속하고 타 메이드에게 이관하지 않는다. 재청소는 무급 0원이며 새 폭탄방 추가요금이나 수익 원장을 만들지 않는다.
- 승인된 청소만 주급에 반영한다. 한국시간 월요일~일요일 수행분을 다음 월요일에 외부 지급하며 앱은 송금을 실행하지 않는다.
- 벌점·컴플레인은 평가 참고 기록이고 주급을 자동 차감하지 않는다.
- 관리자와 메이드 모두 객실 특이사항을 등록하고, 관리자만 해결 처리한다.
- 오늘 운영판과 객실·메이드 상세에서 날짜를 조정해 담당·수행·상태 이력을 조회한다.
- 구조화된 객실 상태를 색 한 값으로 저장하지 않는다. 화면 색은 실제 예약·청소·검수·촛불·차단 상태에서 파생한다.

### 메이드

모바일 하단 내비게이션은 `내 업무 / 근무 일정 / 알림 / 주급 / 더보기`를 사용한다. 데스크톱은 좌측 내비게이션으로 확장한다. 본인 대상 변경·취소 알림과 미전송 수는 상단 공통으로 둔다.

| 영역 | 필수 화면·패널 |
|---|---|
| 내 업무 | 오늘·내일 통보 일정, 출입 대기, 시작 가능, 청소 중 한 건, 업로드 대기, 취소 요청 상태 |
| 근무 일정 | 다음 주 가능일 제출·수정 요청, 주차별 제출 상태 |
| 알림 | 본인 담당·순서 변경, 청소 취소 사유, 남은 1–N 경로와 핵심 시각 |
| 청소 상세 | 담당·일정, 마스킹 PIN, 시작, 구역별 카메라·갤러리 사진, 특이사항, 촛불 수량, 현장 완료·업로드·전체 제출 |
| 완료 | 승인·반려·재청소 결과, 날짜·기간별 실제 수행 이력, 해당 청소 상세 딥링크 |
| 평가 | 본인 컴플레인 판정 확인, 내용 확인, 이의 메모, 관리자 재검토 결과 |
| 주급 | 이번 주 예상, 승인 확정, 검수 대기, 지난주 지급 예정, 지급 완료 이력 |
| 더보기 | 내 정보, 알림 권한·수신 상태, 로그인 비밀번호 변경 |

청소 한 건은 모든 큐에서 같은 `청소 상세`로, 객실 안전·예약 사건은 `객실 상세`로, 컴플레인은 `컴플레인 상세`로, 지급은 `메이드 × 지급 주차 상세`로 연결한다.

## 5. 반드시 클릭 가능한 대표 시나리오

1. 관리자가 예약 저장 → 대상일 퇴실 청소 자동 생성 → `내일 배정`에서 근무 가능 메이드의 담당·순서 저장·통보 → 대상일에 같은 업무를 정확히 한 번 활성화.
2. 메이드가 본인 `내 업무`에서 입퇴실 시각·단가·순서를 확인 → 체크아웃 전 대기 → 시각 도달 뒤 PIN 확인 → 청소 시작.
3. 구역별 사진·특이사항·촛불 입력 → 현장 완료 → 업로드 진행/실패/재시도 → 전체 제출.
4. 관리자가 전체 제출 승인 → 객실 상태 재계산 → 메이드 적립 확인. 반려 시에는 사유 확인 → 최초 청소한 메이드에게 무급 재청소 자동 귀속.
5. 촛불 1개로 입실 차단 → 관리자가 회수해 0개 → 다른 조건까지 충족하면 입실 준비 완료.
6. 레이트 체크아웃 변경으로 PIN 공개·청소 시작과 충돌 → 영향 확인 → 현장 조율·작업 중단/재계획·PIN 교체 → 해결.
7. 메이드 담당 취소 요청 → 관리자 유지·담당 변경·보류 결정 → 이전·새 담당에게 각각 본인 변화만 앱 내부 알림.
8. 활성 예약에서 연박 청소 요청 입력 → 대상일 청소 자동 생성 → 관리자 배정·통보 → 허용 시간에 시작.
9. 메이드 비활성 처리 → 미시작 재배정, 진행 중 마무리/중단 선택, 업로드 전용 상태 → 최종 완료.
10. 지난주 지급 `OPEN → PAYING` 선점 → 외부 송금 안내 → `PAID` 또는 정산 확인 필요 복구.
11. 컴플레인 접수 → 관리자 판정 → 메이드 확인 또는 이의 → 관리자 유지/정정 → 종결.
12. 객실·메이드 이력 날짜 변경, 필터 적용, 상세 진입 후 돌아왔을 때 날짜·필터·스크롤 복원.
13. 정상 목록을 `불러오는 중 / 0건 / 필터 결과 없음 / 오래된 데이터·오류`로 전환하고 오류 상태에서 위험 행동이 잠기는지 확인.
14. 관리자가 `오늘 배정`에서 현장 청소를 추가하거나 미시작 담당·순서를 바꿔 저장·통보, 또는 정해진 운영 사유를 선택해 즉시 소프트 취소 → 메이드 `내 업무`와 이전/새 담당별 앱 내부 알림 갱신 → 시작·업로드·검수 건은 배정 조정 대신 해당 진행·상세 화면으로 이동.

각 상태 변경은 성공 토스트만 띄우지 말고 원래 카드·배지·타임라인·가능 행동이 함께 바뀌어야 한다. 실제 서버 동시성은 구현하지 않되 오래된 버전과 중복 검수 방지는 결정적인 데모 토스트와 최신 상태 재로딩으로 표현한다.

## 6. 데모 데이터 기준

객실 번호·타입 매핑과 타입별 기본 청소요금은 2026년 8월 객실현황 시트를 운영 정본으로 사용한다. 아래 201–402호 표는 최초 화면 구조를 설명하던 과거 예시일 뿐 현재 객실 fixture가 아니며, 인명·예상시간·예약·청소 상태·과거 기록만 기능 검증용 데모로 사용한다.

| 데모 객실 | 타입 | 대표 상태 |
|---|---|---|
| 201호 | 스탠다드 더블 로프트 | 16:00 입실 예정, 미검수·촛불 1개로 빨강 차단 |
| 202호 | 프리미엄 더블 로프트 | 김민지1 청소 중, 주황 |
| 203호 | 프리미엄 더블 로프트 | 현장 완료·사진 업로드 대기 |
| 301호 | 파셜 오션뷰 프리미엄 더블 로프트 | 승인·촛불 0, 초록 준비 완료 |
| 302호 | 파셜 오션뷰 프리미엄 더블 로프트 | 검수 대기 |
| 401호 | 파셜 오션뷰 패밀리 투룸 로프트 | 예약상 투숙 중·연박 청소 요청 |
| 402호 | 파셜 오션뷰 패밀리 투룸 로프트 | 미래 예약·미래 작업, 중립 `예정` |

타입별 기본 청소요금은 정본 값 `16,000 / 20,000 / 20,000 / 30,000원`을 사용하고 예상시간은 데모 값으로 주급 계산 UI를 검증한다. 고객 이름은 관리자 예약 상세에서만 `홍길동 (데모)`처럼 선택값 한 건을 보여주고 메이드 목록·알림·특이사항에는 노출하지 않는다. PIN은 마스킹하고 사용자가 `보기`를 눌렀을 때만 `1234 · 데모 PIN`을 최대 30초 동안 메모리에서 표시한다.

메이드 계정은 `김민지1`, `김민지2`, `이서연` 같은 데모 이름을 사용한다. 담당·실제 시작자·제출자·검수자·수익 귀속자가 다른 재배정 사례를 하나 포함해 과거 이력이 현재 담당으로 덮이지 않는지 보여준다.

## 7. 상태·표현·행동 규칙

- 빨강: 입실 차단, 기한 초과, 해결 전 충돌처럼 즉시 조치가 필요한 상태.
- 주황: 청소 중, 업로드 대기, 검수 대기처럼 진행 중인 상태.
- 초록: 승인·촛불 0·운영 정상·차단 없음으로 실제 입실 준비가 끝난 상태.
- 중립: 예약상 투숙 중, 미래 예정, 운영 정보처럼 빨강·주황·초록으로 축약하면 안 되는 상태.
- 색만 쓰지 말고 상태명·아이콘·이유를 함께 표시한다.
- 관리자 카드 주 행동 우선순위: `입실 차단 해결 → 검수 → 긴급 배정 → 청소대상 생성 → 상세 보기`.
- 메이드 카드 주 행동 우선순위: `미전송 재시도 → 계속 청소 → 시작 → 결과 보기`.
- 카드에는 주 행동 한 개만 직접 노출하고 나머지 저위험 행동은 상세 또는 오버플로에 둔다.
- 위험 변경은 대상·현재 상태·변경 결과를 보여주는 확인창을 사용한다. 단순 조회·필터에는 확인창을 쓰지 않는다.
- 본문 14px 이상, 보조문구 12px 이상, 터치 영역 44×44px 이상을 지킨다.
- 긴 객실 타입명은 모바일에서 두 줄까지 허용하고 말줄임만으로 타입을 구분하지 않는다.
- 모달은 포커스를 가두고 `Esc`·닫기 버튼·완료 후 원래 트리거로 포커스 복귀를 지원한다.

## 8. 목록·오프라인·오류 화면 계약

모든 운영 큐는 다음 네 상태를 실제로 전환해 볼 수 있어야 한다.

1. `불러오는 중`: 스켈레톤, 없음 문구 금지.
2. `불러옴·0건`: 진짜 0건과 필터 결과 0건 구분, 필터 초기화 제공.
3. `불러옴·데이터 있음`: 최신 동기화 시각과 정상 행동 제공.
4. `오래된 데이터·오류`: 마지막 정상 동기화 시각, 읽기 전용 캐시 표기, 재시도 제공. 배정·상태 변경·PIN·검수·지급 잠금.

사진 업로드 실패는 사진 단위 재시도와 전체 미전송 수로 보여준다. `현장 완료·업로드 대기`는 다른 청소의 물리적 진행 슬롯을 해제하지만, 다음 작업 시작은 온라인 검증 뒤에만 가능하다는 설명을 둔다. 프로토타입이 실제 백그라운드 동기화·푸시를 제공한다고 오해시키지 말고 `데모 시뮬레이션`으로 표시한다.

## 9. 이번 HTML에서 제외할 것

- OTA/PMS/CSV 연동과 예약 가져오기
- 실제 계좌 송금·결제
- 실제 도어락 API·실제 PIN 저장
- 실시간 다중 사용자 서버, 실제 CAS·DB 제약
- 위치 기반 메이드 자동 배정과 동선 최적화
- 운영 통계·고급 분석
- 실제 사진 업로드·서버 보존
- 실제 푸시·SMS 발송과 다중 기기 실시간 변경 통보

제외 기능의 버튼을 활성 기능처럼 만들지 않는다. 구조 설명이 필요하면 `후속 범위` 또는 `데모` 배지와 비활성 설명으로만 표시한다.

## 10. 완료 조건

- 360, 390, 768, 1440px에서 가로 스크롤이 없고 내비게이션이 역할·뷰포트에 맞게 전환된다.
- 모든 하단/좌측 내비게이션, 목록 카드 주 행동, 뒤로 가기, 모달 저장·취소, 알림 딥링크가 동작한다.
- 14개 대표 시나리오를 초기화 가능한 데모 상태로 재현한다.
- 날짜·필터·스크롤 복귀와 관리자/메이드 역할 전환이 동작한다.
- 4개 목록 상태와 사진 업로드 실패·재시도를 재현한다.
- PIN은 목록·알림·브라우저 영속 저장소에 남지 않는다.
- 키보드만으로 주요 여정을 수행할 수 있고 모달 포커스·Esc·상태 안내가 동작한다.
- 브라우저 콘솔 오류와 깨진 버튼이 없다.
- 관리자 모바일, 메이드 모바일, 데스크톱 화면을 캡처하고 `QA.md`에 확인 결과와 알려진 제한을 기록한다.

객실 번호·타입 매핑과 타입별 기본 청소요금은 2026년 8월 객실현황 시트 정본을 사용한다. 인명·예상시간·예약·청소 상태·과거 기록과 아직 확정되지 않은 레이아웃 템플릿은 `데모`로 표시하고 교체 가능한 데이터 상수로 모은다.
