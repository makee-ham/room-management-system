# 객실 PIN 시트·청소 사진 이력 결정사항

기준일: 2026-09-04
상태: 확정
적용 범위: Google Drive 객실 비밀번호 시트, 청소 제출 사진 보관·조회, 담당 메이드 객실 PIN 접근

이 문서는 위 세 범위에서 `FINAL_UX_AUDIT.md`와 기존 화면 문구보다 우선하는 최신 정본이다. 그 밖의 제품 정책은 기존 정본을 유지한다.

## 1. Google Drive 객실 비밀번호 스프레드시트

- 객실 현황의 CSV·엑셀 다운로드와 별도로 `Google Drive 스프레드시트 비밀번호 업데이트` 버튼을 둔다.
- 대상 파일과 탭은 백엔드 설정으로 지정한다. 브라우저 번들, URL, 알림, 감사 이력에는 스프레드시트 링크·파일 ID·인증정보를 넣지 않는다.
- 쓰기 형식은 `객실번호`와 `비밀번호` 두 열이다. 사용자가 일부 객실을 필터링했더라도 비밀번호 시트 업데이트는 전체 객실을 한 번에 동기화한다.
- CSV·엑셀 객실 현황 파일에는 계속 PIN 원문을 포함하지 않는다.
- 실행 전 관리자에게 대상 성격, 전체 객실 수, 현재 비밀번호 revision을 보여 주고 재확인한다.
- 백엔드는 허용된 파일·탭만 수정할 수 있는 서비스 계정 또는 동등한 최소 권한 자격을 사용한다. 요청 revision, idempotency key, 전체 행 수를 검증한 뒤 원자적으로 교체한다.
- 작업 중 객실 PIN revision이 바뀌면 요청을 거절하고 최신 상태에서 다시 실행한다.
- 감사 이력에는 실행 관리자, 시각, 성공·실패, 행 수, revision만 남기며 PIN 원문과 대상 링크를 남기지 않는다.
- 현재 정적 와이어프레임은 실제 Google API나 백엔드와 연결하지 않는다. 성공 상태와 감사 이벤트만 결정적으로 시뮬레이션한다.

## 2. 청소 제출 사진 7일 보관과 과거 이력

- 메이드가 전체 청소 제출에 포함한 사진은 관리자 검수 결정 시점부터 정확히 7×24시간 보관한다.
- 검수 결정 전인 제출은 7일 타이머를 시작하지 않고 결정될 때까지 보관한다.
- 승인과 반려 모두 같은 7일 규칙을 적용한다. 재청소가 만들어지면 새 재청소 제출은 별도 보관기간을 가진다.
- 보관기간 안에는 관리자와 그 제출의 실제 수행 메이드만 사진 원본·미리보기를 볼 수 있다. 메이드는 다른 메이드의 사진이나 제출을 직접 URL로도 열 수 없다.
- 보관기간이 끝나면 원본, 파생 미리보기, 캐시를 삭제한다. 감사 이력에 파일명이나 사진 원문을 남기지 않는다.
- 사진이 만료된 뒤에도 객실, 실제 수행자, 청소 종류, 시작·현장 완료·제출·검수 시각, 제출 확인 내용과 메모, 검수 결과와 사유는 계속 조회할 수 있다.
- 메이드 주 내비게이션에 `청소 내역`을 제공한다. 목록에는 검수 결과, 사진 수와 만료 시각 또는 만료 상태, 제출 내용 요약을 함께 표시한다.
- 관리자 메이드 상세에서도 해당 메이드의 과거 제출을 열어 같은 사진·제출·검수 상세를 확인할 수 있다.
- 관리자는 `청소 → 완료`에서 선택 기준일을 포함한 최근 7일의 검수 완료 기록을 한 번에 조회한다. 기준일보다 6일 전부터 기준일까지를 포함하며 그 밖의 기록은 이 목록에서 제외한다.
- 관리자 완료 목록은 현장 완료 날짜를 최신순으로 묶고 각 날짜의 건수를 표시한다. 객실번호 또는 실제 수행자 이름 하나로 검색하며, 검색 결과도 날짜 그룹을 유지한다.
- 관리자 완료 카드에서 객실, 실제 수행자, 현장 완료·제출·검수 시각, 사진 보관 상태, 제출 내용 요약과 검수 결과를 확인하고 같은 사진·제출·검수 상세로 진입한다.

## 3. 담당 메이드 객실 PIN 접근과 실시간 갱신

- 메이드의 객실 PIN 접근은 관리자가 객실 담당을 저장·통보한 순간 시작한다. 청소 시작 가능 시각 전에도 볼 수 있다.
- 접근은 현장 청소, 업로드 대기, 전체 제출, 관리자 검수 대기까지 유지한다.
- 관리자 최종 승인 또는 반려 결정, 담당 취소 승인, 다른 메이드로 재배정, 계정 비활성 종결 중 하나가 확정되면 이전 담당의 접근을 즉시 끝낸다.
- 담당 취소를 요청했어도 관리자 결정 전에는 담당과 PIN 접근을 유지한다.
- 청소팀장 또는 관리자가 작업 중 PIN을 변경하면 현재 담당자와 이미 통보된 다음 근무일 담당자에게 새 revision을 즉시 전파한다. 열어 둔 기존 PIN 원문은 즉시 폐기하고 다음 조회에서 최신 값을 받는다.
- 한 번에 한 객실의 PIN만 메모리에 두고, 매 조회는 30초 뒤 자동으로 가린다. PIN 원문은 URL, 알림, 로그, `localStorage`, `sessionStorage`, 브라우저 history state에 저장하지 않는다.
- 오프라인 또는 오래된 데이터 상태에서는 새 PIN 조회와 변경을 막고 최신 상태를 다시 확인하게 한다.

## 4. 와이어프레임 확인 기준

- 관리자 객실 내보내기 모달에서 CSV, 엑셀, Google Drive 비밀번호 업데이트를 구분할 수 있어야 한다.
- 비밀번호 시트 업데이트에는 전체 객실 수, 두 열 형식, revision, 백엔드 지정 대상, 정적 데모 한계가 보여야 한다.
- 메이드가 다음 근무일 배정 통보를 받은 객실과 현재 담당 객실의 PIN을 시작 시각 전부터 열 수 있어야 한다.
- 현장 완료·업로드 대기와 검수 대기에서도 PIN을 볼 수 있고 최종 결정 뒤에는 볼 수 없어야 한다.
- PIN 변경 뒤 같은 화면 상태를 역할 전환해도 담당 메이드에게 최신 변경 시각과 값이 반영되어야 한다.
- `청소 내역`에서 보관 중 사진 상세와 7일 만료 상태를 모두 확인할 수 있어야 한다.
- 과거 청소 상세에는 사진, 제출 확인 내용과 메모, 검수 결과와 사유가 함께 보여야 한다.
- 관리자 `청소 → 완료`에는 최근 7일 범위와 전체 건수가 표시되고, 기록은 현장 완료 날짜별 최신순으로 구분되어야 한다.
- 관리자 완료 검색에서 객실번호와 실제 수행자 이름이 각각 일치하는 기록만 남고, 결과가 없어도 검색 해제 행동을 제공해야 한다.
