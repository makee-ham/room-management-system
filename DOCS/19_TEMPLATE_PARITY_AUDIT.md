# 메이드·관리자 청소 사진 템플릿 정합성 감사 보고서

- 감사일: 2026-08-24
- 기준: `DOCS/18_TYPE_PHOTO_TEMPLATE_POLICY.md`, `WIREFRAME/index.html`
- 범위: 관리자 템플릿 관리, 메이드 작업 사진 슬롯, 관리자 제출 검수

## 결론

메이드 작업 화면의 항목이 많은 것이 정상이다. 퇴실 청소의 타입 기본 규칙은 객실별 침실·욕실·배수구·팬트리 수에 따라 여러 개의 실제 사진 슬롯으로 확장된다. 기존 관리자 템플릿 관리 화면은 확장 전 기본 규칙만 표시해 메이드 화면보다 항목이 적어 보였으며, 이것이 주된 불일치였다.

관리자 제출 검수는 이미 제출 당시 `templateSnapshot`을 사용하고 있었으나, 화면에서 동일 개수와 계약 일치를 명시하지 않아 사용자가 정합성을 확인하기 어려웠다. 이번 보정으로 관리자 템플릿 미리보기와 검수 모두 메이드 슬롯 계약을 명시적으로 보여준다.

## 발견 사항과 조치

| 구분 | 발견 | 판정 | 조치 |
|---|---|---|---|
| 관리자 템플릿 상세 | 확장 전 `template.photos`만 표시 | 결함 | 실제 객실 선택과 객실별 확장 슬롯 전체 미리보기 추가 |
| 관리자 템플릿 목록 | 기본 규칙 수를 `필수 사진 N장`으로 표시 | 결함 | 기본 규칙과 메이드 실제 슬롯 범위를 분리 표시 |
| 관리자 검수 | 제출 스냅샷 사용은 정상이나 동일 구조 확인이 어려움 | 확인성 부족 | 메이드 제출 기준 슬롯 수, 관리자 검수 슬롯 수, 구조 일치 배지 추가 |
| 개수 명칭 | 슬롯 수를 `필수 촬영 구역`으로 표현 | 결함 | `필수 사진 슬롯`으로 통일 |
| TV 안내 | `version === v7`일 때만 메이드 안내 노출 | 결함 | 실제 `tv-on` 슬롯 존재 여부로 판단 |
| 과거 v6 | 현재 v7과 달리 TV 슬롯 없음 | 의도된 차이 | 제출 당시 버전·슬롯을 보존하고 소급하지 않음 |
| 다중 사진 문구 | 한 슬롯 1장 구조인데 `여러 장 허용`으로 안내 | 결함 | 한 슬롯 1장·재촬영 시 교체로 명확화 |
| 미확인 112실 | 최소 공통 레이아웃만 사용 | 의도된 보류 | 관리자 미리보기에 `레이아웃 확인 보류`와 사유 노출 |
| 연박·재청소 | 123장 표본 기반 퇴실 청소와 규칙 출처가 다름 | 의도된 차이 | 공통 데모 슬롯으로 구분 표시 |

## 통일한 사진 슬롯 계약

관리자 미리보기, 메이드 작업, 관리자 검수는 다음 값을 같은 순서로 사용한다.

1. 슬롯 ID
2. 순서
3. 구역
4. 항목명
5. 촬영 설명
6. 필수·선택 여부
7. 반복 인스턴스 번호와 총수

관리자 검수는 현재 활성 템플릿을 다시 계산하지 않고 제출 당시 스냅샷을 기준으로 한다. 따라서 템플릿 버전이나 객실 타입이 이후 변경되어도 과거 제출은 바뀌지 않는다.

## 의도적으로 유지한 차이

- 새 퇴실 청소 v7 이상: `TV 켜짐·화면 출력 확인` 필수 슬롯 포함
- 과거 퇴실 청소 v6: TV 슬롯 미포함, 소급 추가 금지
- 퇴실 청소: 123장 표본과 객실 레이아웃 보정 기반
- 연박·재청소: 현재 데모 공통 규칙
- 사진 확인 9실: 확인된 반복 수 사용
- 나머지 112실: 침실 1·욕실 1·배수구 1 최소 공통값과 확인 보류 표시

## 남은 한계

- 관리자 편집 화면은 예상시간만 수정하며 사진 슬롯 추가·삭제·순서 변경과 레이아웃 마스터 편집은 지원하지 않는다.
- 112실의 실제 레이아웃은 운영 전 별도 확인이 필요하다.
- 사진은 현재 탭 메모리 데모이며 실제 서버 업로드·권한·보존·동시 편집 계약은 구현되지 않았다.
