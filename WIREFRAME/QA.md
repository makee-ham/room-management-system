## 결과 요약

배정 대상일의 체크아웃 fixture 4건과 연박 청소 신청 fixture 1건이 청소대상 객실에 자동 포함되고, 기존 직접 등록 1건과 출처별로 구분되는지 확인했다. 객실 호수·타입·요금·특수 시각과 `가능` 메이드만 표시하는 기존 배정 규칙을 유지하면서 `전체 + 네 객실 타입` 필터에 대상 수와 객실당 고정 청소 요금을 표시했다. 객실 행에서는 담당만 고르고, 별도 `메이드별 청소 순서` 보드에서 전체 배정을 메이드별 1–N번으로 조정하도록 분리했다. `청소대상 직접 등록`에서 1208호 퇴실 청소를 추가하자 목록이 6건에서 7건으로 늘고 프리미엄 타입 필터로 자동 전환됐으며 같은 객실·청소 유형의 재등록은 차단됐다.

메이드별 보드를 `메이드별 타입 배정·청소 순서`로 확장했다. 근무 가능한 김민지1·이서연 카드에 네 객실 타입을 0객실까지 항상 표시하고, 담당을 선택·재배정할 때 타입별 객실 수와 `총 N객실 · 총 청소비 N원`을 동시에 다시 계산했다. 두 메이드에게 3객실씩 배정한 비교 상태에서 김민지1은 스탠다드 2·패밀리 1·총 64,000원, 이서연은 프리미엄 1·오션뷰 프리미엄 1·패밀리 1·총 75,000원으로 표시됐다. 이는 관리자의 형평성 판단을 돕는 요약이며 자동 균등 배정은 아니다.

전체 여섯 객실 중 401호 한 건만 새로 배정한 상태에서 나머지 402·412호가 미배정이어도 `배정된 객실만 저장·통보`가 활성화되는지 확인했다. 저장 뒤 누적 통보는 4건, 미배정 대기는 2건이었고 저장 버튼은 다시 비활성화되어 기존 통보 3건을 중복 기록하지 않았다. 김민지1의 `내 업무`에는 새로 통보된 401호가 보이지만 미배정 402·412호는 보이지 않았다.

예약 예정 시각을 기준으로 얼리 체크인·레이트 체크아웃을 자동 판정하도록 확장했다. 체크인 15:00은 얼리 1시간, 14:00은 얼리 2시간, 체크아웃 13:00은 레이트 2시간으로 표시됐고 정확히 16:00·11:00에서는 특수 상태가 제거됐다. 예약 저장 결과가 객실 카드·상세·필터와 청소 배정 일정에 동일하게 반영되는지 확인했다.

메이드 203호 청소 중 화면에서 이미지 3장을 한 번에 선택해 미리보기 3개를 확인하고 한 장을 개별 제거한 뒤, 메모와 이미지 2장을 객실 특이사항으로 등록했다. 같은 탭에서 관리자 역할로 전환해 203호 객실 상세의 등록자·시각·유형·메모·이미지 2장과 확대 대화상자를 확인했다. 사진만 등록, 메모만 등록, 개인정보 형식 차단, 타 메이드 302호 직접 URL 진입 차단도 각각 별도 상태에서 확인했다.

메이드가 본인 담당 203호를 폭탄방으로 이미지와 함께 신고하고, 관리자가 해당 신고를 먼저 승인해야 전체 검수를 완료할 수 있는 흐름을 확인했다. 승인 결과는 203호 고정 청소비 22,000원에 같은 금액의 폭탄방 추가 22,000원만 더해 해당 객실 합계 44,000원으로 확정됐으며, 다른 객실이나 주간 총액 전체를 두 배로 계산하지 않았다. 관리자의 검수·폭탄방 요금 원장과 메이드의 주급·과거 이력에서 같은 객실 단위 산식과 상태를 확인했고, 별도 302호에서는 미인정 뒤 기본 청소비만 유지되는 분기도 확인했다.

3. 412호 퇴실 청소는 현장 요청 `직접 등록`으로 구분되고 요약이 `자동 5 · 직접 1`인지 확인했다. 재청소는 직접 등록 선택지에 없었다.
4. `청소대상 직접 등록`에서 1208호·퇴실 청소를 추가하자 배정 행과 담당 드롭다운이 즉시 생성되고 요약이 `자동 5 · 직접 2`로 바뀌었다.
5. 같은 1208호·퇴실 청소를 다시 등록하자 대상 수는 7건을 유지하고 `이미 직접 등록된 청소대상` 안내와 대화상자를 유지했다.
6. 7개 담당 드롭다운 모두 `담당 선택 / 김민지1 (근무 가능) / 이서연 (근무 가능)`만 포함하고 김민지2·불가·미제출 선택지는 없었다.
7. 새로 등록한 1208호 한 건만 김민지1에게 배정해도 다른 미배정 객실과 관계없이 저장 버튼이 활성화되고, 그 한 건만 추가 통보 이력에 남는지 확인했다.

### 3. 근무 가능 메이드만 배정

1. 월요일 가능 현황은 김민지1 `가능`, 김민지2 `불가`, 이서연 `가능`이었다.
2. 초기 여섯 개와 직접 등록 후 일곱 개 담당 드롭다운에서 `담당 선택 / 김민지1 (근무 가능) / 이서연 (근무 가능)`만 확인했다.
3. `김민지2`, `불가`, `미제출` 문자열은 담당 선택지에 0건이었다.
4. 직접 등록 후 1208호 한 건만 김민지1에게 배정해도 저장 버튼이 활성화됐다.
5. 저장 뒤 그 한 건만 새 통보 이력에 포함되고 다른 미배정 객실은 대기 상태로 남는지 확인했다.

### 4. 메이드별 청소 순서 지정·통보

1. 초기 메이드별 보드에서 김민지1의 201호는 `1번째`, 이서연의 202·302호는 각각 `1번째`, `2번째`인지 확인했다.
2. 객실 담당 표 안에는 순서 이동 버튼이 없고, 각 행에는 현재 `메이드명 · 순서 보드 N번째`를 읽기 전용으로 표시했다.
3. 401호를 김민지1에게 지정하자 김민지1 보드 마지막 2번째로 추가됐고, 보드의 401호 위 이동 버튼으로 401호 1번째·201호 2번째를 만들었다.
4. 402·412호를 미배정으로 둔 채 401호만 김민지1의 2번째로 지정하자 `배정된 객실만 저장·통보`가 활성화됐다.
5. 저장 뒤 누적 통보 4건·미배정 2건이 되었고, 401호 한 건의 이전·새 담당과 순서만 새 이력에 추가됐다.
6. 새 변경이 사라진 직후 저장 버튼이 다시 비활성화되어 기존 통보 행을 중복 통보하지 않았다.
7. 메이드 역할 `내 업무`에서 김민지1의 201·401호만 순서대로 표시되고, 미배정 402·412호와 관리자 전용 담당·순서 컨트롤은 노출되지 않았다.

### 5. 메이드별 타입 구성·총 청소비 비교

1. 초기 김민지1 카드에서 스탠다드 1객실과 나머지 세 타입 0객실, 총 1객실·18,000원을 확인했다.
2. 초기 이서연 카드에서 프리미엄 1객실·오션뷰 프리미엄 1객실·나머지 두 타입 0객실, 총 2객실·47,000원을 확인했다.
3. 401호를 김민지1에게 선택한 뒤 이서연으로 재배정해 양쪽 타입 개수·총 객실 수·총 청소비가 선택 즉시 바뀌는지 확인했다.
4. 402·412호를 김민지1에게 배정해 두 사람 모두 총 3객실이지만 타입 구성과 총 청소비가 다른 상태를 만들고 한 화면에서 비교했다.
5. 객실 타입 필터를 바꿔도 요약은 전체 6객실 배정 기준을 유지하고, 미배정 객실은 요약 개수와 금액에서 제외되는지 확인했다.

### 6. 주간 근무 기록

1. 배정 상단 `주간 근무 기록`에서 `메이드 → 근무 기록`으로 이동했다.
2. 기본 선택인 2026-08-10–16에서 전체 3명의 가능 제출 15인일, 담당 통보 12인일, 실근무 완료 11인일을 확인했다.
3. 주차를 2026-08-03–09, 메이드를 김민지2로 바꾸자 인물 카드가 1개로 줄고 가능 5일·배정 4일·실근무 4일로 바뀌었다.
4. 각 날짜에서 `가능 제출`, `담당 통보`, `실근무 완료`가 독립 표식으로 보이며 가능 제출만 있는 날짜를 실근무로 세지 않는지 확인했다.
5. 현재 계획 주차와 과거 마감 기록을 같은 필터에서 전환할 수 있고, 화면에 서버 영속 저장이 아닌 데모 fixture임을 명시했다.

## 확인된 프로토타입 한계

- 체크아웃·연박 신청 자동 구성, 직접 등록, 가능일 제출·담당·순번·통보·실근무 완료 기록은 현재 탭 메모리와 결정적 fixture다. 실제 예약 서버 영속 저장·동시성·불변 이벤트 원장이 아니다.
- 객실 특이사항 이미지 선택·미리보기·관리자 조회는 현재 탭 메모리의 `blob:` URL 시뮬레이션이다. 실제 이미지 서버 전송·재개·영속 보존·악성 파일 검사는 구현하지 않았고 초기화·시나리오 교체·탭 종료 뒤 복원되지 않는다.
- 폭탄방 신고 이미지·검수 결정·객실별 추가금 원장도 현재 탭 메모리와 데모 fixture다. 실제 파일 선택기는 자동화하지 않고 `데모 이미지 2장`으로 신고 흐름을 확인했으며, 실제 이미지 서버 업로드·장기 보존·검수 동시성·급여 송금은 구현하지 않았다.
- 전체 반려 뒤 최초 수행자에게 자동 귀속되는 무급 재청소와 0원 완료 이력도 탭 메모리 데모다. 실제 근로·급여 시스템에 0원 정산을 전송하거나 다른 외부 서비스에서 재배정을 강제하지 않는다.
- `배정 통보 완료`는 앱 내부 화면 갱신 시뮬레이션이며 실제 푸시·SMS·전화 발송이 아니다.
- 타입별 객실 수와 총 청소비는 현재 탭의 배정 fixture를 실시간 합산한 판단 보조값이며 자동 균등 배정·업무 강도 산정·동선 최적화는 구현하지 않았다.
- 실제 운영 데이터가 없어 객실·인명·단가·예상시간·특수 시각·과거 기록은 모두 데모 fixture다.
- 최종 서비스 전에는 가능일 제출 버전, 마감 스냅샷, 배정 이벤트, 실제 수행 회차를 불변 사용자 ID와 한국시간 기준으로 서버에 분리 저장해야 한다.
