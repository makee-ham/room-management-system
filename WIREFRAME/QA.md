## 대표 업무 흐름

### 1. 메이드 주간 가능일

1. 시나리오 1, 메이드 `근무 일정`, 2026-08-16 21:10에서 시작했다.
2. 월·화·목·금 기본 선택에 수요일을 추가했다.
3. `다음 주 가능일 제출` 뒤 `제출 완료`, `제출 내용 수정`, 수요일 `근무 가능`을 확인했다.
4. 시간을 22:15로 바꾼 뒤 `가능일 변경 요청`을 실행했다.
5. `제출 마감 지남`, `변경 요청`, `관리자 확인 요청됨` 상태를 확인했다.

### 2. 관리자 전날 배정·통보

1. 시나리오 2, 관리자 `청소 → 전날 배정`, 2026-08-16 21:55에서 시작했다.
2. `3/3 제출`, 다음 날 5객실, 담당 선택 3건, 미배정 2건을 확인했다.
3. 미배정 상태에서는 `배정 저장·메이드 통보`가 비활성임을 확인했다.
4. 402호에 근무 가능 메이드 김민지1, 412호에 월요일 불가 메이드 김민지2를 선택했다.
5. 예외 사유 입력 영역이 나타나고 사유가 없을 때 저장이 계속 잠기는 것을 확인했다.
6. `얼리 체크인 우선 대응 가능 확인`을 입력한 뒤에만 저장이 활성화됐다.
7. 저장 뒤 담당 5건, 미배정 0건, 통보 완료, 402·412호 배정 이력과 예외 사유를 확인했다.

### 3. 통보 전후 공개 경계

- 402호 담당을 선택만 하고 저장하지 않은 상태에서 메이드로 전환했을 때 402호는 보이지 않았다.
- 저장·통보 뒤 메이드 `내 업무`에 `다음 근무일 배정 통보 2건`과 201·402호가 표시됐다.
- 메이드 `알림`에 201·402호 배정 알림이 각각 표시됐다.
- 김민지2에게 배정한 412호와 전체 메이드 가능일 매트릭스는 김민지1 화면에 노출되지 않았다.
- 메이드 화면에는 `assignment-maid` 컨트롤이 없고 공개 청소 내비게이션도 없다.

## 확인된 프로토타입 한계

- 제출·배정·통보는 현재 탭 메모리의 결정적 데모 상태다. 실제 저장·동시성·충돌 제어가 아니다.
- `배정 통보 완료`는 앱 내부 화면 갱신 시뮬레이션이며 실제 푸시·SMS·전화 발송이 아니다.
- 실제 운영 데이터가 없어 객실·인명·단가·예상시간·사진은 모두 데모 fixture다.
- 최종 서비스 전에는 서버 권한 검사, 주간 마감 스케줄러, 불변 감사 로그, 알림 발송 재시도, 다중 관리자 버전 충돌 처리가 필요하다.
