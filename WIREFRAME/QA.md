## 결과 요약

배정 대상일의 체크아웃 fixture 4건과 연박 청소 신청 fixture 1건이 청소대상 객실에 자동 포함되고, 기존 직접 등록 1건과 출처별로 구분되는지 확인했다. 객실 호수·타입·요금·특수 시각과 `가능` 메이드만 표시하는 기존 배정 규칙을 유지하면서 `전체 + 네 객실 타입` 필터에 대상 수와 객실당 고정 청소 요금을 표시했다. 객실 행에서는 담당만 고르고, 별도 `메이드별 청소 순서` 보드에서 전체 배정을 메이드별 1–N번으로 조정하도록 분리했다. `청소대상 직접 등록`에서 1208호 퇴실 청소를 추가하자 목록이 6건에서 7건으로 늘고 프리미엄 타입 필터로 자동 전환됐으며 같은 객실·청소 유형의 재등록은 차단됐다.

최종 통합본에서 9명 중 월요일 근무 가능·활성 메이드 7명을 후보로 두고 미배정 5건을 랜덤 배정했다. 기존 통보 350호·332호·639호의 담당과 순서는 그대로였고, 새 729·756·211·142·352호는 기존 확정액이 없는 다섯 후보에게 나뉘었다. 별도 메이드별 작업량·동선 비교판은 노출하지 않고, 랜덤 결과 아래 메이드별 객실 카드에서 담당과 1–N 순서만 관리자가 수정한다.

전체 여섯 객실 중 401호 한 건만 새로 배정한 상태에서 나머지 402·412호가 미배정이어도 `배정된 객실만 저장·통보`가 활성화되는지 확인했다. 저장 뒤 누적 통보는 4건, 미배정 대기는 2건이었고 저장 버튼은 다시 비활성화되어 기존 통보 3건을 중복 기록하지 않았다. 김민지1의 `내 업무`에는 새로 통보된 401호가 보이지만 미배정 402·412호는 보이지 않았다.

## 시각 비교 기록

관리자 기준 이미지는 `reference/redesign-concepts/admin-next-day-assignment.png` 1536×1024, 구현 캡처는 1440×1000에서 비교했다. 새 근무 기록 화면은 같은 네이비·화이트·골드 토큰과 표·상태 배지 계열을 확장했다.

간편 예약은 `reference/redesign-concepts/admin-quick-booking-1440.png`와 `admin-quick-booking-390.png`에서 객실 고정 열·날짜 고정 행·노란 1박·파란 연박·회색 잠금·터치 안전 안내의 시각 우선순위를 잡은 뒤, 실제 단일 HTML의 기존 관리자 셸과 360/390/768/1440px 규칙에 맞춰 구현했다.

| 비교 지점 | 기준과 구현 비교 |
|---|---|
| 정보 구조 | 관리자 `청소` 활성·상단 요약·가능일 매트릭스·배정 표를 유지하고, 배정 표 아래에 메이드별 순서 보드를 추가했다. |

| 자동 구성 안내 | 요약 바로 아래 얇은 파란 안내 띠에 체크아웃·연박·직접 등록 수를 배치해 기존 카드/표 구조를 바꾸지 않았다. |
| 후보 제한 | 기준의 가능/불가 상태를 유지하되 최신 결정에 따라 드롭다운은 가능 제출자만 노출한다. |
| 타입별 보기 | 기존 얇은 선·카드 토큰으로 `전체 + 네 타입` 필터를 만들고 대상 수와 객실당 고정 요금을 한눈에 비교하게 했다. |

| 반응형 | 데스크톱 타입 필터·메이드 보드를 모바일 2열 필터·1열 순서 보드로 전환하고, 7일 가로 기록은 날짜별 세로 행으로 바꿨다. |
