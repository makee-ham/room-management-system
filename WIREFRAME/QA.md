## 날짜·객실·PIN 수용 기준

- 날짜 버튼을 누르면 390px에서는 월간 달력 바텀시트, 1440px에서는 화면 중앙 월간 달력 대화상자(centered dialog)가 열린다.
- 이전/다음 달 이동, 날짜 선택, 바깥 클릭, Escape 닫기가 동작하고 선택 날짜가 화면·URL에 반영된다.
- 객실 번호 검색과 네 객실 유형, 운영 상태 필터를 조합할 수 있다.
- 상태 필터의 `얼리 체크인`과 `레이트 체크아웃`이 각각 해당 객실만 남기고 URL 상태에도 반영된다.
- `내보내기`는 기본적으로 선택 날짜의 전체 객실을 CSV와 실제 OOXML Excel `.xlsx`(`.xls` 아님)로 저장하고, 선택하면 현재 검색·필터 결과만 저장한다. 확장자·MIME·ZIP/XML 패키지를 확인하고 Excel에서 열어 보며, HTML을 `.xls` 또는 `.xlsx`로 이름만 바꾼 파일은 통과시키지 않는다.
- 내보낸 파일에는 객실 유형·입퇴실·입실 가능·청소·촛불·운영 상태·중지 사유·대체 객실이 있고 객실 PIN 원문은 없다.
- 객실 카드에 체크아웃·체크인 시각, 레이트/얼리 긴급도, 예약 등록 가능 여부, 현재 입실 가능 여부가 구분된다.
- 레이트 체크아웃을 15:00 뒤로 설정할 수 없다. 얼리 체크인의 미확정 최저 시각을 임의로 제한하거나 사실처럼 표기하지 않는다.
- 각 객실 카드·상세에서 PIN 영역은 한 번만 나온다.
- PIN은 기본 마스킹이고 관리자만 모든 객실을 한 객실씩 볼 수 있다. 30초 만료, 역할·화면 이동, 창 비활성화에서 다시 마스킹된다.
- PIN 수정 시트는 정확히 네 자리 숫자와 선행 0을 허용하고, 보안 난수 생성 → 변경 내용 확인 → 저장 순서를 제공한다.
- 미래 예약 저장은 허용하되 현재 입실 불가 사유는 제거하지 않는다.

## 상태 조합 수용 기준

다음 fixture와 화면 상태를 교차 확인합니다.

- 촛불 `− / +` 입력은 관리자 객실 상세와 메이드 청소 결과 입력 중에만 보인다.
- 메이드가 `현장 완료`하기 전에는 입력 중 수량이 객실 최종 수량에 반영되지 않고, 현장 완료 시 한 번 반영된다.
- 투숙 중인 모든 객실의 촛불 값은 0이고 관리자·메이드 양쪽에 촛불 입력/회수 UI가 보이지 않으며 변경도 차단된다.
- `오늘 퇴실 + 퇴실 전 + 촛불 있음` 조합이 없다.
- 비투숙 객실에서는 촛불과 청소 필요·예약 준비 상태를 유연하게 조합할 수 있다.
- 관리자 객실 상세의 촛불 변경 또는 메이드 `현장 완료` 뒤 관리자 `오늘`의 촛불 객실 요약이 현재 상태로 다시 계산된다. 투숙 중 객실은 요약에서 제외한다. 412호 상태 변경 전후 요약 수치 재계산과 201호 회수를 Browser에서 확인했다.
- 얼리 체크인은 일반 체크인보다 높은 긴급도로 정렬·표시된다.
- 운영 중지는 어느 객실 상태에서도 시작할 수 있다.
- 운영 중지 뒤 객실 카드와 상세에 입력한 중지 사유가 즉시 보이고, 대체 객실을 정했다면 함께 보인다. 운영 재개는 별도의 `재개 사유` 입력을 요구하지 않으며, 재개 뒤에도 기존 중지 사유와 중지·재개 이벤트 및 각 시각이 사건 이력에 보존된다.
- 다른 방 배정은 운영 중지 흐름 안에서만 제공하고, 같은 유형 준비 완료 우선·타 유형 사유 필수를 지킨다.
- 객실 이동 전후 예약·객실·PIN 변경 이력이 보존된다.

## 메이드 근무·청소 수용 기준

- 09:00 근무 등록에서 `오늘 근무 가능`과 `오늘 쉬어요`를 선택할 수 있다.
- 미등록 메이드는 공개 목록을 볼 수 있지만 선점 버튼이 잠기고 정확히 `오늘 근무 가능 여부를 먼저 등록해 주세요`가 표시된다.
- 업무 없음/배정 있음/진행 중에 따라 휴무 전환이 각각 즉시/관리자 승인/중단·인계로 분기된다.
- 관리자는 시작 전 청소를 특정 메이드에게 직접 배정할 수 있다.
- `일감 찾기 → 선점 → 시간 게이트 → PIN → 일 시작 → 체크·사진·메모·촛불 → 현장 완료 → 업로드 재시도 → 청소 전체 제출`을 이어서 수행할 수 있다.
- 시작 전에는 `일 시작`, 현장 입력 완료 뒤에는 `현장 완료`, 업로드 완료 뒤에는 `청소 전체 제출`이 주 행동이다.
- 한 메이드가 두 청소를 동시에 시작할 수 없다.
- 메이드가 청소 전체를 제출한 뒤 관리자는 해당 작업의 전체 제출에 포함된 결정적 데모 이미지 302호 4장·203호 3장을 썸네일로 확인할 수 있다.
- 각 썸네일은 확대 보기로 열 수 있고, 확대 화면에서 작업·객실 맥락을 잃지 않는다.
- 검수는 이미지 전체를 확인한 뒤 제출 전체를 승인 또는 반려하며 사진별 승인 컨트롤이 없다.
- 반려 시 사유와 재청소 후속 상태가 관리자·메이드 양쪽에 반영된다.

- 관리자 `더보기 → 청소 템플릿 설정`에 `4 객실 유형 × 퇴실·연박·재청소`의 중복 없는 12개 데모 조합이 나온다.
- 목록에서 템플릿을 열면 예상시간, 체크 항목, 필수 사진 항목을 함께 확인할 수 있다.
- 수정은 편집값 입력 뒤 변경 내용 확인을 거쳐 저장하며, 확인 없이 즉시 기존 값을 덮어쓰지 않는다.
- 저장 뒤 새로 생성한 작업에는 변경된 템플릿이 적용된다.
- 저장 전에 생성된 기존 작업은 예상시간·체크·사진 항목의 생성 당시 스냅샷을 유지한다.
- 템플릿 목록 12개·상세 체크 4개·사진 4개, 예상시간 55→60분과 필수 사진 4→3 변경, 확인 뒤 v4→v5 저장, 기존 작업 스냅샷 유지와 새 작업 적용을 Browser에서 확인했다.

## 주급·컴플레인 수용 기준

- 관리자 주급은 메이드별 예상 포함·검수 대기·지급액을, 메이드 주급은 이번 주 작업별 예상/확정을 누적해 보여 준다.
- 관리자와 메이드 모두 이번 주 요약을 상단에 고정하고, 기본 이력에는 저장된 전체 과거 주차만 최신순으로 표시한다.
- 주급 달력은 월요일부터 일요일 순서이며 날짜 하나를 누르면 그 날짜가 포함된 주 전체로 정규화한다. 2026-07-23 선택 시 `2026-07-20(월)–07-26(일)`이 표시되고 객실 조회 기준일은 바뀌지 않는 것을 Browser에서 확인했다.
- 관리자 화면은 선택 주차의 전체 메이드 금액·상태를, 메이드 화면은 본인의 금액·작업 상세·승인·지급 상태만 표시한다. 김민지1의 같은 주차 금액은 두 역할에서 일치한다.
- 메이드 기본 화면에서 과거 데모 5주, 달력 선택 뒤 정확히 1주, `전체 과거 주차 보기` 뒤 다시 5주와 달력 버튼 초점 복원을 Browser에서 확인했다.
- 현재 주의 일요일 2026-08-16은 같은 주 선택으로 활성화되고 다음 주 월요일 2026-08-17부터 잠긴다. 기록 없는 주차는 다른 자료를 대체 표시하지 않고 0건 상태를 제공한다.
- 302호 전체 승인 전후 관리자 이번 주 요약이 `198,500 / 253,500 / 55,000원`에서 `223,500 / 253,500 / 30,000원`으로 전환되고, 실제 수행자 이서연의 확정액이 74,000원에서 99,000원으로 바뀌며 김민지1 금액은 유지되는 것을 Browser에서 확인했다.
- 메이드 화면에는 관리자 전용 `지급 완료` 토글이나 지급 상태 변경 컨트롤이 없다.
- 메이드 역할에서 `detail=pay:*`, 관리자 객실 상세와 다른 메이드 컴플레인 ID를 직접 요청해도 관리자 컨트롤·타인 기록이 렌더되지 않으며, 지급·컴플레인 삭제 실행 취소 액션도 역할을 다시 확인한다.
- 지난주 지급 컨트롤은 `지급 완료` 단일 토글이며 내부 `OPEN → PAYING` 같은 단계를 사용자 UI에 노출하지 않는다.
- 토글 안내는 정확히 `앱은 송금하지 않고 지급 여부만 기록합니다`다.
- ON 즉시 지급 완료를 기록하고 10초 실행 취소를 제공한다. OFF/취소도 삭제가 아닌 정정 감사 이벤트를 남긴다.
- 컴플레인·벌점 추가 시 메이드와 사유가 필수이며 벌점은 점수도 필수다.
- 활성 목록 삭제는 소프트 삭제이고 10초 실행 취소가 가능하다.
- 컴플레인·벌점 추가·삭제·복원 이력이 남고 주급 금액은 자동으로 바뀌지 않는다.

## 접근성 수용 기준

- 페이지에 건너뛰기 링크와 논리적인 제목 구조가 있다.
- 아이콘 버튼, 역할 전환, PIN 보기, 토글, 접이식 섹션에 접근 가능한 이름과 상태가 있다.
- 모든 입력에 연결된 `label` 또는 동등한 접근 가능한 이름이 있고 중복 ID가 없다.
- 상태는 색만으로 전달하지 않고 텍스트·아이콘·원인·다음 행동을 함께 쓴다.
- 바텀시트·대화상자를 열면 초점이 내부로 이동하고 Tab 순환이 내부에 머문다.
- Escape와 명시적 닫기로 종료한 뒤 호출 요소로 초점이 돌아간다.
- 배경 스크롤·상호작용이 잠기고 `prefers-reduced-motion`에서 불필요한 전환이 제거된다.
- 주요 터치 대상은 최소 44×44px다.

실제 화면 판독기와 물리 키보드 전체 순회는 이 브라우저 회귀와 별도로 실기기 검증이 필요합니다.

## 콘솔·개인정보·오류 상태 수용 기준

- 최초 로드와 역할 전환, 13개 시나리오 핵심 조작 뒤 console `error`·`warn`이 0건이다.
- `localStorage.length`와 `sessionStorage.length`가 0이다.
- PIN, 고객명, 사진 원문이 저장소·URL·목록·알림에 노출되지 않는다.
- 오프라인·오래된 캐시에서는 마지막 동기화 시각과 읽기 전용 사유를 표시하고, 선점·PIN·검수·지급 등 상태 변경을 잠근다.
- 재시도 뒤 최신 권한과 화면 상태를 함께 복구한다.

실행 결과 Browser console warning/error는 0건이었고, 소스에는 `localStorage`·`sessionStorage` 접근이 없습니다. PIN은 `runtimePins`와 30초 만료 `Map`에만 존재하며 URL·history payload·내보내기·알림에는 넣지 않습니다. Browser 제어 샌드박스가 Storage API 자체를 노출하지 않아 길이 값은 정적 무사용 검사로 대체했습니다.
