## 결과 요약

배정 대상일의 체크아웃 fixture 4건과 연박 청소 신청 fixture 1건이 청소대상 객실에 자동 포함되고, 기존 직접 등록 1건과 출처별로 구분되는지 확인했다. 객실 호수·타입·요금·특수 시각과 `가능` 메이드만 표시하는 기존 배정 규칙을 유지하면서, 관리자가 같은 메이드의 청소 순서를 연속된 1–N번으로 조정하고 저장·통보·이력·메이드 화면에서 같은 순서를 확인했다. `청소대상 직접 등록`에서 1208호 퇴실 청소를 추가하자 목록이 6건에서 7건으로 늘었으며 같은 객실·청소 유형의 재등록은 차단됐다.

예약 예정 시각을 기준으로 얼리 체크인·레이트 체크아웃을 자동 판정하도록 확장했다. 체크인 15:00은 얼리 1시간, 14:00은 얼리 2시간, 체크아웃 13:00은 레이트 2시간으로 표시됐고 정확히 16:00·11:00에서는 특수 상태가 제거됐다. 예약 저장 결과가 객실 카드·상세·필터와 청소 배정 일정에 동일하게 반영되는지 확인했다.

## 대표 업무 흐름

### 1. 객실 정보와 특수 입퇴실 시각

1. 시나리오 2, 관리자 `청소 → 전날 배정`, 2026-08-16 21:55에서 시작했다.
2. 초기 여섯 객실 모두 호수·타입·고정 청소 요금이 보이는지 확인했다.
3. 201호에서 `스탠다드 더블 로프트 · 18,000원 · 얼리 체크인 · 체크인 15:00`을 확인했다.
4. 202호에서 `프리미엄 더블 로프트 · 22,000원 · 레이트 체크아웃 · 체크아웃 13:00`을 확인했다.
5. 402호 직접 배정 대화상자에서도 호수·타입·청소 유형·요금·특수 일정 요약이 반복되는지 확인했다.

### 2. 청소대상 자동 구성과 직접 등록

1. 시나리오 2 첫 진입에서 201·202·302·402호가 `자동 · 내일 체크아웃`, 401호가 `자동 · 연박 청소 신청`으로 표시되는지 확인했다.
2. 401호는 `요청 완료 14:30 · 출입 허용 13:00–15:00`, 자동 체크아웃 객실은 `체크아웃 → 준비 마감` 일정이 보이는지 확인했다.
3. 412호 재청소는 `직접 등록`로 구분되고 요약이 `자동 5 · 직접 1`인지 확인했다.
4. `청소대상 직접 등록`에서 1208호·퇴실 청소를 추가하자 배정 행과 담당 드롭다운이 즉시 생성되고 요약이 `자동 5 · 직접 2`로 바뀌었다.
5. 같은 1208호·퇴실 청소를 다시 등록하자 대상 수는 7건을 유지하고 `이미 직접 등록된 청소대상` 안내와 대화상자를 유지했다.
6. 7개 담당 드롭다운 모두 `담당 선택 / 김민지1 (근무 가능) / 이서연 (근무 가능)`만 포함하고 김민지2·불가·미제출 선택지는 없었다.
7. 미배정 4건을 김민지1에게 배정하자 저장 버튼이 활성화되고, 저장 뒤 통보 완료 7건과 자동 포함·직접 등록 근거가 배정 이력에 남았다.

### 3. 근무 가능 메이드만 배정

1. 월요일 가능 현황은 김민지1 `가능`, 김민지2 `불가`, 이서연 `가능`이었다.
2. 초기 여섯 개와 직접 등록 후 일곱 개 담당 드롭다운에서 `담당 선택 / 김민지1 (근무 가능) / 이서연 (근무 가능)`만 확인했다.
3. `김민지2`, `불가`, `미제출` 문자열은 담당 선택지에 0건이었다.
4. 직접 등록 후 남은 네 작업을 김민지1에게 배정하자 저장 버튼이 활성화됐다.
5. 저장 뒤 담당 7건·미배정 0건·통보 완료 7건과 `자동 포함 / 직접 등록 · 근무 가능 제출 확인` 이력을 확인했다.

### 4. 메이드별 청소 순서 지정·통보

1. 초기 배정에서 김민지1의 201호는 `1번째 청소`, 이서연의 202·302호는 각각 `1번째 청소`, `2번째 청소`인지 확인했다.
2. 302호의 위 이동 버튼을 누르자 이서연 작업 안에서만 302호가 1번째, 202호가 2번째로 교환되고 두 행이 `저장 전`으로 바뀌었다.
3. 미배정 401·402·412호를 김민지1에게 지정한 뒤 202호도 이서연에서 김민지1로 변경했다. 김민지1은 201·401·402·412·202호가 1–5번째로 이어지고, 이서연에게 남은 302호는 1번째로 자동 정규화됐다.
4. 첫 작업의 위 이동과 마지막 작업의 아래 이동은 비활성이고, 중간 작업은 위·아래 이동이 모두 가능했다. 미배정 행에는 순번 대신 담당 선택 안내가 표시됐다.
5. `배정·순서 저장 및 통보` 후 6건 모두 통보 완료가 되고, 배정 이력에 202호 `이서연 · 1번째 → 김민지1 · 5번째`, 302호 `이서연 · 2번째 → 이서연 · 1번째`와 신규 담당 순번이 남았다.
6. 메이드 역할 `내 업무`에서 김민지1의 201·401·402·412·202호가 1–5번째 순으로 표시되고, 알림도 같은 순서로 정렬되는지 확인했다. 이서연의 302호와 관리자 전용 배정·순번 컨트롤은 노출되지 않았다.

### 5. 주간 근무 기록

1. 배정 상단 `주간 근무 기록`에서 `메이드 → 근무 기록`으로 이동했다.
2. 기본 선택인 2026-08-10–16에서 전체 3명의 가능 제출 15인일, 담당 통보 12인일, 실근무 완료 11인일을 확인했다.
3. 주차를 2026-08-03–09, 메이드를 김민지2로 바꾸자 인물 카드가 1개로 줄고 가능 5일·배정 4일·실근무 4일로 바뀌었다.
4. 각 날짜에서 `가능 제출`, `담당 통보`, `실근무 완료`가 독립 표식으로 보이며 가능 제출만 있는 날짜를 실근무로 세지 않는지 확인했다.
5. 현재 계획 주차와 과거 마감 기록을 같은 필터에서 전환할 수 있고, 화면에 서버 영속 저장이 아닌 데모 fixture임을 명시했다.

- 체크아웃·연박 신청 자동 구성, 직접 등록, 가능일 제출·담당·순번·통보·실근무 완료 기록은 현재 탭 메모리와 결정적 fixture다. 실제 예약 서버 영속 저장·동시성·불변 이벤트 원장이 아니다.
- `배정 통보 완료`는 앱 내부 화면 갱신 시뮬레이션이며 실제 푸시·SMS·전화 발송이 아니다.
- 실제 운영 데이터가 없어 객실·인명·단가·예상시간·특수 시각·과거 기록은 모두 데모 fixture다.
- 최종 서비스 전에는 가능일 제출 버전, 마감 스냅샷, 배정 이벤트, 실제 수행 회차를 불변 사용자 ID와 한국시간 기준으로 서버에 분리 저장해야 한다.
