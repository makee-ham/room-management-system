# CASTLE THE ART 객실관리 앱 클릭형 와이어프레임

모바일 현장 사용을 우선한 단일 파일 반응형 프로토타입입니다. 관리자는 객실·예약·청소 배정·폭탄방 검수·메이드·주급 기록을 운영하고, 메이드는 다음 주 근무 가능일을 제출한 뒤 관리자가 통보한 업무만 수행합니다.

현재 청소 운영 정책은 [주간 근무 가능일·관리자 전날 배정·폭탄방 2배 적립 정책](../DOCS/16_WEEKLY_AVAILABILITY_ASSIGNMENT_POLICY.md)이 정본입니다. 이 정책은 기존 문서의 일일 근무 등록, 공개 일감, 메이드 선점, 재공개 규칙과 폭탄방 요금 예외를 대체합니다. 타입별 청소 사진의 근거·원본 비반입·객실 레이아웃 보정은 [객실 타입별 청소 사진 템플릿 정책](../DOCS/18_TYPE_PHOTO_TEMPLATE_POLICY.md)을 따릅니다. 다른 정책은 [최종 UX 감사 원문](../DOCS/FINAL_UX_AUDIT.md)과 [제작 인계서](../DOCS/14_CLICKABLE_WIREFRAME_HANDOFF.md)를 따르며 최종 감사 원문은 수정하지 않습니다.

객실 호수·타입·엘리베이터 구역과 타입별 기본 청소요금은 사용자가 제공한 `객실현황(26.08)`의 `8월` 시트를 초기 정본으로 반영했습니다. 총 121개 객실이며 최초 타입별 22/51/13/35개, 엘리베이터 A/B/C 33/21/56개, 미기재 11개입니다. 호수는 현재 불변 내부키와 연결된 읽기 전용 값이고, 관리자는 객실 상세에서 타입과 엘리베이터 위치를 수정할 수 있습니다. 따라서 타입·엘리베이터 개수는 초기값을 하드코딩하지 않고 현재 기준정보에서 다시 계산합니다. 기본 청소요금은 `스탠다드 16,000원 / 프리미어 20,000원 / 파셜 오션뷰 20,000원 / 패밀리 투룸 30,000원`이며 임시값이 아닙니다.

점유는 체류 기간과 관계없이 `투숙 / 공실`만 사용합니다. `장기-결제` 시트의 활성 11실은 최초 `투숙` seed이고, 그 11실과 762호를 제외한 109실은 최초 `공실` seed입니다. 초기 109실은 별도 운영 fixture가 없는 경우 준비 완료 근거도 함께 seed해 `공실 · 고객 배정 가능`이 파생되지만 고정 마스터 상태로 저장하지 않습니다. 장기투숙 전용 상태·필터·집계·상세 패널은 없습니다. 762호는 제3 점유 상태가 아니라 별도 `확인 필요` 데이터 배지로 표시하고, 관리자가 실제 점유를 확인해 투숙 또는 공실로 확정할 때까지 고객 배정·청소 배정만 잠급니다. `고객 배정 가능`은 마스터 상태가 아니라 청소·운영·안전 조건을 모두 만족한 공실에서만 계산되는 결과입니다. 상세 기준은 [8월 객실 기준정보·점유 상태 결정](../DOCS/17_ROOM_CATALOG_LONG_STAY_DECISIONS.md)에 정리했습니다.

## 실행

빌드나 설치는 필요하지 않습니다. 저장소 루트에서 아래 명령을 실행하고 `http://127.0.0.1:4173/index.html`을 엽니다.

```bash
python3 scripts/serve.py
```

Windows에서는 `python scripts/serve.py`를 사용합니다. 외부 CDN, 프레임워크, 백엔드, 실제 계정을 사용하지 않습니다.

## 정보 구조

관리자 내비게이션은 `오늘 / 객실 / 청소 / 메이드 / 더보기`입니다.

- `오늘`: 객실 요약, 다음 날 배정 준비, 제출 인원, 긴급 사건
- `객실`: 투숙·공실 검색과 필터, 읽기 전용 호수·수정 가능한 타입/엘리베이터 기준정보, 예약, 예정 전 지금 체크아웃, 입실 준비, PIN, 운영 중지, 메이드 등록 특이사항·사진 조회
- `청소`: `전날 배정 / 진행 중 / 검수 대기 / 완료`. 전날 배정은 객실 타입·요금별 담당 선택과 메이드별 작업량·청소 순서 보드를 분리합니다. 8–10명 운영을 위해 미배정 객실의 출입·마감 가능성을 먼저 확인하고 예상시간·객실 수·엘리베이터를 비교하는 결정적 추천 초안을 제공합니다. 추천은 저장 전 상태이며 관리자가 수정·부분 통보할 수 있습니다. `메이드 주간 근무표`는 셀 너비를 줄이기 위해 `✓ / × / —`만 표시하고 표 아래 범례와 접근성 이름으로 상태 의미를 전달합니다. 검수에서는 폭탄방 이미지 증빙과 기본·추가·해당 객실 총액을 보고 인정 또는 미인정을 결정합니다.
- `메이드`: 다음 주 가능일 매트릭스, 주차별 근무 기록, 메이드별 업무·컴플레인과 주급 정산. 주급 카드의 `청소 내역 · 산출 보기`에서 주차·메이드별 객실 청소 원장과 폭탄방 요금을 확인합니다.
- `더보기`: 감사 이력, 4개 타입 × 퇴실·연박·재청소 템플릿 목록·상세·데모 편집, 계정·정본 단가 조회

메이드 내비게이션은 `내 업무 / 근무 일정 / 알림 / 주급 / 더보기`입니다.

- `근무 일정`: 일요일에 다음 주 월–일 가능일 제출, 마감 전 수정, 마감 뒤 변경 요청
- `내 업무`: 관리자 통보 완료 업무와 현재 주 행동, 객실 특이사항 메모·다중 이미지 등록, 전체 제출 전 폭탄방 이미지 신고
- `알림`: 신규 배정·변경·반려·PIN 변경 등 본인 운영 알림
- `주급`: 본인 예상·확정·지급 이력과 폭탄방 기본요금·추가요금·해당 객실 총액
- `더보기`: 본인 계정과 근무 상태

메이드에게 공개 객실 목록과 객실 선택·담당 확정 권한은 없습니다. 관리자 전용 화면과 상세는 역할 전환이나 URL 직접 진입에서도 차단합니다.

객실의 얼리 체크인·레이트 체크아웃은 별도 수동 상태가 아닙니다. 예정 체크인이 기본 16:00보다 이르거나 예정 체크아웃이 기본 11:00보다 늦을 때 실제 시각과 차이를 자동 계산하며, 예약 변경 결과를 객실 카드·상세·필터와 관리자 청소 배정 일정에 함께 반영합니다. 이미 메이드에게 통보한 일정은 변경 통보 전까지 기존 스냅샷을 유지하고, 관리자가 다시 저장·통보한 뒤 새 시각으로 바뀝니다.

## 객실 기준정보와 점유

관리자는 모든 객실 상세의 `기본정보 수정`에서 객실 타입과 엘리베이터 위치 `A / B / C / 미기재`를 바꿀 수 있습니다. 호수는 현재 내부키이므로 읽기 전용입니다. 저장하면 객실 목록·상세·청소대상·배정 추천과 현재 집계를 다시 계산하고 변경 전후·관리자·시각을 이력에 남깁니다. 타입 변경은 새 작업의 단가·템플릿에만 적용하고 이미 생성한 작업의 스냅샷은 유지합니다.

투숙 객실 상세에는 예정 체크아웃 전에도 실행할 수 있는 `지금 체크아웃`이 있습니다. 예정 체크아웃이 없는 초기 투숙도 `예정 체크아웃 없음`을 보여주고 같은 행동을 제공합니다. 성공하면 예정 체크아웃 시각은 그대로 보존하고 실제 체크아웃 시각·관리자를 별도 기록하며, 객실은 즉시 `공실 · 청소 필요`가 됩니다. 연결 퇴실 청소가 있으면 같은 작업을 갱신하고 없을 때만 한 건 생성하므로 재시도와 이후 예정 체크아웃 시각 도달로 중복 작업이 생기지 않습니다. 청소 승인·운영 정상·촛불 0·차단 없음까지 충족하기 전에는 `고객 배정 가능`으로 표시하지 않습니다. 체크인 전 예약을 없애는 행동은 `예약 취소`, 이미 시작한 투숙을 끝내는 행동은 `지금 체크아웃`으로 구분합니다.

체류 중 청소가 필요하면 모든 투숙 객실에서 같은 `투숙 중 청소 요청`을 만들고 기존 연박 청소 템플릿·전날 배정 흐름을 사용합니다. 장기투숙 여부나 별도 장기투숙 상세는 요구하지 않습니다.

## 간편 예약 원장

관리자 상단의 `간편 예약`은 121개 전체 객실을 세로, 선택한 달의 날짜를 가로로 둔 빠른 입력 화면입니다. 객실 고정 열에 호수·타입·엘리베이터·퇴실 청소 담당을 표시하고 날짜 헤더와 객실 열은 표 안에서 고정합니다. 노란 `1박`은 각각 별도 예약 ID이고, 이어진 파란 `연박 N박`은 한 예약 ID입니다. 바로 붙은 두 예약도 자동으로 합치지 않으므로 `1박 + 1박 + 연박`을 구분할 수 있습니다.

예약 정본은 객실별 단일 시각 필드가 아니라 안정적인 예약 ID를 가진 여러 `[체크인, 체크아웃)` 구간입니다. 간편 예약표와 객실 카드는 같은 메모리 원장을 다시 읽습니다. 어느 화면에서 접수·변경해도 두 화면에 즉시 반영되고, 이미 예약된 날짜는 새 예약을 만들 수 없습니다. 확인 보류·운영 중지·퇴실 미정 투숙 객실은 행 전체가 사유와 자물쇠로 잠깁니다. 청소·검수·촛불 미준비는 현재 고객 입실 판단에는 쓰지만 미래 예약 등록 자체를 막지는 않습니다.

마우스는 빈 날짜를 클릭하거나 같은 객실 행에서 가로로 드래그합니다. 키보드는 방향키로 셀을 이동하고 `Shift + 좌우 방향키`로 범위를 고른 뒤 `Enter` 또는 `Space`로 접수합니다. 터치는 오입력을 막기 위해 다음 안전 규칙을 사용합니다.

- 짧은 탭만으로는 새 예약을 만들지 않습니다.
- 0.35초 길게 눌러 `길게` 표시와 진동 피드백이 나온 뒤 같은 객실 행에서만 가로로 범위를 고릅니다.
- 길게 누르기 전 세로 이동은 선택을 취소하고 객실표 세로 스크롤로 처리합니다.
- 길게 누르기 전 가로 스와이프는 예약하지 않고 날짜표만 이동합니다.
- 다른 객실 행으로 넘어가면 전체 선택을 취소합니다.
- 손을 뗄 때 한 예약 ID로 접수하고 10초 동안 `실행 취소`할 수 있습니다.

예약 한 건을 접수하면 해당 체크아웃 날짜의 비공개 퇴실 청소 초안 한 건을 연결합니다. 담당 메이드를 임의로 자동 선택하지 않으며, 전날 배정에서 이미 정한 담당·통보 상태 또는 `청소 미배정`을 카드와 예약표에 같은 값으로 표시합니다. 예약·청소 초안·실행 취소는 현재 탭 메모리의 데모 상태이고 실제 OTA/PMS, 서버 저장, 동시 예약 잠금, 외부 알림은 연결하지 않았습니다.

## 타입별 청소 사진 템플릿

사용자 제공 `clean-template/`의 9객실·123장 참고 사진을 촬영 구역 문구로 정규화했습니다. 객실 번호는 파일명·폴더명·EXIF가 아니라 각 폴더의 첫 객실 표지 사진을 확인해 복원했으며, 참고 원본 파일·썸네일·로컬 경로·파일명은 앱과 저장소에 반입하지 않았습니다.

| 타입 | 정본 기본 청소요금 | 참고 객실 | 참고 사진 | 퇴실 청소 촬영 구역 |
|---|---:|---|---:|---:|
| 스탠다드 | 16,000원 | 750호 | 11장 | 필수 8 + 선택 1 |
| 프리미어 | 20,000원 | 651·540·455호 | 42장 | 필수 9 + 선택 1 |
| 파셜 오션뷰 | 20,000원 | 639·641·536호 | 42장 | 필수 11 + 선택 1 |
| 패밀리 투룸 | 30,000원 | 645·542호 | 28장 | 필수 9 + 선택 1 |

퇴실 청소는 타입 기본 촬영 구역을 먼저 적용하고, 침실·욕실·배수구처럼 객실마다 개수가 달라질 수 있는 구역은 실제 객실 레이아웃 수만큼 필수 슬롯을 반복하는 `타입 기본 + 객실 레이아웃 보정` 원칙을 사용합니다. `ROOM_LAYOUT_PROFILES`에는 사진으로 확인한 750·651·540·455·639·641·536·645·542호의 침실·욕실·배수구 수가 있고, 작업 생성 시 반복 규칙이 필수 슬롯으로 실제 펼쳐집니다. 나머지 112실은 `레이아웃 확인 보류`로 표시하고 최소 공통 슬롯만 적용합니다. 작업을 만들 때 타입·단가·예상시간·체크·사진 구역·레이아웃을 버전 스냅샷으로 고정하므로 이후 템플릿 변경은 기존 작업에 소급하지 않습니다. 관리자는 템플릿 목록·상세와 제출 당시 버전을 보고, 메이드는 본인에게 통보된 작업의 읽기 전용 촬영 구역만 봅니다.

원본 표지 사진 일부에는 운영 연락처가 있어 템플릿 자산으로 재사용하지 않습니다. 새 청소 사진도 연락처·얼굴·거울 반사·고객 물품·켜진 TV 화면을 제외해 촬영하도록 안내합니다. 현재 와이어프레임은 참고 객실·사진 수와 텍스트 촬영 규칙만 담고 실제 원본 예시 사진은 보여주지 않습니다.

현재 데모에는 4개 타입 × 퇴실·연박·재청소 12개 조합, 타입별 목록·상세, 예상시간·체크 필수 여부 편집, 작업·제출의 버전 스냅샷과 사진 확인 9객실의 레이아웃 반복 슬롯 생성이 있습니다. 나머지 112실의 확정 레이아웃 프로필, 촬영 구역 편집·게시 서버, 실제 이미지 업로드·분류·보존은 구현하지 않았습니다. 123장 표본을 직접 반영한 것은 퇴실 청소 촬영 구역과 9객실 레이아웃이며, 연박·재청소 규칙과 예상시간은 데모 fixture입니다. 타입별 기본 청소요금 16,000/20,000/20,000/30,000원은 시트 정본을 사용합니다.

## 청소 운영 흐름

일요일은 다음 주 가능일 제출·마감일이고, `내일 청소 배정`은 일요일에만 여는 기능이 아닙니다. 청소대상이 있는 매일 전날 다음 날 근무 가능자를 기준으로 반복합니다.

1. 일요일 오후–22:00에 메이드가 다음 주 가능일을 제출합니다.
2. 관리자는 전체 제출·미제출·변경 요청과 요일별 가능 인원을 확인합니다.
3. 시스템은 다음 날 예정 체크아웃 객실, 관리자가 `지금 체크아웃`한 객실, 다음 날 투숙 중 청소 신청 객실을 `청소대상 객실`에 자동 포함합니다. 같은 예약의 수동·예정 체크아웃은 활성 퇴실 청소 한 건을 공유합니다.
4. 관리자는 같은 화면의 `청소대상 직접 등록`에서 자동 대상 외 현장 요청을 추가할 수 있습니다. 검수 반려 재청소는 직접 등록하지 않고 최초 청소한 메이드에게 자동 귀속합니다. 같은 객실·청소 유형의 중복 등록은 차단됩니다.
5. 근무일 전날 밤, 관리자는 `전체` 또는 네 객실 타입별로 대상 수와 객실당 고정 청소 요금을 비교합니다. 타입 필터는 표시만 좁히고 숨은 객실도 전체 대상·미배정 현황과 부분 통보 판단에 유지합니다.
6. 자동 포함·직접 등록된 청소대상 중 담당 가능한 객실의 메이드를 직접 선택합니다. 각 행은 객실 호수·타입·청소 요금과 `자동 · 예정 체크아웃 / 자동 · 수동 체크아웃 / 자동 · 투숙 중 청소 신청 / 직접 등록` 근거를 함께 표시합니다.
7. 담당 목록에는 해당 날짜를 `근무 가능`으로 제출한 메이드만 표시되고, `근무 불가`·`미제출` 메이드는 선택할 수 없습니다.
8. 예약 시각에서 자동 판정된 얼리 체크인·레이트 체크아웃과 실제 체크인·체크아웃 시각·기준 대비 차이를 객실 행에서 확인합니다.
9. 미배정 객실이 많으면 `추천 배정`으로 근무 가능·활성 메이드만 대상으로 한 저장 전 초안을 만듭니다. 추천은 기존 통보와 수동 배정을 보존하고, 출입 가능 시각 이후부터 준비 마감 전까지 완료할 수 있는 객실만 예상시간·객실 수·엘리베이터 기준으로 나눕니다. 마감을 지킬 수 없는 객실은 억지로 배정하지 않습니다.
10. `메이드별 작업량·동선 비교`에서 근무 가능자별 객실 수·예상시간·청소비·A/B/C/미기재 엘리베이터·네 타입 구성을 한 줄씩 비교합니다. 실제 청소 순서는 필요한 메이드만 펼쳐 `1번째`부터 위·아래로 수정합니다.
11. 추천은 메이드에게 통보되지 않으며 담당 드롭다운이 최종 결정권을 가집니다. 추천 뒤 수동 편집을 시작하면 추천 되돌리기를 폐기하고, 같은 입력의 추천은 고정 ID 동점 처리로 항상 같은 결과를 냅니다. 예상시간은 데모이고 실제 이동시간·난이도는 반영하지 않습니다.
12. 보드는 네 타입의 0건도 숨기지 않고 타입 필터와 관계없이 전체 배정 객실을 기준으로 집계합니다. 미배정 객실은 누구의 타입 개수에도 포함하지 않고 순서 없는 별도 영역에 표시합니다.
13. 모든 객실을 다 배정하지 못해도 담당 메이드와 연속된 청소 순서가 정해진 객실이 한 건 이상이면 `배정된 객실만 저장·통보`할 수 있습니다. 미배정 객실은 대기 상태로 남고 후속 배정 때 추가 통보합니다.
14. 부분 저장 뒤 해당 메이드의 `내 업무`와 `알림`은 이번에 확정된 객실을 지정 순서대로 반영합니다. 관리자 이력에는 이번·누적 통보 수, 남은 미배정 수, 이전·새 담당과 순서·시각·사유가 남습니다.
15. 가능일 제출·배정·순서 통보·실제 청소 완료일은 서로 다른 주간 기록으로 보존합니다. 관리자는 `메이드 → 근무 기록`에서 월요일–일요일 주차를 달력으로 선택하고 사람별로 조회하며, 요약은 `메이드 N명`과 `메이드별 날짜 합계 N일`을 분리해 표시합니다.
16. 메이드는 시작 가능 시각 뒤 PIN을 확인하고 `일 시작 → 체크·청소 사진·객실 특이사항·촛불 → 현장 완료 → 업로드 재시도 → 전체 제출`을 진행합니다. 객실 특이사항은 업무 메모나 이미지 중 하나만으로도 등록할 수 있고, 여러 이미지를 한 번에 선택한 뒤 저장 전에 한 장씩 제거할 수 있습니다.
17. 저장한 객실 특이사항에는 등록자·시각·유형·메모·이미지 수가 남고 관리자 객실 상세·검수 흐름에서 같은 이미지 갤러리를 확대 조회합니다. 메이드는 본인 담당 청소 중 객실에서만 등록할 수 있습니다.
18. 메이드는 본인 담당 객실이 통상 범위를 크게 넘게 지저분하면 청소 시작 전부터 업로드 단계까지, 전체 제출 전에 이미지 1장 이상을 첨부해 폭탄방으로 신고합니다. 여러 이미지를 선택할 수 있고 메모는 선택 사항입니다.
19. 전체 제출 뒤 폭탄방 증빙은 해당 제출 버전에 잠깁니다. 관리자는 이미지·메모와 기본·추가·총액을 확인해 `폭탄방 인정` 또는 `폭탄방 미인정`을 먼저 결정합니다.
20. 폭탄방 인정 뒤 전체 청소까지 승인되면 주간 전체가 아니라 **해당 객실의 기본 청소요금만 정확히 2배**로 적립됩니다. 화면과 원장은 `기본 청소요금 + 같은 금액의 폭탄방 추가요금 = 해당 객실 총액 2배`로 표시합니다.
    - 전체 청소 반려로 생긴 재청소는 최초 청소한 메이드 본인에게 자동 귀속하며 타 메이드에게 이관·재배정하지 않습니다. 재청소는 무급 0원이고 폭탄방 신고·추가요금·폭탄방 수익 원장을 새로 만들지 않습니다.
21. 폭탄방 미인정 뒤 전체 청소가 승인되면 기본 청소요금만 적립합니다. 전체 청소가 반려되면 적립하지 않고 신고·이미지·관리자 결정과 사유를 제출·재청소 이력에 보존합니다.
22. 관리자와 해당 메이드는 청소 상세·검수 결과·완료 내역·주급 내역에서 같은 폭탄방 상태와 기본·추가·총액을 확인합니다. 같은 제출을 다시 승인해도 수익 원장은 한 번만 생성됩니다.
23. 관리자는 전체 제출을 승인 또는 반려합니다. 반려 재청소에는 별도 담당 선택을 제공하지 않고 최초 청소한 본인에게 자동 귀속한 `재청소 · 무급 0원` 상태를 통보합니다.

동시에 진행할 수 있는 청소는 한 건입니다. PIN 원문은 한 객실만 최대 30초 메모리에 유지하며 역할·화면 이동과 창 비활성화 때 다시 가립니다.

## 관리자 주급 산출 원장

관리자는 `메이드 → 주급 정산`에서 월요일–일요일 조회 주차를 선택한 뒤 메이드별 카드의 `청소 내역 N건 · 산출 보기`를 열 수 있습니다. 상세 원장은 각 청소의 완료일·객실·객실 타입·청소 종류·당시 기본 청소요금·폭탄방 추가요금·해당 객실 총액·검수 및 정산 상태를 표시하고, 확정 포함 행의 합계를 카드의 확정 주급과 대조합니다.

같은 화면의 모든 메이드 카드에는 주차·메이드별 독립 지급 스위치가 있습니다. 첫 확인에서 `PAYING`으로 전환해 금액·수익 ID를 잠그고, 외부 전액 송금 뒤 같은 스위치에서 `PAID` 완료를 기록합니다. 송금 결과가 불명확하면 `CHECK`로 잠가 두고, 송금하지 않은 것이 확인된 경우에만 필수 사유를 남겨 `OPEN`으로 복귀합니다. 이때 이전 지급 시도의 잠근 금액·수익 ID·관리자·사유는 감사 스냅샷으로 보존합니다. `PAID` 완료 기록은 직접 취소하지 않고 이후 차이를 정정·상계합니다. 다른 메이드와 다른 주차는 바뀌지 않으며, 확정액 0원과 아직 마감되지 않은 주차는 스위치 자리를 유지한 채 각각 `지급 대상 없음`, `주차 마감 전` 이유로 잠깁니다. 이 앱은 실제 송금을 실행하지 않습니다.

지급 진행 뒤 객실 원장이 바뀌더라도 카드와 메이드 지급 내역은 당시 잠근 지급액을 유지합니다. 현재 객실 원장 금액은 따로 표시하고 차이는 지급 완료 기록을 덮어쓰지 않은 채 정정·상계 대상으로 구분합니다.

- 객실 타입과 기본 청소요금은 8월 시트 정본인 `스탠다드 16,000원 / 프리미어 20,000원 / 파셜 오션뷰 20,000원 / 패밀리 투룸 30,000원`을 사용합니다.
- 검수 대기는 `승인 시` 예상액으로 따로 표시하며 확정 주급과 지급액에 포함하지 않습니다.
- 청소 전체 반려와 처음 청소한 본인의 무급 재청소는 상세 이력에 `0원 · 주급 합계 제외`로 남고 새 수익 원장을 만들지 않습니다.
- 데모 과거 주차인 2026년 8월 3일–9일 김민지1은 승인 청소 6건 합계 **138,000원**입니다. 536호 폭탄방 한 건만 `기본 20,000원 + 추가 20,000원 = 40,000원`이고, 나머지 다섯 객실은 `20,000원 + 30,000원 + 16,000원 + 16,000원 + 16,000원 = 98,000원`이므로 주차 합계는 138,000원입니다.
- 위 인명·예약·과거 주급 내역은 기능 확인용 데모 fixture이며, 실제 지급이나 송금 기록이 아닙니다.

## 대표 데모 시나리오

상단 `데모 제어`에서 역할·시각·네트워크·시나리오를 바꾸고 초기화할 수 있습니다.

1. 메이드: 일요일 다음 주 근무 가능일 제출
2. 관리자: 예정 체크아웃·수동 체크아웃·투숙 중 청소 신청 자동 대상 확인 → 객실 타입별 대상 수·요금 비교 → 현장 요청 직접 등록·중복 차단 → 객실·타입·요금·특수 시각 확인 → 근무 가능·활성 메이드 추천 초안 또는 수동 배정 → 메이드별 예상시간·객실 수·청소비·엘리베이터 비교 → 필요한 순서만 펼쳐 수정 → 부분 통보 · 미배정 대기
3. 메이드: 지정 순서대로 통보된 내 업무 → 시간 게이트 → PIN → 청소 시작
4. 체크·청소 사진 → 객실 특이사항 메모·여러 이미지 등록 → 폭탄방 이미지 1장 이상 신고 → 현장 완료 → 업로드 실패·재시도 → 전체 제출

## 데모 데이터와 경계

객실 호수·객실 유형·엘리베이터 구역의 최초 값과 타입별 기본 청소요금 16,000/20,000/20,000/30,000원은 2026년 8월 객실현황 시트 정본입니다. 호수는 읽기 전용이고 타입·엘리베이터는 관리자 수정값을 현재 정본으로 사용합니다. `장기-결제` 시트의 활성 11실은 최초 투숙 seed일 뿐이며 고객명·회사명·시작일·결제 메모와 장기투숙 구분은 앱·내보내기에 반입하지 않습니다. 정상 점유는 투숙/공실, 762호는 확인 필요 데이터 배지, 고객 배정 가능은 준비된 공실의 파생 결과입니다. 인명·예상시간·예약·청소 상태·사진·폭탄방 승인·과거 근무·주급 기록은 실제 운영 데이터가 아닌 결정적 fixture이며 화면 상태는 브라우저 메모리에서만 시뮬레이션됩니다.

- 실제 서버 저장, 다중 사용자 동시성, 도어락 발급, 폭탄방을 포함한 사진 전송·영속 보관, 자동 지급·송금, 푸시·SMS·전화는 연결하지 않습니다.
- `localStorage`와 `sessionStorage`를 사용하지 않습니다.
- PIN·고객명·사진 원문을 URL, 알림, 로그, 브라우저 영속 저장소에 남기지 않습니다.
- 사용자가 선택한 객실 특이사항 이미지는 현재 탭의 메모리 `blob:` 미리보기로만 유지되며 초기화·시나리오 교체 또는 탭 종료 뒤 복원되지 않습니다. 파일명은 화면 상태와 이력에 저장하지 않습니다.
- 사용자가 선택한 폭탄방 이미지도 현재 탭 메모리에서만 미리보고, 과거 승인 건은 기능 확인용 이미지 fixture로 표시합니다. 화면의 2배 금액은 실제 자동 지급 결과가 아니라 결정적 원장 시뮬레이션입니다.
- `clean-template/` 참고 원본 123장은 앱·저장소에 복사하지 않았습니다. 타입별 참고 객실·사진 수와 촬영 구역 문구만 fixture로 사용하며, 표지 사진의 운영 연락처 등 개인정보성 정보는 화면에 옮기지 않습니다.
- 타입별 사진 템플릿은 사진 확인 9객실에서 침실·욕실·배수구 수만큼 필수 슬롯을 정확히 확장합니다. 나머지 112실은 최소 공통 슬롯만 생성하고 `레이아웃 확인 보류`를 노출합니다. 이 객실들의 확정 레이아웃 마스터, 실제 파일 업로드·자동분류·서버 버전 게시·영속 보존은 구현하지 않았습니다.
- 실제 서비스에는 서버 권한 검사, 감사 로그, 알림 발송, 업로드 재개, 동시 배정 충돌 처리가 필요합니다.
