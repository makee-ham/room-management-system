# CASTLE THE ART 객실관리 앱 클릭형 와이어프레임

모바일 현장 사용을 우선한 단일 파일 반응형 프로토타입입니다. 관리자는 객실·예약·청소 배정·검수·메이드·주급 기록을 운영하고, 메이드는 다음 주 근무 가능일을 제출한 뒤 관리자가 통보한 업무만 수행합니다.

현재 청소 운영 정책은 [주간 근무 가능일·관리자 전날 배정 정책](../DOCS/16_WEEKLY_AVAILABILITY_ASSIGNMENT_POLICY.md)이 정본입니다. 이 정책은 기존 문서의 일일 근무 등록, 공개 일감, 메이드 선점, 재공개 규칙을 대체합니다. 다른 정책은 [최종 UX 감사 원문](../DOCS/FINAL_UX_AUDIT.md)과 [제작 인계서](../DOCS/14_CLICKABLE_WIREFRAME_HANDOFF.md)를 따르며 최종 감사 원문은 수정하지 않습니다.

## 실행

빌드나 설치는 필요하지 않습니다. 저장소 루트에서 아래 명령을 실행하고 `http://127.0.0.1:4173/index.html`을 엽니다.

```bash
python3 scripts/serve.py
```

Windows에서는 `python scripts/serve.py`를 사용합니다. 외부 CDN, 프레임워크, 백엔드, 실제 계정을 사용하지 않습니다.

## 정보 구조

관리자 내비게이션은 `오늘 / 객실 / 청소 / 메이드 / 더보기`입니다.

- `오늘`: 객실 요약, 다음 날 배정 준비, 제출 인원, 긴급 사건
- `객실`: 검색·필터, 예약, 입실 준비, PIN, 운영 중지
- `청소`: `전날 배정 / 진행 중 / 검수 대기 / 완료`
- `메이드`: 다음 주 가능일 매트릭스, 주차별 근무 기록, 메이드별 업무·주급·컴플레인
- `더보기`: 감사 이력, 데모 청소 템플릿, 계정·단가 설정

메이드 내비게이션은 `내 업무 / 근무 일정 / 알림 / 주급 / 더보기`입니다.

- `근무 일정`: 일요일에 다음 주 월–일 가능일 제출, 마감 전 수정, 마감 뒤 변경 요청
- `내 업무`: 관리자 통보 완료 업무와 현재 주 행동
- `알림`: 신규 배정·변경·반려·PIN 변경 등 본인 운영 알림
- `주급`: 본인 예상·확정·지급 이력
- `더보기`: 본인 계정과 근무 상태

메이드에게 공개 객실 목록과 객실 선택·담당 확정 권한은 없습니다. 관리자 전용 화면과 상세는 역할 전환이나 URL 직접 진입에서도 차단합니다.

## 청소 운영 흐름

1. 일요일 오후–22:00에 메이드가 다음 주 가능일을 제출합니다.
2. 관리자는 전체 제출·미제출·변경 요청과 요일별 가능 인원을 확인합니다.
3. 근무일 전날 밤, 관리자가 다음 날 청소 대상 모든 객실의 담당을 직접 선택합니다.
4. 담당 목록에는 해당 날짜를 `근무 가능`으로 제출한 메이드만 표시되고, `근무 불가`·`미제출` 메이드는 선택할 수 없습니다.
5. 각 객실 행에서 객실 호수·타입·청소 요금을 확인하고, 얼리 체크인·레이트 체크아웃이 있으면 조정된 체크인·체크아웃 시각도 함께 확인합니다.
6. 모든 객실에 근무 가능 메이드가 배정되어야 `배정 저장·메이드 통보`가 활성화됩니다.
7. 저장 뒤 해당 메이드의 `내 업무`와 `알림`이 갱신되고, 이전 담당·새 담당·시각·사유가 이력에 남습니다.
8. 가능일 제출·배정 통보·실제 청소 완료일은 서로 다른 주간 기록으로 보존하고, 관리자가 `메이드 → 근무 기록`에서 주차·사람별로 조회합니다.
9. 메이드는 시작 가능 시각 뒤 PIN을 확인하고 `일 시작 → 체크·사진·메모·촛불 → 현장 완료 → 업로드 재시도 → 전체 제출`을 진행합니다.
10. 관리자는 전체 제출을 승인 또는 반려합니다. 담당 취소 승인과 다른 메이드 재청소도 공개 목록 없이 관리자가 직접 재배정합니다.

동시에 진행할 수 있는 청소는 한 건입니다. PIN 원문은 한 객실만 최대 30초 메모리에 유지하며 역할·화면 이동과 창 비활성화 때 다시 가립니다.

## 대표 데모 시나리오

상단 `데모 제어`에서 역할·시각·네트워크·시나리오를 바꾸고 초기화할 수 있습니다.

1. 메이드: 일요일 다음 주 근무 가능일 제출
2. 관리자: 제출 현황 확인 → 객실·타입·요금·특수 시각 확인 → `가능` 메이드만 다음 날 객실별 직접 배정 → 통보
3. 메이드: 통보된 내 업무 → 시간 게이트 → PIN → 청소 시작
4. 체크·사진 → 현장 완료 → 업로드 실패·재시도 → 전체 제출
5. 관리자 전체 검수 → 승인 또는 반려·직접 재배정
6. 레이트 체크아웃과 청소·PIN 충돌 해결
7. 메이드 담당 취소 요청 → 관리자 유지·직접 재배정·보류 결정
8. 활성 예약의 연박 청소 작업 생성 → 전날 관리자 배정
9. 메이드 비활성 → 진행 업무 인계·미시작 업무 관리자 재배정
10. 지난주 지급 완료 기록과 실행 취소
11. 컴플레인·벌점 판정·이의·정정·소프트 삭제
12. 모달 → 상세 → 목록 뒤로가기와 날짜·필터·스크롤 복원
13. 로딩·진짜 0건·필터 0건·오래된 캐시·재시도
14. 관리자: 메이드 근무 기록 → 주차·메이드 필터 → 가능 제출일·배정 통보일·실근무 완료일 비교

## 데모 데이터와 경계

객실 번호·객실 유형·인명·단가·예상시간·사진·과거 근무 기록은 실제 운영 데이터가 아닌 결정적 fixture입니다. 화면 상태는 브라우저 메모리에서만 시뮬레이션됩니다.

- 실제 서버 저장, 다중 사용자 동시성, 도어락 발급, 사진 전송, 송금, 푸시·SMS·전화는 연결하지 않습니다.
- `localStorage`와 `sessionStorage`를 사용하지 않습니다.
- PIN·고객명·사진 원문을 URL, 알림, 로그, 브라우저 영속 저장소에 남기지 않습니다.
- 실제 서비스에는 서버 권한 검사, 감사 로그, 알림 발송, 업로드 재개, 동시 배정 충돌 처리가 필요합니다.
