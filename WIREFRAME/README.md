# CASTLE THE ART 객실관리 앱 클릭형 와이어프레임

모바일 현장 사용을 우선한 단일 파일 반응형 프로토타입입니다. 관리자는 객실·예약·청소 배정·폭탄방 검수·메이드·주급 기록을 운영하고, 메이드는 다음 주 근무 가능일을 제출한 뒤 관리자가 통보한 업무만 수행합니다.

현재 청소 운영 정책은 [주간 근무 가능일·관리자 전날 배정·폭탄방 2배 적립 정책](../DOCS/16_WEEKLY_AVAILABILITY_ASSIGNMENT_POLICY.md)이 정본입니다. 이 정책은 기존 문서의 일일 근무 등록, 공개 일감, 메이드 선점, 재공개 규칙과 폭탄방 요금 예외를 대체합니다. 객실 기준정보·점유·카드 주 상태·수동 체크아웃은 [8월 객실 기준정보·점유 상태 결정](../DOCS/17_ROOM_CATALOG_LONG_STAY_DECISIONS.md), 타입별 청소 사진의 근거·원본 비반입·객실 레이아웃 보정은 [객실 타입별 청소 사진 템플릿 정책](../DOCS/18_TYPE_PHOTO_TEMPLATE_POLICY.md)을 따릅니다. 다른 정책은 [최종 UX 감사 원문](../DOCS/FINAL_UX_AUDIT.md)과 [제작 인계서](../DOCS/14_CLICKABLE_WIREFRAME_HANDOFF.md)를 따르며 최종 감사 원문은 수정하지 않습니다.

객실 호수·타입과 타입별 기본 청소요금은 사용자가 제공한 `객실현황(26.08)`의 `8월` 시트를 초기 정본으로 반영했습니다. 엘리베이터는 시트 값을 유지하되 2026-08-18 제공 건물 지도로 미기재 11실을 보완했습니다. 총 121개 객실이며 최초 타입별 22/51/13/35개, 엘리베이터 A/B/C 33/29/59개, 미기재 0개입니다. 지도상 15번과 43번 사이의 끊긴 구간은 연결 동선으로 계산하지 않습니다. 호수는 현재 불변 내부키와 연결된 읽기 전용 값이고, 관리자는 객실 상세에서 타입과 엘리베이터 위치를 수정할 수 있습니다. 따라서 타입·엘리베이터 개수는 초기값을 하드코딩하지 않고 현재 기준정보에서 다시 계산합니다. 기본 청소요금은 `스탠다드 16,000원 / 프리미어 20,000원 / 파셜 오션뷰 20,000원 / 패밀리 투룸 30,000원`이며 임시값이 아닙니다.

점유는 체류 기간과 관계없이 `투숙 / 공실`만 사용합니다. `장기-결제` 시트의 활성 11실은 최초 `투숙` seed이고, 그 11실과 762호를 제외한 109실은 최초 `공실` seed입니다. 초기 109실은 별도 운영 fixture가 없는 경우 준비 완료 근거도 함께 seed해 점유 `공실`과 카드 주 상태 `배정 가능`이 파생되지만 고정 마스터 상태로 저장하지 않습니다. 장기투숙 전용 상태·필터·집계·상세 패널은 없습니다. 762호는 제3 점유 상태가 아니라 별도 `확인 필요` 데이터 배지로 표시하고, 관리자가 실제 점유를 확인해 투숙 또는 공실로 확정할 때까지 고객 배정·청소 배정만 잠급니다. `배정 가능`은 마스터 상태가 아니라 청소·운영·안전 조건을 모두 만족한 공실에서만 계산되는 카드 주 상태입니다. 상세 기준은 [8월 객실 기준정보·점유 상태 결정](../DOCS/17_ROOM_CATALOG_LONG_STAY_DECISIONS.md)에 정리했습니다.

## 객실 카드 주 상태

객실 카드의 주 상태는 `투숙 중(회색) / 청소 필요(주황) / 배정 가능(초록) / 배정 불가(빨강)` 네 가지 중 하나만 사용합니다. 조건이 겹치면 `배정 불가 → 청소 필요 → 투숙 중 → 배정 가능` 순서로 고릅니다. 청소 미완료는 빨강 배정 불가가 아니라 주황 청소 필요이고, `배정 가능 / 배정 불가`는 고객에게 객실을 배정할 수 있는지를 뜻하며 청소 담당자의 미배정·통보 상태와 다릅니다.

촛불, 입실 차단 특이사항, 운영 중지, 정보 확인 필요 등 기존 상세 분류는 삭제하지 않고 주 상태 아래 상태명·아이콘·이유로 표시합니다. `청소 미배정`, `청소 중`, `현장 완료·업로드 대기`, `검수 대기`, `재청소` 같은 청소 진행 단계는 주 상태보다 덜 중요한 서브 배지로 유지합니다. 얼리 체크인·레이트 체크아웃은 조정된 실제 예정 시각과 차이를 함께 보여주는, 청소 진행 서브 배지보다 눈에 잘 띄는 일정 배지입니다. 얼리·레이트 배지 자체는 카드 주 상태나 색을 바꾸지 않습니다.

## 실행

빌드나 설치는 필요하지 않습니다. 저장소 루트에서 아래 명령을 실행하고 `http://127.0.0.1:4173/index.html`을 엽니다.

```bash
python3 scripts/serve.py
```

Windows에서는 `python scripts/serve.py`를 사용합니다. 외부 CDN, 프레임워크, 백엔드, 실제 계정을 사용하지 않습니다.

## 정보 구조

관리자 내비게이션은 `오늘 / 객실 / 간편 예약 / 청소 / 메이드 / 더보기`입니다.

관리자와 메이드 기본 화면에는 현재 상태·금액·이유·다음 행동만 우선 표시합니다. 조작 순서나 계산 기준처럼 필요할 때만 보는 설명은 제목 옆 44×44px `ⓘ` 도움말에서 확인하며, 도움말은 클릭·Enter·Space로 열고 Escape 또는 바깥 클릭으로 닫습니다. 데이터 잠금, 실제 송금 미연결, 개인정보 금지처럼 행동 전 반드시 알아야 하는 경고는 도움말 안에 숨기지 않습니다.

- `오늘`: 데모 운영 기준일의 오늘·이번 주 청소비 예상 지출, 객실 요약, 다음 날 배정 준비, 제출 인원, 긴급 사건. 청소비는 주급 원장의 확정액과 검수 통과 시 더해질 최대 대기액을 분리하고, 카드 전체를 누르면 같은 주차의 `메이드 → 주급 정산`으로 이동합니다. 날짜 탐색 중에도 비용 카드는 운영 기준일 `8월 15일`과 현재 주차 `8월 10일–16일`을 유지해 과거·미래 객실판을 현재 지출처럼 오인하지 않게 합니다.
- `객실`: 투숙·공실 검색과 필터, `투숙 중 / 청소 필요 / 배정 가능 / 배정 불가` 카드 주 상태, 읽기 전용 호수·수정 가능한 타입/엘리베이터 기준정보, 예약, 예정 전 지금 체크아웃, 입실 준비 근거·의무, PIN, 운영 중지, 메이드 등록 특이사항·사진 조회
- `간편 예약`: 객실별 날짜표에서 한 고객의 체크인부터 체크아웃까지를 한 번에 선택해 등록·수정
- `청소`: `전날 배정 / 진행 중 / 검수 대기 / 완료`. 전날 배정은 `메이드 주간 근무표 → 동선 고려 랜덤 배정 초안 → 객실별 담당 수정 → 메이드별 1–N 순서 수정 → 저장·통보` 순서입니다. 랜덤 초안은 총 청소요금 균형을 1순위로 맞추고, 금액 점수가 같은 후보에서 같은 엘리베이터 구역과 가까운 호수를 2순위로 고려합니다. 실제 이동시간 최적화는 아니며, 기존 통보·관리자 수동 배정은 보존합니다. 사전 조건부터 관리자 최종 수정까지의 상세 기준은 제목 옆 툴팁 하나에 묶고 반복 칩 줄은 표시하지 않습니다. 관리자는 초안 뒤 필요한 담당과 순서만 고쳐 부분 통보할 수 있고 별도 작업량·동선 비교판은 제공하지 않습니다. 근무표 셀은 `✓ / × / —`만 표시하고 표 아래 범례와 접근성 이름으로 상태 의미를 전달합니다. 검수에서는 폭탄방 이미지 증빙과 기본·추가·해당 객실 총액을 보고 인정 또는 미인정을 결정합니다.
- `메이드`: 다음 주 가능일 매트릭스, 주차별 근무 기록, 메이드별 업무·컴플레인과 주급 정산. 주급 카드의 `청소 내역 · 상세 보기`에서 주차·메이드별 객실 청소 내역과 폭탄방 요금을 확인합니다.
- `더보기`: 감사 이력, 4개 타입 × 퇴실·연박·재청소 템플릿 목록·상세·데모 편집, 계정·정본 단가 조회

메이드 내비게이션은 `내 업무 / 근무 일정 / 알림 / 주급 / 더보기`입니다.

메이드 화면도 같은 간소화 원칙을 사용합니다. 근무 가능일 제출, 통보된 업무 확인, 월–일 주급 계산, 구역별 촬영 방법은 필요한 위치의 `ⓘ`에서 확인하고, 실제 업무 화면에는 객실·순서·시작 시각·진행 상태·필수 체크·필수 사진·금액·다음 버튼을 우선 표시합니다. 시나리오 단계, 버전, 내부 연결 ID, 서버·브라우저 저장 방식 같은 구현 설명은 메이드 화면에 표시하지 않습니다.

- `근무 일정`: 일요일에 다음 주 월–일 가능일 제출, 마감 전 수정, 마감 뒤 변경 요청
- `내 업무`: 관리자 통보 완료 업무와 현재 주 행동, 구역별 체크·즉시 카메라/갤러리 촬영, 객실 특이사항 메모·다중 이미지 등록, 전체 제출 전 폭탄방 이미지 신고
- `알림`: 신규 배정·변경·반려·PIN 변경 등 본인 운영 알림
- `주급`: 본인 예상·확정·지급 이력과 폭탄방 기본요금·추가요금·해당 객실 총액
- `더보기`: 본인 계정과 근무 상태

메이드에게 공개 객실 목록과 객실 선택·담당 확정 권한은 없습니다. 관리자 전용 화면과 상세는 역할 전환이나 URL 직접 진입에서도 차단합니다.

객실의 얼리 체크인·레이트 체크아웃은 별도 수동 상태가 아닙니다. 예정 체크인이 기본 16:00보다 이르거나 예정 체크아웃이 기본 11:00보다 늦을 때 실제 시각과 차이를 자동 계산하며, 예약 변경 결과를 객실 카드·상세·필터와 관리자 청소 배정 일정에 함께 반영합니다. 이미 메이드에게 통보한 일정은 변경 통보 전까지 기존 스냅샷을 유지하고, 관리자가 다시 저장·통보한 뒤 새 시각으로 바뀝니다.

한 고객의 예약 등록·수정은 항상 `체크인 → 체크아웃` 순서이며 두 시각을 같은 예약 ID로 저장합니다. 체크아웃은 체크인보다 뒤인 최소 1박이어야 하고 실제 시각이 기존 예약과 겹치면 저장하지 않습니다. 이전 고객의 체크아웃과 다음 고객의 체크인은 한 예약 폼에 섞지 않으며, 객실 준비 일정에서만 서로 다른 예약임을 밝힌 `이전 예약 체크아웃 → 준비 마감 → 다음 예약 체크인`으로 표시합니다. 다음 예약 체크인 변경·취소가 직전 예약의 퇴실 청소 마감에 영향을 주면 기존 담당 스냅샷은 보존하고 재통보 대상으로 전환합니다.

객실 카드, 관리자 청소 배정 행, 메이드별 청소 순서 수정 보드에서 얼리·레이트는 조정된 예정 시각과 기준 대비 차이를 함께 담은, 청소 진행 서브 배지보다 눈에 잘 띄는 일정 배지로 보여줍니다.

유효한 2박 이상 예약의 실제 투숙 기간에는 객실 카드에 현재 일차와 전체 일차를 `연박 2/4일차` 형식의 일정 강조 배지로 표시합니다. 이 연박 진행도는 별도 주 상태·필터·집계가 아니고 카드 주 상태나 색을 바꾸지 않습니다. 장기투숙 seed처럼 전체 숙박일 근거가 없으면 일차를 추정하거나 배지를 만들지 않습니다.

## 객실 기준정보와 점유

관리자는 모든 객실 상세의 `기본정보 수정`에서 객실 타입과 엘리베이터 위치 `A / B / C / 미기재`를 바꿀 수 있습니다. 호수는 현재 내부키이므로 읽기 전용입니다. 저장하면 객실 목록·상세·청소대상·랜덤 배정 초안과 현재 집계를 다시 계산하고 변경 전후·관리자·시각을 이력에 남깁니다. 타입 변경은 새 작업의 단가·템플릿에만 적용하고 이미 생성한 작업의 스냅샷은 유지합니다.

투숙 객실 상세에는 예정 체크아웃 전에도 실행할 수 있는 `지금 체크아웃`이 있습니다. 예정 체크아웃이 없는 초기 투숙도 `예정 체크아웃 없음`을 보여주고 같은 행동을 제공합니다. 성공하면 예정 체크아웃 시각은 그대로 보존하고 실제 체크아웃 시각·관리자를 별도 기록하며, 점유는 즉시 `공실`, 카드 주 상태는 `청소 필요`가 됩니다. 연결 퇴실 청소가 있으면 같은 작업을 갱신하고 없을 때만 한 건 생성하므로 재시도와 이후 예정 체크아웃 시각 도달로 중복 작업이 생기지 않습니다. 청소 승인·운영 정상·촛불 0·차단 없음까지 충족하기 전에는 `배정 가능`으로 표시하지 않습니다. 체크인 전 예약을 없애는 행동은 `예약 취소`, 이미 시작한 투숙을 끝내는 행동은 `지금 체크아웃`으로 구분합니다.

체류 중 청소가 필요하면 모든 투숙 객실에서 같은 `투숙 중 청소 요청`을 만들고 기존 연박 청소 템플릿·전날 배정 흐름을 사용합니다. 장기투숙 여부나 별도 장기투숙 상세는 요구하지 않습니다.

수동 체크아웃 직후에는 점유 `공실`과 카드 주 상태 `청소 필요`를 각각 기록합니다. 카드의 대표 문구는 `청소 필요`로 통일하고, 청소·안전 조건이 해소된 공실만 `배정 가능`으로 바꾸어 표시합니다.

## 간편 예약 원장

관리자 상단의 `간편 예약`은 121개 전체 객실을 세로, 선택한 달의 날짜를 가로로 둔 빠른 입력 화면입니다. 객실 고정 열에는 호수·타입·엘리베이터만 표시하고 호실을 누르면 해당 객실 상세로 이동합니다. 퇴실 청소 담당은 예약표에서 표시하지 않고 객실 기록과 청소 화면에서 확인합니다. 빠른 조회는 객실번호 검색과 객실 유형 필터만 제공하며 엘리베이터 분류 필터는 두지 않습니다. 날짜 헤더와 객실 열은 표 안에서 고정합니다. 노란 `1박`은 각각 별도 예약 ID이고, 이어진 파란 `연박 N박`은 한 예약 ID입니다. 바로 붙은 두 예약도 자동으로 합치지 않으므로 `1박 + 1박 + 연박`을 구분할 수 있습니다.

예약 정본은 객실별 단일 시각 필드가 아니라 안정적인 예약 ID를 가진 여러 `[체크인, 체크아웃)` 구간입니다. 간편 예약표와 객실 카드는 같은 메모리 원장을 다시 읽습니다. 어느 화면에서 접수·변경해도 두 화면에 즉시 반영되고, 이미 예약된 날짜는 새 예약을 만들 수 없습니다. 확인 보류·운영 중지·퇴실 미정 투숙 객실은 행 전체가 사유와 자물쇠로 잠깁니다. 청소·검수·촛불 미준비는 현재 고객 입실 판단에는 쓰지만 미래 예약 등록 자체를 막지는 않습니다.

예약 상세 대화상자도 간편 예약표와 같은 예약 ID를 편집합니다. 간편 예약표의 예약 칸과 카드형 객실 목록의 `예약 N건`은 같은 상세·변경·취소 설정을 엽니다. 기존 예약에는 `예약정보 수정 저장`과 별도 위험 행동인 `예약 취소`를 함께 제공합니다. 날짜·시각을 고쳐 저장하면 같은 예약 ID의 카드·예약표·퇴실 청소 일정이 즉시 다시 계산되고, 다른 예약과 실제 시각이 겹치면 저장하지 않습니다. 열어 둔 예약이나 청소 영향이 이미 변경·취소되었으면 오래된 값으로 덮어쓰거나 신규 예약으로 바꾸지 않고 최신 목록에서 다시 열도록 안내합니다.

카드형 객실 목록과 예약 상세의 일정 목록은 한 번에 월요일–일요일 한 주만 표시합니다. `〈 8월 17일(월)–23일(일) 〉`의 양쪽 버튼으로 한 주씩 이동하고, 가운데 날짜를 누르면 달력에서 날짜가 포함된 주차를 고릅니다. 선택한 주와 겹치는 예약만 목록에 표시하되 월간 간편 예약표와 예약 충돌 검사는 전체 예약을 계속 사용합니다. 지난 주의 예약과 이미 체크아웃·취소된 기록은 삭제하지 않고 같은 주차 탐색에서 `지난 예약 기록 · 조회만 가능`으로 보관하며, 입력 필드와 수정·취소 행동을 제공하지 않습니다. 신규·기존 예약 모두 체크아웃이 이미 지난 일정으로 저장하거나 옮길 수 없고, 상세 화면을 새로고침해도 선택 객실·예약·주차를 그대로 복원합니다. 오프라인·오래된 데이터에서도 보관된 과거 기록 조회는 허용하지만 저장·취소는 계속 잠급니다. 여러 주에 걸친 예약은 겹치는 각 주에서 확인할 수 있고, 객실 카드는 가장 가까운 예약이 속한 주의 건수와 이후 예약 건수를 구분합니다.

예약 취소는 체크인 전 예약만 허용하며 객실·기간·예약 ID·비공개/공개 청소 작업·담당 통보·인접 예약 준비 마감 영향을 확인하고 운영 사유를 선택한 뒤 확정합니다. 정해진 사유가 없으면 `기타`에서 1–120자의 운영 사유를 적을 수 있으며, 공백·121자 이상·연락처·이메일·4자리 객실 PIN은 최종 저장 단계에서도 차단합니다. 기타 사유는 URL·브라우저 history state·영속 저장소에 넣지 않습니다. 선택한 예약 ID 한 건만 소프트 취소하고 연결된 비공개 초안을 제거합니다. 이미 공개된 연결 작업, 연결 청소 수행 회차, 활성 랜덤 배정 초안이 있으면 조용히 되돌리지 않고 청소 화면에서 먼저 중단·조율하도록 취소와 일정 변경을 차단합니다. 이미 통보된 미시작 청소는 당시 담당·순서·일정 스냅샷과 담당 취소 통보 이력을 보존하며, 같은 날짜의 독립 현장 청소 요청은 유지하고 필요하면 재통보 상태로 바꿉니다. 체크인이 시작됐으면 `예약 취소` 대신 객실 상세의 `지금 체크아웃`을 사용합니다. 외부 OTA/PMS 원본은 이 데모에서 바뀌지 않습니다. 방금 만든 비공개·미배정 예약의 10초 `실행 취소`와 달리, 영향 확인을 거쳐 확정한 일반 예약 취소는 통보 업무를 조용히 복원할 수 없으므로 자동 실행 취소를 제공하지 않습니다.

마우스는 빈 날짜를 클릭하거나 같은 객실 행에서 가로로 드래그합니다. 키보드는 방향키로 셀을 이동하고 `Shift + 좌우 방향키`로 범위를 고른 뒤 `Enter` 또는 `Space`로 접수합니다. 터치는 오입력을 막기 위해 다음 안전 규칙을 사용합니다.

- 짧은 탭만으로는 새 예약을 만들지 않습니다.
- 0.35초 길게 눌러 `길게` 표시와 진동 피드백이 나온 뒤 같은 객실 행에서만 가로로 범위를 고릅니다.
- 길게 누르기 전 세로 이동은 선택을 취소하고 객실표 세로 스크롤로 처리합니다.
- 길게 누르기 전 가로 스와이프는 예약하지 않고 날짜표만 이동합니다.
- 다른 객실 행으로 넘어가면 전체 선택을 취소합니다.
- 손을 뗄 때 한 예약 ID로 접수하고 10초 동안 `실행 취소`할 수 있습니다.

예약 한 건을 접수하면 해당 체크아웃 날짜의 비공개 퇴실 청소 초안 한 건을 연결합니다. 담당 메이드를 임의로 자동 선택하지 않으며, 담당·통보 상태는 객실 기록과 청소 화면에서 확인합니다. 간편 예약표에는 예약 구간과 예약 불가 사유만 표시합니다. 예약·청소 초안·실행 취소는 현재 탭 메모리의 데모 상태이고 실제 OTA/PMS, 서버 저장, 동시 예약 잠금, 외부 알림은 연결하지 않았습니다.

| 타입 | 정본 기본 청소요금 | 참고 객실 | 참고 사진 | 퇴실 청소 촬영 구역 |

퇴실 청소는 타입 기본 촬영 구역을 먼저 적용하고, 침실·욕실·배수구처럼 객실마다 개수가 달라질 수 있는 구역은 실제 객실 레이아웃 수만큼 필수 슬롯을 반복하는 `타입 기본 + 객실 레이아웃 보정` 원칙을 사용합니다. `ROOM_LAYOUT_PROFILES`에는 사진으로 확인한 750·651·540·455·639·641·536·645·542호의 침실·욕실·배수구 수가 있고, 작업 생성 시 반복 규칙이 필수 슬롯으로 실제 펼쳐집니다. 나머지 112실은 `레이아웃 확인 보류`로 표시하고 최소 공통 슬롯만 적용합니다. 작업을 만들 때 타입·단가·예상시간·체크·사진 구역·레이아웃을 버전 스냅샷으로 고정하므로 이후 템플릿 변경은 기존 작업에 소급하지 않습니다. 관리자는 템플릿 목록·상세와 제출 당시 버전을 보고, 메이드는 본인에게 통보된 작업의 읽기 전용 촬영 구역만 봅니다.

원본 표지 사진 일부에는 운영 연락처가 있어 템플릿 자산으로 재사용하지 않습니다. 새 청소 사진도 연락처·얼굴·거울 반사·고객 물품·켜진 TV 화면을 제외해 촬영하도록 안내합니다. 현재 와이어프레임은 참고 객실·사진 수와 텍스트 촬영 규칙만 담고 실제 원본 예시 사진은 보여주지 않습니다.

현재 데모에는 4개 타입 × 퇴실·연박·재청소 12개 조합, 타입별 목록·상세, 예상시간·체크 필수 여부 편집, 작업·제출의 버전 스냅샷과 사진 확인 9객실의 레이아웃 반복 슬롯 생성이 있습니다. 메이드 작업 상세에서는 기존 체크와 촬영 슬롯을 구역별 카드로 묶되 각각의 완료 상태는 독립적으로 유지합니다. 각 슬롯의 `바로 촬영`은 `accept="image/*" capture="environment"` 입력으로 지원 기기의 후면 카메라를 요청하고, `갤러리`는 별도 이미지 입력을 엽니다. 슬롯당 현재 사진 1장만 로컬 `blob:` 미리보기로 유지해 재촬영 시 교체하고 제출 전 삭제할 수 있으며, 원본 파일명과 `blob:` URL 문자열은 화면과 이력에 표시하지 않습니다.

나머지 112실의 확정 레이아웃 프로필, 촬영 구역 편집·게시 서버, 실제 이미지 전송·분류·영속 보존은 구현하지 않았습니다. 카메라·갤러리에서 선택한 새 사진은 현재 탭 메모리의 미리보기 데모이며 초기화·시나리오 교체·탭 종료 뒤 복원되지 않습니다. `capture="environment"`는 후면 카메라 요청 힌트이므로 브라우저·기기에 따라 파일 선택기로 열릴 수 있고 실제 모바일 카메라 동작은 실기기 확인이 필요합니다. 123장 표본을 직접 반영한 것은 퇴실 청소 촬영 구역과 9객실 레이아웃이며, 연박·재청소 규칙과 예상시간은 데모 fixture입니다. 타입별 기본 청소요금 16,000/20,000/20,000/30,000원은 시트 정본을 사용합니다.

1. 일요일 오후–22:00에 메이드가 다음 주 가능일을 제출합니다.
2. 관리자는 전체 제출·미제출·변경 요청과 요일별 가능 인원을 확인합니다.
3. 시스템은 다음 날 예정 체크아웃 객실, 관리자가 `지금 체크아웃`한 객실, 다음 날 투숙 중 청소 신청 객실을 객실 카드 주 상태와 무관하게 `청소대상 객실`에 자동 포함합니다. 같은 예약의 수동·예정 체크아웃은 활성 퇴실 청소 한 건을 공유합니다.
4. 관리자는 같은 화면의 `청소대상 직접 등록`에서 자동 대상 외 현장 요청을 추가할 수 있습니다. 검수 반려 재청소는 직접 등록하지 않고 최초 청소한 메이드에게 자동 귀속합니다. 같은 객실·청소 유형의 중복 등록은 차단됩니다.
5. 근무일 전날 밤, 관리자는 `메이드 주간 근무표`에서 대상일의 근무 가능자를 먼저 확인합니다.
6. 근무표 바로 다음의 `동선 고려 랜덤 배정`에서 저장 전 초안을 만듭니다. 초안은 해당 날짜의 근무 가능·활성 메이드만 사용하고, 이미 통보했거나 관리자가 수동으로 지정한 담당·순서를 보존한 채 미배정 객실만 채웁니다.
7. 배정 계산은 마감 안에 완료 가능한 객실 수를 먼저 최대화합니다. 그 최대 배정 후보 안에서 메이드별 총 청소요금의 최대·최소 격차와 전체 편차를 줄이고, 금액 점수가 정확히 같은 후보에서만 같은 엘리베이터 구역·가까운 호수를 비교하며, 그 다음까지 같으면 랜덤으로 고릅니다. 실제 이동시간이나 전역 경로를 최적화하는 기능은 아닙니다. 이 기준은 상시 칩 목록 대신 `랜덤 배정 기준 설명` 툴팁에서 확인합니다.
8. 랜덤 초안 아래에서 관리자는 `전체` 또는 네 객실 타입별로 대상 수와 객실당 고정 청소 요금을 확인합니다. 각 행은 객실 호수·타입·청소 요금, `자동 · 예정 체크아웃 / 자동 · 수동 체크아웃 / 자동 · 투숙 중 청소 신청 / 직접 등록` 근거, 얼리 체크인·레이트 체크아웃·연박 청소 일정을 함께 표시합니다. 타입 필터는 표시만 좁히고 숨은 객실도 전체 대상·미배정 현황과 부분 통보 판단에 유지합니다.
9. 관리자는 필요한 객실만 담당을 직접 수정하거나 미배정으로 되돌립니다. 담당 목록에는 해당 날짜를 `근무 가능`으로 제출한 메이드만 표시되고, `근무 불가`·`미제출` 메이드는 선택할 수 없습니다.
10. 이어지는 메이드별 1–N 순서 보드에서 얼리 체크인·레이트 체크아웃의 조정된 예정 시각과 기준 대비 차이를 확인하며 청소 순서를 조정합니다. 별도 작업량·동선 비교판은 표시하지 않습니다.
11. 초안과 세부 수정은 메이드에게 바로 통보되지 않습니다. 관리자가 저장·통보한 객실만 메이드 업무와 알림에 반영됩니다.
12. 미배정 객실은 누구의 순서에도 포함하지 않고 별도 대기 영역에 남깁니다.
13. 모든 객실을 다 배정하지 못해도 담당 메이드와 연속된 청소 순서가 정해진 객실이 한 건 이상이면 `배정된 객실만 저장·통보`할 수 있습니다. 미배정 객실은 대기 상태로 남고 후속 배정 때 추가 통보합니다.
14. 부분 저장 뒤 해당 메이드의 `내 업무`와 `알림`은 이번에 확정된 객실을 지정 순서대로 반영합니다. 관리자 이력에는 이번·누적 통보 수, 남은 미배정 수, 이전·새 담당과 순서·시각·사유가 남습니다.
15. 가능일 제출·배정·순서 통보·실제 청소 완료일은 서로 다른 주간 기록으로 보존합니다. 관리자는 `메이드 → 근무 기록`에서 월요일–일요일 주차를 달력으로 선택하고 사람별로 조회하며, 요약은 `메이드 N명`과 `메이드별 날짜 합계 N일`을 분리해 표시합니다.
16. 메이드는 시작 가능 시각 뒤 PIN을 확인하고 `일 시작 → 구역별 체크·바로 촬영 → 객실 특이사항·촛불 → 현장 완료 → 업로드 재시도 → 전체 제출`을 진행합니다. 체크와 사진은 각각 완료해야 하며 한쪽 입력이 다른 쪽을 자동 완료하지 않습니다. 각 사진 슬롯은 카메라 또는 갤러리에서 현재 1장을 선택하고 재촬영하면 교체합니다. 객실 특이사항은 업무 메모나 이미지 중 하나만으로도 등록할 수 있고, 여러 이미지를 한 번에 선택한 뒤 저장 전에 한 장씩 제거할 수 있습니다.
17. 저장한 객실 특이사항에는 등록자·시각·유형·메모·이미지 수가 남고 관리자 객실 상세·검수 흐름에서 같은 이미지 갤러리를 확대 조회합니다. 메이드는 본인 담당 청소 중 객실에서만 등록할 수 있습니다.
18. 메이드는 본인 담당 객실이 통상 범위를 크게 넘게 지저분하면 청소 시작 전부터 업로드 단계까지, 전체 제출 전에 이미지 1장 이상을 첨부해 폭탄방으로 신고합니다. 여러 이미지를 선택할 수 있고 메모는 선택 사항입니다.
19. 전체 제출 뒤 폭탄방 증빙은 해당 제출 버전에 잠깁니다. 관리자는 이미지·메모와 기본·추가·총액을 확인해 `폭탄방 인정` 또는 `폭탄방 미인정`을 먼저 결정합니다.
20. 폭탄방 인정 뒤 전체 청소까지 승인되면 주간 전체가 아니라 **해당 객실의 기본 청소요금만 정확히 2배**로 적립됩니다. 화면과 원장은 `기본 청소요금 + 같은 금액의 폭탄방 추가요금 = 해당 객실 총액 2배`로 표시합니다.
    - 전체 청소 반려로 생긴 재청소는 최초 청소한 메이드 본인에게 자동 귀속하며 타 메이드에게 이관·재배정하지 않습니다. 재청소는 무급 0원이고 폭탄방 신고·추가요금·폭탄방 수익 원장을 새로 만들지 않습니다.
21. 폭탄방 미인정 뒤 전체 청소가 승인되면 기본 청소요금만 적립합니다. 전체 청소가 반려되면 적립하지 않고 신고·이미지·관리자 결정과 사유를 제출·재청소 이력에 보존합니다.
22. 관리자와 해당 메이드는 청소 상세·검수 결과·완료 내역·주급 내역에서 같은 폭탄방 상태와 기본·추가·총액을 확인합니다. 같은 제출을 다시 승인해도 수익 원장은 한 번만 생성됩니다.
23. 관리자는 전체 제출을 승인 또는 반려합니다. 반려 재청소에는 별도 담당 선택을 제공하지 않고 최초 청소한 본인에게 자동 귀속한 `재청소 · 무급 0원` 상태를 통보합니다.

동시에 진행할 수 있는 청소는 한 건입니다. PIN 원문은 한 객실만 최대 30초 메모리에 유지하며 역할·화면 이동과 창 비활성화 때 다시 가립니다.

## 관리자 주급 청소 내역

관리자는 `메이드 → 주급 정산`에서 월요일–일요일 조회 주차를 선택한 뒤 메이드별 카드의 `청소 내역 N건 · 상세 보기`를 열 수 있습니다. 상세에는 각 청소의 완료일·객실·객실 타입·청소 종류·당시 기본 청소요금·폭탄방 추가요금·해당 객실 총액·검수 및 정산 상태를 표시합니다.

같은 화면의 모든 메이드 카드에는 주차·메이드별 독립 지급 스위치가 있습니다. 첫 확인에서 `PAYING`으로 전환해 금액·수익 ID를 잠그고, 외부 전액 송금 뒤 같은 스위치에서 `PAID` 완료를 기록합니다. 송금 결과가 불명확하면 `CHECK`로 잠가 두고, 송금하지 않은 것이 확인된 경우에만 필수 사유를 남겨 `OPEN`으로 복귀합니다. 이때 이전 지급 시도의 잠근 금액·수익 ID·관리자·사유는 감사 스냅샷으로 보존합니다. `PAID` 완료 기록은 직접 취소하지 않고 이후 차이를 정정·상계합니다. 다른 메이드와 다른 주차는 바뀌지 않으며, 확정액 0원과 아직 마감되지 않은 주차는 스위치 자리를 유지한 채 각각 `지급 대상 없음`, `주차 마감 전` 이유로 잠깁니다. 이 앱은 실제 송금을 실행하지 않습니다.

지급 진행 뒤 객실 원장이 바뀌더라도 카드와 메이드 지급 내역은 당시 잠근 지급액을 유지합니다. 현재 객실 원장 금액은 따로 표시하고 차이는 지급 완료 기록을 덮어쓰지 않은 채 정정·상계 대상으로 구분합니다.

- 객실 타입과 기본 청소요금은 8월 시트 정본인 `스탠다드 16,000원 / 프리미어 20,000원 / 파셜 오션뷰 20,000원 / 패밀리 투룸 30,000원`을 사용합니다.
- 검수 대기는 `승인 시` 예상액으로 따로 표시하며 확정 주급과 지급액에 포함하지 않습니다.
- 청소 전체 반려와 처음 청소한 본인의 무급 재청소는 상세 이력에 `0원 · 주급 합계 제외`로 남고 새 수익 원장을 만들지 않습니다.
- 데모 과거 주차인 2026년 8월 3일–9일 김민지1은 승인 청소 6건 합계 **138,000원**입니다. 536호 폭탄방 한 건만 `기본 20,000원 + 추가 20,000원 = 40,000원`이고, 나머지 다섯 객실은 `20,000원 + 30,000원 + 16,000원 + 16,000원 + 16,000원 = 98,000원`이므로 주차 합계는 138,000원입니다.
- 위 인명·예약·과거 주급 내역은 기능 확인용 데모 fixture이며, 실제 지급이나 송금 기록이 아닙니다.

## 대표 데모 시나리오

상단 `데모 제어`에서 역할·시각·네트워크·시나리오를 바꾸고 초기화할 수 있습니다.

1. 메이드: 일요일 다음 주 근무 가능일 제출
2. 관리자: 예정 체크아웃·수동 체크아웃·투숙 중 청소 신청 자동 대상 확인 → 현장 요청 직접 등록·중복 차단 → 메이드 주간 근무표 확인 → 총 청소요금 균형 우선·엘리베이터와 가까운 호수 차선의 동선 고려 랜덤 배정 초안 → 객실 타입·요금·특수 시각 확인과 객실별 담당 수정 → 메이드별 1–N 순서 수정 → 부분 통보 · 미배정 대기
3. 메이드: 지정 순서대로 통보된 내 업무 → 시간 게이트 → PIN → 청소 시작
4. 구역별 체크·바로 촬영/갤러리 선택 → 슬롯별 재촬영·교체 → 객실 특이사항 메모·여러 이미지 등록 → 폭탄방 이미지 1장 이상 신고 → 현장 완료 → 업로드 실패·재시도 → 전체 제출
5. 관리자 객실 특이사항·폭탄방 이미지 확대 조회 → 폭탄방 인정·미인정 → 전체 검수 승인 또는 반려 → 승인 시 해당 객실 기본+동일 금액 추가요금 확인 / 반려 시 최초 청소한 본인에게 무급 0원 재청소 자동 귀속
6. 레이트 체크아웃과 청소·PIN 충돌 해결
7. 메이드 담당 취소 요청 → 관리자 유지·담당 변경·보류 결정
8. 투숙 객실의 투숙 중 청소 작업 생성 → 전날 관리자 배정
9. 메이드 비활성 → 신규 배정 후보 제외 → 기존 미래 통보·미종결 수행·업로드·검수·출입 충돌 종결 확인. 검수 반려 재청소는 최초 청소한 본인이 무급으로 완료하며 타 메이드 이관 없이 종결한 뒤 비활성 확정
10. 지난주 모든 메이드 카드의 독립 지급 진행 시작 → 특정 메이드만 정산 확인 필요 → 미송금 필수 사유로 지급 대기 복귀 → 다시 진행 시작 → 외부 송금 완료 기록
11. 컴플레인·벌점 판정·이의·정정·소프트 삭제
12. 모달 → 상세 → 목록 뒤로가기와 날짜·필터·스크롤 복원
13. 로딩·진짜 0건·필터 0건·오래된 캐시·재시도
14. 관리자: 메이드 근무 기록 → 주차·메이드 필터 → 가능 제출일·배정 통보일·실근무 완료일 비교
15. 관리자: 더보기 → 청소 템플릿 → 타입별 참고 객실·촬영 구역·활성 버전 확인 → 데모 변경 내용 검토·새 작업부터 적용 → 메이드 작업·관리자 검수에서 같은 스냅샷 확인
16. 관리자: 객실 상세 → 읽기 전용 호수 확인 → 타입·엘리베이터 수정 → 목록·청소대상·랜덤 배정 초안 반영과 기존 작업 스냅샷 유지 확인
17. 관리자: 예정 체크아웃 전 투숙 객실에서 `지금 체크아웃` → 예정·실제 시각 분리 → 점유 `공실`·카드 주 상태 `청소 필요` → 동일 예약 퇴실 청소 한 건 확인
18. 관리자: `간편 예약` → 빈 날짜를 클릭·드래그하거나 터치로 길게 누른 뒤 같은 행에서 가로 선택 → 별도 1박과 한 건의 연박 구분 → 카드·청소 초안 즉시 반영 → 10초 실행 취소
19. 관리자: 카드형 객실 목록 또는 간편 예약표의 기존 예약 상세 → 날짜·시각 오류는 `예약정보 수정 저장` → 예약 자체를 없앨 때는 `예약 취소` → 대상·청소 영향·운영 사유 확인 → 정해진 사유가 없으면 `기타` 운영 사유 입력 → 선택한 예약 ID 한 건만 카드·예약표·청소 배정에 즉시 반영. 체크인 뒤에는 `지금 체크아웃` 사용

## 데모 데이터와 경계

객실 호수·객실 유형과 타입별 기본 청소요금 16,000/20,000/20,000/30,000원은 2026년 8월 객실현황 시트 정본입니다. 엘리베이터 구역은 같은 시트와 2026-08-18 제공 건물 지도를 함께 사용하며 최초 미기재 객실은 없습니다. 호수는 읽기 전용이고 타입·엘리베이터는 관리자 수정값을 현재 정본으로 사용합니다. `장기-결제` 시트의 활성 11실은 최초 투숙 seed일 뿐이며 고객명·회사명·시작일·결제 메모와 장기투숙 구분은 앱·내보내기에 반입하지 않습니다. 정상 점유는 투숙/공실, 762호는 현재 투숙 상태 확인 필요 데이터 배지, 카드 주 상태 `배정 가능`은 준비된 공실의 파생 결과입니다. 인명·예상시간·예약·청소 상태·사진·폭탄방 승인·과거 근무·주급 기록은 실제 운영 데이터가 아닌 데모 fixture이며 화면 상태는 브라우저 메모리에서만 시뮬레이션됩니다.

- 실제 서버 저장, 다중 사용자 동시성, 도어락 발급, 폭탄방을 포함한 사진 전송·영속 보관, 자동 지급·송금, 푸시·SMS·전화는 연결하지 않습니다.
- `localStorage`와 `sessionStorage`를 사용하지 않습니다.
- PIN·고객명·사진 원문을 URL, 알림, 로그, 브라우저 영속 저장소에 남기지 않습니다.
- 사용자가 선택한 객실 특이사항 이미지는 현재 탭의 메모리 `blob:` 미리보기로만 유지되며 초기화·시나리오 교체 또는 탭 종료 뒤 복원되지 않습니다. 파일명은 화면 상태와 이력에 저장하지 않습니다.
- 사용자가 선택한 폭탄방 이미지도 현재 탭 메모리에서만 미리보고, 과거 승인 건은 기능 확인용 이미지 fixture로 표시합니다. 화면의 2배 금액은 실제 자동 지급 결과가 아니라 결정적 원장 시뮬레이션입니다.
- 청소 구역별 카메라·갤러리에서 선택한 이미지는 현재 탭 메모리의 `blob:` 미리보기로만 유지합니다. 슬롯당 현재 1장을 유지하고 재촬영으로 교체하며, 파일명과 `blob:` URL 문자열은 화면 상태·URL·로그·영속 저장소에 남기지 않습니다. 실제 서버 업로드·재전송·영속 보존은 연결하지 않았습니다.
- `clean-template/` 참고 원본 123장은 앱·저장소에 복사하지 않았습니다. 타입별 참고 객실·사진 수와 촬영 구역 문구만 fixture로 사용하며, 표지 사진의 운영 연락처 등 개인정보성 정보는 화면에 옮기지 않습니다.
- 타입별 사진 템플릿은 사진 확인 9객실에서 침실·욕실·배수구 수만큼 필수 슬롯을 정확히 확장합니다. 나머지 112실은 최소 공통 슬롯만 생성하고 `레이아웃 확인 보류`를 노출합니다. 이 객실들의 확정 레이아웃 마스터, 실제 이미지 서버 전송·자동분류·서버 버전 게시·영속 보존은 구현하지 않았습니다.
- 실제 서비스에는 서버 권한 검사, 감사 로그, 알림 발송, 업로드 재개, 동시 배정 충돌 처리가 필요합니다.
