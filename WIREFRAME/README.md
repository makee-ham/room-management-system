# CASTLE THE ART 객실관리 앱 클릭형 와이어프레임

모바일 현장 사용을 우선해 다시 구성한 단일 파일 반응형 프로토타입입니다. 관리자는 객실 상태·예약·청소 배치·검수·메이드·주급 기록을 운영하고, 메이드는 근무 가능 등록부터 일감 선점·청소 제출·주급 확인까지 이어지는 흐름을 확인할 수 있습니다.

정책 적용 우선순위는 다음과 같습니다.

1. 이 작업에서 사용자가 확정한 최신 결정
2. 최종 UX 감사 문서
3. [최종 UX 감사 원문](../DOCS/FINAL_UX_AUDIT.md)
4. [클릭형 와이어프레임 제작 인계서](../DOCS/14_CLICKABLE_WIREFRAME_HANDOFF.md)
5. [2회 감사 결과](../DOCS/15_TWO_PASS_AUDIT_RESULT.md)

최종 UX 감사 문서는 구현 과정에서 수정하지 않습니다. 객실표·단가·예상시간 등 미확정 값은 제작 인계서의 명시적 데모 데이터만 사용합니다.

## 실행

빌드와 설치는 필요하지 않습니다. [index.html](index.html)을 직접 열 수 있으며, URL hash·새로고침과 브라우저·모바일 뒤로가기를 함께 확인할 때는 저장소 루트의 정적 서버 사용을 권장합니다. 뒤로가기 회귀의 수용 경로는 `모달 → 상세 → 목록`이고, 목록 복귀 때 선택 날짜·검색·객실 유형·상태 필터와 스크롤 위치를 유지해야 합니다.

```bash
python3 scripts/serve.py
```

Windows에서는 `python scripts/serve.py`를 사용합니다. 그다음 `http://127.0.0.1:4173/index.html`을 엽니다. 외부 CDN, 프레임워크, 백엔드, 실제 계정은 사용하지 않습니다.

## 모바일 우선 정보 구조

관리자 하단 내비게이션은 중요도 순서대로 `오늘 / 객실 / 청소 / 메이드 / 더보기`입니다.

- `오늘`: 2×2 객실 요약, 오늘 체크인·체크아웃, 근무 인원과 긴급 조치
- `객실`: 전체 객실 검색, 객실 유형·운영 상태 조회, 예약·입실 준비·PIN·운영 중지
- `청소`: `공개 대기 / 진행 중 / 검수 대기 / 완료`, 비공개 초안 공개와 전체 제출 검수
- `메이드`: 근무 현황, 직접 배정, 주급, 컴플레인·벌점
- `더보기`: 전체 이력, 12개 데모 청소 템플릿, 계정·로그인, 중첩된 단가 설정

메이드 하단 내비게이션은 `내 업무 / 공개 청소 / 알림 / 주급 / 더보기`입니다.

- `내 업무`: 현재 한 건의 주 행동과 다음 단계
- `공개 청소`: 근무 가능 등록 뒤 선점할 수 있는 일감
- `알림`: 배정·반려·PIN 변경 등 운영 알림
- `주급`: 이번 주 누적 예상·확정 금액, 달력으로 찾는 전체 과거 주차, 주차별 작업 상세·승인·지급 상태
- `더보기`: 계정과 근무 상태

데스크톱은 같은 정보 구조를 왼쪽 내비게이션과 넓은 콘텐츠 영역으로 확장합니다. 객실 현황도 다른 관리자 화면과 같은 데모바·공통 헤더·알림·역할 전환을 사용하고, 날짜 도구는 본문 첫 영역에 둡니다. PC 회귀에서는 공통 헤더의 상단 공백·offset과 메이드 목록 아바타가 34×34 원형을 유지해 타원으로 늘어나지 않는지를 확인합니다. 모바일에서 `비공개 청소 초안`, `검수 대기`, `지난주 지급` 같은 보조 묶음은 접힌 상태에서 제목·건수·긴급 여부를 확인하고 펼칠 수 있습니다.

관리자 `오늘`의 네 객실 요약 카드는 모두 버튼입니다. `고객 배정 가능 / 청소 필요 / 고객 배정 불가 / 촛불 있음`을 누르면 이전 객실번호 검색·객실 유형 조건을 초기화하고 해당 상태 필터만 적용한 `객실` 목록으로 이동하며, 선택 필터는 URL에도 반영됩니다. `고객 배정 불가`는 요약 수치와 동일하게 투숙 중 객실을 포함한 현재 배정 불가 객실 전체를 뜻합니다.

## 핵심 정책

### 날짜와 객실 조회

- 날짜 버튼을 누르면 모바일에서는 월간 달력 바텀시트, 데스크톱에서는 화면 중앙 월간 달력 대화상자(centered dialog)가 열립니다.
- 관리자는 전체 객실을 객실 번호·객실 유형·상태로 검색하거나 필터링합니다.
- 객실 카드는 체크아웃과 체크인 시각을 바로 보여 주고, `예약 등록 가능`과 `현재 입실 가능`을 구분합니다.
- 미래 예약은 현재 객실이 준비되지 않아도 등록할 수 있지만 현재 입실은 준비 조건을 모두 만족해야 합니다.
- 레이트 체크아웃 상한은 15:00입니다. 얼리 체크인의 하한은 확정하지 않았으며 데모는 1시간 단위 조정만 보여 줍니다.
- 장기투숙은 7박 이상입니다. 연박·장기투숙 청소는 자동 생성하지 않고 관리자 요청으로 만듭니다.

### 객실 PIN

- 객실 카드·상세에는 PIN 영역을 한 번만 표시합니다: `객실 PIN •••• / 보기 / 수정`.
- 관리자는 모든 객실 PIN을 한 객실씩 최대 30초 동안 볼 수 있습니다. 역할·화면 이동과 창 비활성화 시 다시 가립니다.
- 수정은 모바일 바텀시트/데스크톱 대화상자에서 진행하며, 선행 0을 포함한 정확히 네 자리 숫자만 허용합니다.
- `랜덤`은 네 자리 보안 난수를 만들고, 확인 단계 뒤 저장합니다.
- PIN은 언제든 변경할 수 있습니다. 메이드는 다음 PIN 조회 때 최신 값을 받습니다.

### 객실 상태 조합

- 촛불 수량의 `− / +` 입력은 관리자 객실 상세와 메이드 청소 결과 입력 중에만 제공합니다. 메이드가 `현장 완료`할 때 최종 수량을 객실에 반영합니다.
- 투숙 중인 모든 객실의 촛불 수량은 0이며 관리자와 메이드 양쪽에서 촛불 입력 UI를 숨기고 변경을 금지합니다.
- `오늘 퇴실 + 퇴실 전 + 촛불 있음` 조합은 만들지 않습니다.
- 관리자 `오늘`의 촛불 객실 요약은 현재 객실 상태에서 동적으로 다시 계산하며, 투숙 중 객실은 집계에서 제외합니다.
- 촛불, 청소 필요, 얼리 체크인, 레이트 체크아웃, 연박, 장기투숙, 배정 불가 등은 상호 독립 상태로 표현하되 위 금지 조합은 fixture와 UI 양쪽에서 막습니다.
- 얼리 체크인은 일반 체크인보다 높은 긴급도로 표시합니다.
- 운영 중지는 모든 객실 상태에서 가능하며 카드와 상세에 `운영 중지` 상태, 입력한 중지 사유, 대체 객실을 함께 표시합니다. 운영 재개는 별도의 `재개 사유`를 입력받지 않으며, 기존 중지 사유와 중지·재개 이벤트 및 각 시각을 사건 이력에 남깁니다.
- 다른 객실 배정은 운영 중지 흐름 안에서만 진행합니다. 같은 유형의 준비 완료 객실을 우선 제안하고 다른 유형을 선택하면 사유를 기록합니다.
- 객실 현황 상태 필터에는 `얼리 체크인`과 `레이트 체크아웃`이 각각 있으며, 카드에서도 변경 시각과 함께 별도 상태로 표시합니다.
- 객실 현황의 `내보내기`에서 선택 날짜 전체 객실 또는 현재 검색·필터 결과를 CSV와 실제 OOXML Excel `.xlsx`(`.xls` 아님)로 저장할 수 있습니다. 객실 유형, 입퇴실 시각, 얼리·레이트 상태, 예약 등록·현재 입실, 청소, 담당, 촛불, 운영 상태·중지 사유·대체 객실을 포함하고 객실 PIN 원문은 제외합니다.

### 메이드 근무와 청소

- 매일 09:00 기준으로 `오늘 근무 가능` 또는 `오늘 쉬어요`를 등록합니다.
- 미등록 상태에서도 공개 청소는 볼 수 있지만 선점은 잠기며 `오늘 근무 가능 여부를 먼저 등록해 주세요`를 표시합니다.
- 담당 업무가 없으면 휴무 전환은 즉시 반영됩니다. 배정 업무가 있으면 관리자 승인, 진행 중 업무가 있으면 중단·인계가 필요합니다.
- 관리자는 시작 전 청소를 메이드에게 직접 배정할 수 있습니다.
- 메이드 기본 흐름은 `일감 찾기 → 선점 → 내 업무 → 시간 게이트 → PIN → 일 시작 → 체크·사진·메모·촛불 → 현장 완료 → 업로드 재시도 → 청소 전체 제출 → 검수 → 주급`입니다.
- 동시에 진행할 수 있는 청소는 한 건이고, 화면에는 현재 단계에서 필요한 주 행동 하나를 우선합니다.
- 메이드가 청소 전체를 제출하면 해당 작업에 포함된 결정적 데모 이미지를 검수 자료로 사용합니다. 302호 제출은 4장, 203호 제출은 3장입니다.
- 관리자는 제출된 전체 이미지를 썸네일로 훑고 필요한 사진을 확대해 확인한 뒤 청소 전체 제출을 승인 또는 반려합니다. 사진별 승인 컨트롤은 제공하지 않습니다.

### 청소 템플릿 설정

- 관리자 `더보기 → 청소 템플릿 설정`에는 네 객실 유형과 `퇴실 / 연박 / 재청소`를 조합한 12개 결정적 데모 템플릿이 있습니다.
- 각 템플릿 상세에서 예상시간, 체크 항목, 필수 사진 항목을 확인합니다.
- 변경은 `수정 → 변경 내용 확인 → 저장` 순서로 진행합니다.
- 저장 시 이미 생성된 작업은 생성 당시 템플릿 스냅샷을 유지하며, 변경 내용은 새로 생성하는 작업부터 적용합니다.

### 주급과 평가 기록

- 관리자와 메이드 모두 주급이 주차 안에서 차곡차곡 쌓이는 예상·검수 대기·확정·이전 지급 내역을 확인합니다.
- 이번 주 요약은 화면 상단에 고정하고, 그 아래 지급 이력은 월요일 00:00부터 일요일 23:59까지의 과거 주차로 나눕니다.
- 관리자와 메이드 모두 주차 달력에서 날짜를 누르면 그 날짜가 포함된 월요일–일요일 주차로 이동합니다. 현재 주의 일요일까지는 같은 주로 선택할 수 있고 다음 주부터는 잠깁니다.
- 관리자는 선택한 주차의 전체 메이드 금액·상태를, 메이드는 본인 금액·작업 상세·승인·지급 상태만 확인합니다. 기록이 없는 주차는 다른 주 자료 대신 명시적인 0건 상태를 표시합니다.
- 관리자의 `지급 완료` 토글은 메이드 화면에 제공하지 않습니다.
- 메이드는 본인 주급·작업·컴플레인·감사 이력·알림만 볼 수 있습니다. 관리자 지급·객실·메이드·템플릿 상세는 URL이나 브라우저 이력으로 직접 진입해도 열리지 않습니다.
- 관리자의 지난주 지급은 단일 `지급 완료` 토글입니다. 앱은 송금하지 않으며 정확한 안내 문구는 `앱은 송금하지 않고 지급 여부만 기록합니다`입니다.
- 토글을 켜면 즉시 지급 완료로 기록하고 10초 동안 실행 취소할 수 있습니다. 끄거나 되돌린 동작도 감사 이력으로 남깁니다.
- 컴플레인·벌점은 메이드를 지정하고 사유를 입력해 추가합니다. 벌점은 점수를 함께 기록합니다.
- 각 기록 상세에서 `관리자 판정 → 메이드 내용 확인 또는 이의 → 관리자 판정 유지·종결 또는 새 버전 정정·재알림`을 왕복하며 원 기록과 메모를 보존합니다.
- 활성 목록에서 삭제할 수 있지만 실제로는 소프트 삭제하며 10초 실행 취소와 감사 이력을 제공합니다.
- 컴플레인·벌점은 주급에서 자동 차감하지 않습니다.

메이드 담당 취소 요청은 관리자 `오늘`에 별도 접이식 사건으로 나타납니다. 관리자는 거절·재공개·직접 배정·보류를 선택하며, 결정 전에는 기존 담당을 유지하고 오프라인·오래된 데이터에서는 요청 처리와 확정을 모두 잠급니다.

## 13개 데모 시나리오

상단 `데모 제어`에서 역할·시각·네트워크·시나리오를 바꾸고 현재 시나리오를 초기화할 수 있습니다.

1. 예약 저장 → 준비 의무·비공개 초안 → 선택 묶음 공개
2. 공개 일감 → 근무 가능 등록 확인 → 선점 → 시간 도달 → PIN → 일 시작
3. 체크·사진 → 현장 완료 → 업로드 실패·재시도 → 청소 전체 제출
4. 302호 4장·203호 3장 제출 사진을 썸네일·확대로 검수 → 제출 전체 승인 또는 반려·재청소
5. 비투숙 객실 촛불 입실 차단 → 회수 → 남은 준비 조건 재판정
6. 레이트 체크아웃 변경 → 청소·출입·PIN 충돌 해결
7. 메이드 담당 취소 요청 → 관리자 결정 → 후속 배치
8. 활성 예약의 연박·장기투숙 청소 → 비공개 작업 생성
9. 메이드 비활성 → 진행 업무 중단·인계 → 미전송 자료 업로드
10. 지난주 `지급 완료` 단일 토글 → 10초 실행 취소·감사 이력
11. 컴플레인·벌점 추가 → 판정·이의 또는 소프트 삭제·실행 취소
12. 모달 → 상세 → 목록 뒤로가기와 날짜·검색·객실 유형·상태 필터·스크롤 복원
13. 목록 로딩·진짜 0건·필터 0건·오래된 캐시·재시도

시나리오 데이터는 실제 운영 데이터가 아닌 결정적 fixture이며, 역할·화면·시간·상태를 함께 초기화합니다.

## 프로토타입 경계와 개인정보

화면 상태는 브라우저 메모리에서만 시뮬레이션됩니다. 예약·청소·검수·주급·컴플레인의 서버 저장, 실시간 동시성, 도어락 PIN 발급, 사진 파일 전송, 송금, 푸시·SMS·전화는 연결하지 않습니다.

- `localStorage`와 `sessionStorage`를 사용하지 않습니다.
- PIN 원문은 명시적 조회 뒤 한 객실만 최대 30초 표시합니다.
- 고객명·PIN·사진 원문을 목록·알림·브라우저 영속 저장소에 기록하지 않습니다.
- 실제 서비스 전환 시 서버 권한 검사, 불변 감사 로그, 업로드 재개, 다중 사용자 충돌 처리가 필요합니다.
